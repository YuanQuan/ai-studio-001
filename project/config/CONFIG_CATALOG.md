# 配置目录与扩展规则

版本：v0.3｜日期：2026-09-28｜Product 草案，待评审与用户审批。

依据：用户本轮要求产品负责配置表结构，先建立可扩展体系与顾客样表；历史方案见 `project/research/历史市场调研与方案_v0.2/`。本目录描述逻辑结构，不宣告运行时格式、技术实现或数值已定稿。职责以当前 Product／Tech Lead 配置为准。

## 优先配置目录

按“对象是谁 → 何时发生 → 发生什么 → 引用何种内容”拆分；仅先落地顾客所需结构，其余保留目录，不建空表。

## 扩展与数据约定

1. 每表单列稳定字符串 ID；不同对象 ID 不复用，删除保留废弃记录。显示名称不做外键。
2. 对象主表、触发条件、行为内容分离。一对多用关联表行表达，避免逗号拼接字段或无限增加“条件1/条件2”。
3. 数值未定用草稿空值并列出待定项，不以 0 冒充已确定数值；必填未定行不可用于运行。
4. 示例行一律 `DRAFT` 且 `enabled=false`；发布行须通过类型、必填、唯一、引用和逻辑校验。
5. 引用尚未建立的内容时标 `PLANNED`；只有目标正式存在且可用才可标 `RESOLVED`。发布不得含未解析引用。
6. 产品维护逻辑字段、语义和示例；技术评审再确定存储类型、导出、运行时加载、跨端分发与校验实现。对规则语义的修改需回到产品确认。
7. 每次修改记录版本、变更原因和迁移影响。新增可选字段可兼容扩展；改名、改类型、改 ID 或改语义必须给迁移说明，不覆盖历史版本。
8. 文档未确定客户端／服务端具体分工；显示字段为客户端候选，触发与奖励判定字段为权威端候选，最终由技术评审决定。禁止以此草稿直接生成线上配置。

## v0.2 更新依据

用户明确独立进货玩法、地府18层不同资源、逐层开放且越来越难、后期世界资源每日固定产量并供玩家争夺。上述新增目录仅保留真实需求对象，不建空表或填数值。资源ID应复用Resource；产出归M04、资源口径归M06、争夺及分配归M07；每日产量不是每位玩家配额。


## v0.3 更新依据

**v0.4历史记录，已被v0.6覆盖：**当时用户明确弱社交、单一共享世界无多区服；顾客按喜好访问1至多个摊位，每次驻足有时间，摊位初始并行容量1且升级提升，排队过久会生气离开，闹事未及时应对会带来客流惩罚。本轮仅补未来结构，不修改已有XLSX样例。

## v0.4 更新依据

用户最新指令覆盖上节历史表述：排队不会因久等使顾客反感离开；等待与店长效率只影响整体收益最大化。CustomerVisitRule 中不再预留“耐心耗尽离开”的现行语义，闹事导致客流中断仍单独处理。少量定时任务、自动经营和长线目标暂只在产品概要登记，尚无确定配置字段或数值；现有XLSX样例不变。
