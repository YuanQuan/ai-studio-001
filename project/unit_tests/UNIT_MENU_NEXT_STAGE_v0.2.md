# 七项菜单单元样例：Product v0.2 批准后的专业修订

日期：2026-10-03。正式输入为用户已批准的 `UNIT-MENU-PRODUCT-001 v0.2`、`DEC-UNIT-FINAL-ASSET-004` 与已选美术方向。用户本次批准的是**产品规格和验收口径**；正式帧图、骨骼、图集、Creator 运行和 QA 报告仍需后续实际交付。

## 并行专业任务与下一门禁

| Task | Owner | 本阶段应交付的审阅包 | 下一门禁 |
|---|---|---|---|
| `UNIT-MENU-TECH-DESIGN-001 v0.2` | Tech Lead | 同源 Scene/Prefab/稳定资源 ID；幽灵 SpriteFrame 序列帧状态、左右翻转、座点和状态清理；其他动态骨骼、图集与目标设备测量契约 | 技术设计 `USER_REVIEW` |
| `UNIT-MENU-ART-DESIGN-001 v0.2` | Art | 空底板和可切换物件分层；幽灵原创逐帧母版/循环/镜像/板凳出图前方案；其他骨骼对象单页草排、来源许可及逐次 Art/Tech 双签清单 | 美术正式出图前方案 `USER_REVIEW` |
| `UNIT-MENU-UI-SPEC-001 v0.2` | UI | 已批七入口结构上的序列帧显示节点与非镜像 UI 修订；共用组件、示例对话、审阅图状态和字体/图片正式资源门槛 | UI 修订规格 `USER_REVIEW` |
| `UNIT-MENU-VFX-SPEC-001 v0.2` | VFX | 店铺亮暗/投影、树花灯效果与幽灵帧对象配套效果的触发、清理和性能降级 | 特效修订规格 `USER_REVIEW` |

Tech、Art、UI、VFX 分别按自身 Task Packet 的 Required Artifacts 交付。Art/Tech 对美术出图前方案交叉评审；Art 对 UI/VFX 视觉方向评审；Master 核对全包，Producer 记录各版 `USER_REVIEW`。只有对应专业版本得到用户明确批准，才能当作正式生产/实现输入。

## 版本边界

- `Product v0.1` 保留已批准七菜单范围的历史；其中幽灵骨骼条款被最新用户决定覆盖，当前以 `Product v0.2` 为准。
- `Tech/Art/VFX v0.1` 整版退回，旧顾客骨骼设计不能下游执行。`UI v0.1` 仅结构和交互已批；其中“顾客骨骼翻转”须由 `UI v0.2` 替换。旧概念 PNG、审阅 SVG、旧 Demo 不算最终正式资源。
- 幽灵顾客只绘一个方向的原创透明序列帧，另一向翻转；移动、跑动等循环动作以每动作约 4–6 帧为起点，首尾自然衔接实测。五状态左右十格、两向板凳坐姿与遮挡保留；孟桃、店铺动态件和树花灯等决定动态的对象继续骨骼，每骨骼对象附件单页。
- 单元实际产出必须是未来主体引用的同一正式资源和表现逻辑。单元阶段验证可编辑源、许可、正式导出、稳定引用、Creator/目标设备及独立/组合双入口；未来主体接入后的第三入口实测届时补验，不声称现在已通过。

## 本阶段之后的依赖

四专业 v0.2 分别获用户批准后，Master 编排正式可编辑逐帧/骨骼/图集/UI/VFX 资产制作、Art/Tech 每次出图前联合签认，以及 Client `FEATURE_BRIEF.md` 与 QA `TEST_PLAN.md` 开工包审批。Client 接入 Creator、运行取证、实现评审、QA 测试与用户确认均是独立后继阶段，不因当前设计获批自动完成。
