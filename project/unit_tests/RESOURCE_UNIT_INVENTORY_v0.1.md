## 建议的可切换单元：8 个基础单元 + 1 个性能单元

公共菜单只负责进入、退出、重置和显示该单元的验证目标，**不计入单元数量**。每个单元单独场景/入口、单独验收和迭代；需要其它对象时可先用测试占位物，避免重新拼整张夜市。

| 编号 | 单元 | 主要验证 | 可直接复用 | 待补 |
|---|---|---|---|---|
| U01 | 瓦片地图 | 4 类 Tile 拼接、等距坐标、边界与小地图显示 | 4 张瓦片 PNG、TMX | 小场景样例与坐标/边界可视化 |
| U02 | 镜头与手势 | 独立小地图上的拖动、双指缩放、边界限制；桌面/手机输入 | U01 地表 | 输入逻辑与实际触控验证 |
| U03 | 建筑占格与通行 | 每个建筑 Prefab 标记占用瓦片；精灵不得穿过阻挡格，并能看见占格覆盖层 | 5 类建筑 Prefab、瓦片 | 建筑占格数据、阻挡检测；桥面可走，桥栏/桥墩阻挡需分区标记 |
| U04 | 建筑与装饰四方向、状态 | 桥、殿、摊位、灯笼和岸树在四方向切换时锚点和占格不漂移；摊位破败/修复切换 | 现有单向图及两态摊位 | 建筑与装饰的四方向图；两态摊位各方向对齐规范 |
| U05 | 精灵四方向与移动 | 店长/三类顾客在四方向移动、待机、转向时脚点稳定且不穿阻挡格 | 角色静态图、顾客单方向两帧 | 四方向角色帧；店长的必要方向表现 |
| U06 | 精灵与建筑遮挡 | 用少量建筑和精灵，单独检查前后、桥栏、屋檐和脚点排序 | 现有建筑/角色图可作问题复现 | 可用的前景层/遮罩或经批准的简化验收标准 |
| U07 | 场景轻特效 | 分别开关灯笼明暗、地面反光、水波、树叶摆动，观察效果与成本 | 灯笼、树、水面静态图 | 独立 VFX/动画方案和所需素材；先定手机性能预算 |
| U08 | UI 与交互 | 菜单切换、按钮状态、修复确认卡、输入优先级与安全区 | UI 规格与评审图 | 运行 UI 素材、菜单及交互实现 |
| U09（可后置） | 同屏密度与性能 | 逐级增加瓦片、建筑、精灵、特效数量，记录 FPS、帧时间、DrawCall、内存 | 前面单元的已验证组件 | 代表手机和可重复的采样场景；不把桌面瞬时 FPS 当结论 |

## 两个先确认的边界

1. **四方向资源是新制作量**：当前建筑、角色及装饰运行图均只有一个等距观察方向；镜像或旋转不能直接算作四方向图。每个相关资产在 U04/U05 中逐项登记四方向是否齐全，再决定制作顺序；特效若随实体朝向变化，也必须核对四方向表现。
2. **视觉占位与阻挡占格分开**：建筑画面可跨多个瓦片，但真正阻挡的格子要独立标记。桥既是建筑又承担通行，默认把桥面标为可走、栏杆和桥墩标为阻挡；若用户希望整座桥不可通行，需要另行调整旧路线设定。

本草案只决定**有哪些验证单元**。每个单元的尺寸、资产数量、通过标准和开发顺序，待用户确认清单后分别细化。
