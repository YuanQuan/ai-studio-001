# 首个可复用单元实战对象选型｜v0.3

状态：`USER_APPROVED`（仅选型与方向范围）。本版按用户最新要求修订 v0.2：孟桃和奶茶店不制作四方向；需要行走转向的旅客（顾客）才需四方向。继续排除现有图片、Prefab、动画或 UI 图稿作为本次生产资产。

## 选型结论与来源边界

建议以**“孟桃的奶茶店”**作为首个从美术到运行效果的实战单元：经营方向为奶茶/饮品，店长为历史角色概念种子**孟婆外孙女·孟桃**。历史设定写明她“叛逆甜品控”“不想继承汤铺”，长期梦想是开自己的奶茶店，玩法钩子为“饮品/奇遇”。来源：`project/research/历史市场调研与方案_v0.2/03_世界观与角色叙事框架.md` 第 7 节。

**批准状态必须分清**：该资料把孟桃列为“用于角色会，不等于定稿”的概念种子。当前 `PRODUCT-001 v0.7` 仅定义店铺品类、经营与店长配置等模块方向，未批准首店品类、孟桃作为首店店长、具体饮品或经营数值。旧 `DEMO-001` 的中央修复摊位也没有定义经营什么、店长是谁。因此“孟桃的奶茶店”是有历史文字依据的**本次选型建议**，不是声称既有正式 PRD 已锁定该组合。

| 候选 | 历史文字中的经营和人物关系 | 首个完整样例适合度 |
|---|---|---|
| 孟桃的奶茶店（建议） | 孟桃明确想开自己的奶茶店，关联饮品/奇遇 | 一组对象可验证店铺、店长的单视角骨骼、经营状态 UI、饮品制作表现与特效；角色和店铺关系最直接 |
| 猫又·阿满的杂货铺 | 阿满想开杂货铺，关联杂货/招客 | 可验证货架和角色，但首轮商品种类与展示面更分散 |
| 河童·阿泽的寿司店 | 阿泽想做鬼市寿司，关联餐饮/制作 | 可验证制作动作，但食材与制作流程需要更多尚未定义的产品细节 |

## 已有文字与待确认内容

- **可作设计输入的历史文字**：孟桃的身份关系、性格、梦想和饮品方向；项目总体的温暖、市井、轻神秘、轻喜剧气质；店长可与经营品类、店铺外观形成可见关联。
- **尚未被产品批准**：孟桃是否为正式角色、是否担任首店店长、奶茶店是否为首店、具体售卖饮品、制作流程、订单、收益、修复或开店方式、店长技能、角色事件内容和数值。Product 须先将本轮需要的最小语义写入新 Artifact 供用户批准，不从旧 Demo 复制一次性“修复”规则。
- **本次单元最小可演示关系**：店铺与店长同屏，保持当前游戏视角；基础工作动作可见，界面显示经批准的店铺与店长身份；制作/营业等状态只在 Product 定义后接入。无需先建立完整经营经济系统。本轮不包含旅客正式资产。

## 从零制作与同源复用要求

1. 不复制、切图、描摹或改造 `apps/client/assets/demo/`、旧 Demo 的摊位/店长 PNG、Prefab、现有 UI 评审图，亦不把旧程序占位形体作为正式美术。旧文件仅保留历史追溯；本轮生产源从新的原创设计和可编辑分层文件开始。
2. Art 在出图前提交店铺与孟桃的单视角概念、骨骼拆件、店长工作动作和店铺可动部件清单，并完成参考来源/授权检查。角色外形尚无已批准定稿，不从现有幽灵店长图片推断孟桃长相。
3. 每个需要骨骼动画的对象各规划一张贴图/图集；店铺与孟桃是两个可独立迭代的对象，不强行合成同一张图。动作、状态、尺寸和合批由 Art 与 Tech Lead 在出图前共同确认；不为本轮两对象制作无用途的四方向资源。旅客的四方向要求留给后续独立旅客单元，并须兼顾其动作与图集尺寸。
4. UI 将店铺卡、店长信息和状态控件设计为可复用组件；系统/美术字体及图标先记录来源与许可。演示专用重置和诊断控件与正式界面隔离。
5. VFX 只围绕获批状态制作必要反馈；不预设具体饮品配方、魔法效果或经营奖励。店铺、角色、UI、VFX 的正式源产物在单元入口和主体游戏入口复用同一版本。
6. QA 检查店长与店铺关联、单视角脚点/锚点、图集/骨骼资源、交互与 UI 一致性、授权记录及目标设备表现；四方向行走验收属于后续旅客单元。

## 下游门禁

本版选型确认后，Product 先固定“孟桃、奶茶店及本轮最小状态/动作”的产品语义，再经 Art 与 Tech Lead 的出图前评审、Art/UI/VFX/Tech 各阶段审批，之后才由 Client 制作正式 Creator 产物并由 QA 验证。`CP-UNIT-REUSE-001` 的同源复用契约仍需完成评审与批准。本次选型批准不等于批准角色造型、奶茶商品、经营规则或旧 Demo 资源。
