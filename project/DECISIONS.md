## DEC-UNIT-MENU-WEB-TEST-005 — 示例1分阶段 Web 多分辨率测试

- 日期：2026-10-05
- 状态：`ACCEPTED`（用户明确选择路径并澄清测试对象；技术稿、Client/QA 开工包与性能预算仍须各自审批）
- 范围：单元示例1当前四层场景接入和现阶段 Web 运行验收。
- 决策：先审场景接入方案，运行验收前另审测试矩阵及性能预算。现阶段所谓“真机测试”指 Web 端多个模拟手机分辨率测试，不是实体手机测试；实体机型号、小游戏容器与发布平台实测不作为本阶段开工门禁，也不得据 Web 模拟结果标记它们 `PASS`。具体模拟视口、浏览器、DPR、硬阈值和降级方案由后续正式 Artifact 提案并获批。
- 理由：用户直接选择分阶段推进，并明确纠正“真机测试”的含义。
- 受影响 Artifact / 角色：Tech Lead、Client、QA、Producer；`project/changes/CP-UNIT-MENU-WEB-TEST-GATE-002.md`、已批 `UNIT-MENU-TECH-DESIGN-001 v0.2` 的性能门禁文字及待修订 Client/QA 开工包。
- 迁移 / 回滚说明：旧版保留历史，不改写既有审批。Tech Lead 在新版本说明条款差异，Client/QA 据获批新规格修订；未来如需实体机或小程序发布验证，另立范围和门禁。

## DEC-UNIT-DIRECTION-003 — 平视角精灵左右复用

- 日期：2026-10-02
- 状态：`ACCEPTED`（用户明确指令；资源分件、翻转例外及运行细节仍待 Art/Tech 正式规格审批）
- 范围：当前平视角的单元示例与后续主体游戏中需要横向移动的精灵。
- 决策：取消四方向资源与验收要求。移动方向仅左、右；同一骨骼动画对象只制作一个方向的原始美术资源，另一个方向使用水平翻转复用，不重复绘制。店铺与固定视角店长仍按实际使用视角设计。翻转后的字形、标识、非对称饰件、持物、动作手势、光影、骨骼挂点、座椅接触和遮挡必须在正式 Art/Tech/QA 规格中验证，不能因技术上可翻转就自动判定视觉通过。
- 理由：用户明确将当前视图改为平视角，并要求以单方向反转覆盖精灵左右移动，降低重复资产量且保持后期主体游戏同源复用。
- 受影响 Artifact / 角色：Product、Art、Tech Lead、UI、VFX、Client、QA；`project/changes/CP-UNIT-MENU-SCOPE-001.md`、`tasks/UNIT-MENU-PRODUCT-001/` 及其后续规格。
- 迁移 / 回滚说明：本决定在方向范围上覆盖 `DEC-UNIT-DIRECTION-002` 及 `DEC-UNIT-DEMO-001` 的旧四方向条款；既有已批准文件保留历史，不静默改写。仍待用户审批中的相关专业 v0.1 稿须修订或补充新版，不能按旧四方向要求进入制作。

## DEC-UNIT-DIRECTION-002 — 对象方向资源范围

- 日期：2026-10-01
- 状态：`ACCEPTED`（用户本轮明确指令）
- 范围：当前游戏的独立单元与后续主体游戏资产
- 决策：店铺与店长不要求四方向资源，按其实际使用视角设计；需要行走转向的旅客（顾客）须有四方向表现。动态对象仍按骨骼动画及单对象单贴图/图集的项目提案进行出图前技术、美术评审；方向要求按对象适用，不为店铺或店长制作无用途的方向图。
- 理由：用户明确指出店长和店铺不用考虑四方向，旅客需要；减少无用途图片面积和制作量，保留旅客转向的可读性。
- 受影响 Artifact / 角色：Product、Art、Tech Lead、UI、VFX、Client、QA；`project/unit_tests/PILOT_SELECTION_v0.3.md`、`project/changes/CP-UNIT-REUSE-001.md`；`DEC-UNIT-DEMO-001` 中“建筑等以四方向图为目标”的条款在方向范围上由本决定覆盖。
- 迁移 / 回滚说明：已批准的 U01–U09 实施数量不变；旧 U04/U05 的四方向占位与缺口说明保留为历史，不作为新一轮店铺/店长正式资产验收条件。旅客单元仍须单独验证四方向。
