# CP-UNIT-MENU-WEB-TEST-GATE-002｜单元示例 Web 多分辨率测试与分阶段门禁

状态：`USER_DIRECTION_ACCEPTED`；记录日期：2026-10-05。用户在示例1 Gate2 获批后明确选择“分阶段推进：先审场景接入方案，真机与性能预算在运行验收前另审”，随即澄清这里所说的“真机测试”现阶段实际是 **Web 端多个模拟手机分辨率测试**，不是实体手机测试。本提案记录该最新明确方向；具体技术规格和性能数值仍要形成正式 Artifact 并单独审批。

## 已确定的范围与时序

1. 先形成四层场景的 Creator 接入技术规格、Client 开工包和相应 QA 计划，按各自专业 Review 与用户审批推进。当前 Gate2 只放行获批的四张切图版本供正式接入流程使用。
2. 现阶段运行验证对象是 Web 构建在多个模拟手机分辨率/视口中的画面、交互与可取得的性能记录。分辨率、宽高比、DPR、浏览器/模拟方式、采样步骤和数值预算由 Tech/Client/QA 提案；用户在运行验收前审核确定。
3. 本阶段不以实体手机型号、真实手机 OS/芯片/内存或微信/抖音小程序真机数据作为开工或 Web 运行验收门禁。尚未做的实体机、小游戏容器与发布平台验证标记 `NOT_TESTED`，不得把 Web 模拟结果外推为其 `PASS`。
4. 性能硬阈值与允许降级仍待正式预算版本和用户批准；预算前可记录原始数据，不给数值达标结论。资源可见性、触控优先级、四层重组及画面一致性仍按获批产品和资源版本验收。
