# U03 六店单店切换｜客户端编码前概要 v0.1

任务 `U03-SHOP-CLIENT-BRIEF-001`。正式输入为已获用户批准的 U03 Product、Art Gate1、Tech、UI 四份 v0.1；本稿只锁实施边界，未修改 Cocos 工程，也未导入或运行任何 U03 店图。用户已明确声明本次附件由本项目生成/制作且允许商用改编为六店 PSD 与游戏资源，Producer 于 `project/APPROVAL_LOG.md` 17:43:15 记为独立 `USER_DECLARATION`。具体工具合同、外来素材、正式牌匾字形来源仍待 Art/Tech 首图前同批预签；切片接入另须 Art Gate2 具体版本用户审批。

## 1. 目标与范围

在当前 `UnitSamples.scene` 菜单加入独立 U03 入口，六店仅呈一店，初入与重入均从 01 奶茶店开始；“上一店/下一店”按 `01→02→03→04→05→06→01` 循环。六店固定为奶茶、糖画、炭烤、理发、花灯、投壶。每次提交店体、牌匾、名称、接地影与该店专属静态光为同一身份。奶茶和理发屋顶不出现大杯、大剪刀。页面只做静态店铺展示和控制，不新增角色、经营、动画、特效、完整街景浏览、服务端字段或持久化。

U03 入口仅在六份同版正式资源均已 Gate2 批准、完成导入并通过结构检查后可进入；未就绪时显示“资源未就绪”并禁入。UI 示意 SVG、用户全景附件、旧奶茶概念不得作为临时可运行店图。单店加载失败是运行异常，保留真实旧店和明确错误提示，不把缺店视为完成。

## 2. 现有能力与增量

沿用当前 `UnitSamples.scene`、`UnitSampleGallery.ts` 的根节点、`720×1280` `FIXED_WIDTH`、菜单导航与基本文字/按钮绘制能力，并复用已批 `LAB_ACTION_BUTTON` 的状态语义；是否把当前 `button()` 抽成一个共享小控件，取决于实施当时 U02 代码，避免两套类似命中逻辑。U03 的店容器、状态机和六项索引是新增的 Lab 逻辑；六个顶层店 Prefab/贴图放 `units/shops/`，供未来主体游戏同源使用，页面自身只保留导航、布局、状态提示。U01 镜头控制器不是 U03 控件或店镜头的复用对象，不改其四层视差与拖缩行为。

当前 Gallery 只有 U01 单入口；U02 也仅处于已批设计/计划阶段，不能把它写成已存在的 Creator 节点。实施时重新核工作区：若 U02 已按批准版本实际接入，U03 在其上增一张入口；若仍未接入，U03 只与 U01 并列。每张可见入口需有编号、名称、简短用途和明确进入操作；不得恢复旧九实验入口。详细源哈希与输入风险见 `U01_U02_IMPACT_AUDIT.md`。

## 3. 结构、状态与资源

推荐由 Gallery 负责菜单和页面生命周期，U03 专用页面控制器负责六项切换状态、请求代次与原子提交。`ShopDefinition` 为只读的六项有序本地表：产品序号、稳定资产 ID、UI 显示名、唯一顶层 Prefab 引用、资源登记版本。第 01 项正式对象身份继承 `MT_SHOP_01`；02–06 为 `SHOP_02` 至 `SHOP_06`，其 Art `U03_SHOP_0x_MASTER/VISUAL` 是同店 PSD/导出登记名，不是额外可运行 Prefab。牌匾必须包含于同一店 Prefab 的已批切片层序，不由页面拿公共牌匾临时拼接。

首选六个序列化 `Prefab` 强引用随 Gallery/Scene 装载，以便 Creator 资产依赖可见、UUID 可核、场景进入前检查六项完整；需要异步加载时，改用显式登记的 typed Prefab 路径/UUID 清单和单一加载入口，不按节点名或文件名猜资源，保持相同 `generation` 状态机。两种策略必须在实际六店贴图尺寸和冷/热进入耗时测量后由 Tech/Client 确认；不能为了快切预建六个可见店实例。只保留一个已呈现店实例，资源缓存可按实际内存选择六店常驻或当前加邻店预取。

无论最终采用强引用或异步加载，都经同一 `requestShop(target,generation)` 适配边界把 Prefab 就绪、结构校验和可提交结果交给状态机。获批实施 Task 内的**测试构建专用**确定性适配层可按用例配置目标、请求代次、延迟与完成顺序，或返回 `MISSING/DECODE/STRUCTURE/TIMEOUT` 分类失败；强引用同步可得时也可延后交付结果以复现 02/03 乱序。注入层不改正式 PNG、Prefab、`.meta`、UUID 或正式引用，生产构建默认禁用且不暴露给页面用户；测试记录注入配置、测试构建 hash 和资源 Gate2 版本。模拟解码失败只验证状态机的失败处理，不冒称真实解码器故障已测；真实解码器专项需在适用异步加载路径另取证。完整接口与时间戳见 `STATE_AND_RESOURCE_PLAN.md`。

状态为 `CLOSED/LOADING/READY/ERROR`；`presentedIndex` 指向实际可见店，`desiredIndex` 指向最近请求目标，`failedTarget` 只用于失败后的定向重试。连按从 `desiredIndex` 递推，完成请求仅最新 `generation` 可提交。切换时旧完整店保持可见，身份栏继续描述 `presentedIndex`，切换提示描述 `desiredIndex`；目标完整就绪后先在非活动节点准备并校验同店层，单帧隐藏/移除旧店并激活新店，再更新已呈现身份。不暴露双店、半套牌匾、旧阴影或错误名称。完整转移和失败回退见 `STATE_AND_RESOURCE_PLAN.md`。

## 4. 协议、平台与审批

无 Server/API、经济数据或大型第三方依赖。Cocos Creator 固定当前 3.8.8；Web-mobile 为后续功能冒烟环境，真实平台性能不得从 Web 推断。竖屏按 `view.getVisibleSize()` 与 `sys.getSafeAreaRect(false)` 计算安全区。`720×1280`、`390×844` 是已批规格候选视口，不是已通过的设备指标。店体保持同一地线、等比 `contain` 和自然宽度，不为填满页面拉伸伞车或架体；控件位于单店展示区外，牌匾不可被遮。UI 当前页只有上一店/下一店与返回，不加重置或滑动手势。

本 Brief 与同轮 QA TEST_PLAN 均须单独专业 Review 和用户批准；Art Gate2 对具体切片、同尺度重组及版本也须另获用户批准。按本 Task 验收，两类批准齐备且 Master 解锁实施后才正式编码或导入六店资源。附件商用改编已有用户声明，但首图前预签还须核具体工具合同、外来素材及原创牌匾字形来源；该声明不批准图片生产结果或 Cocos 接入。计划路径不等于 Creator 已存在资源或已回填 UUID。

## 5. 性能与生命周期

切换由事件驱动，无 U03 持续 `update()`、轮询定时器或粒子；请求代次递增和可缓存 Prefab 避免无效重复实例化。离页令 `generation` 失效、解绑本页按钮/视图监听、销毁当前与临时店实例、清除页面持有的引用；若资源被主体入口共用，不做破坏式全局释放。纹理尺寸、图集页数、透明混合、DrawCall、峰值内存、冷/热切换时延和 GC 要由真实六店切片与构建测量。Tech v0.1 未锁具体 FPS/MiB/毫秒阈值；QA 计划应记录测量条件和待审批判据，缺实测一律 `NOT_TESTED`。

## 6. 日志与调试

稳定标签 `U03_SHOP`，日志中文描述并带 `shopId/desiredIndex/presentedIndex/generation`；加载失败带稳定错误类别与 `failedTarget`，避免把资源路径或字牌文本当身份。候选调试入口为单元菜单 U03 页面，不新增独立 Scene 或临时可运行假店。故障注入只在获批测试构建的请求适配边界执行，必须记录构建、注入配置与资源版本。

低开销诊断以同一单调时钟记录菜单/切换输入、请求开始、Prefab 就绪、结构校验、原子提交、下一帧完整可操作画面，以及失败/取消；每条带 `generation`、目标与已呈现 ID、缓存冷热标记和错误类别。测试构建可记录逐帧序列、活跃店实例与本页监听/待处理请求数；正式构建关闭详细逐帧/注入路径，不用测试开关改变交付资源。计时终点不得停在“旧店仍显示”或仅在实例化函数返回时，须由完整新店可操作画面确认；计数工具不可用时相关 QA 指标保留 `NOT_TESTED`。

## 7. 验证出口与风险

实施先核工作区差异、源哈希、Scene/Prefab 活动引用及可恢复副本；再做受控变更、静态对象图检查、Creator 3.8.8 导入和 CLI 构建；用 loopback HTTP 提供本次实际 Web 输出，并在 Codex 内置浏览器实际点按 U01/U03（若届时已接入 U02，也检查 U02）。记录构建源、退出日志、输出路径、视口/DPR/安全区、六店同尺度截图、01↔06 边界、连按 01→02→03 与 01→02→01、失败与重试、返回重入、U01 镜头往返。Editor 或目标平台专项依获批 QA 计划补证；静态文档、SVG 或旧构建不能代替运行通过。

主要风险：输入的 MOUSE_UP 与 TOUCH_END 可能对一次点击双发；U01 透明按钮间隙须保持可拖动；六个 Prefab 强引用可能增加首载与内存；贴图 trim/alpha/牌匾投影可能导致错位或不可读；具体工具合同、外来素材和正式牌匾字形来源待预签，Gate2 尚未批准。Tech Lead 评审重点为输入去重、强引用与异步取舍、资源身份/UUID 和单帧提交时的生命周期。
