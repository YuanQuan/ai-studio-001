# 单元示例1｜四层场景客户端功能概要 v0.1

任务：`UNIT-MENU-SCENE1-CLIENT-BRIEF-001`。本文是 Client 编码前方案，引用已批准的 `UNIT-MENU-SCENE1-SCOPE-001 v0.1`、`UNIT-MENU-FOUR-LAYER-CUT-001 v0.3` Gate2、`UNIT-MENU-SCENE1-TECH-RUNTIME-001 v0.2` 及 `DEC-UNIT-MENU-WEB-TEST-005`。本概要待专业 Review 与用户审批，不代表 Creator 已实现或运行通过。

## 1. 目标与范围

规划在 Cocos Creator 3.8.8 中接入一份四层固定背景 Prefab，并提供独立示例1入口、镜头拖动/缩放/重置和隔离的 Lab 操作控件。背景采用获批的四张全画布 PNG，保持相同 2172×724 画布、原点 `(0,0)`、从后到前顺序和批准像素；层水平移动系数为 `[0.3, 0.8, 1.0, 1.0]`。四层共用同一倍率与垂直中心，仅水平视差不同。

本概要只包含四层背景及镜头。画内树、灯廊、桥灯、纸船/烛光均属于固定图像；不增加角色、店铺、板凳、第4项独立可切换对象或第7项组合场景内容。S04 与 S07 的未来对象开关仅定义接缝边界，不在本任务实现。无网络/API/服务端规则变更。

## 2. 已有能力复用

- Creator 工程为 `apps/client/`，`package.json` 锁定 Cocos Creator `3.8.8`；当前有 `assets/UnitSamples.scene` 与 `assets/UnitSampleGallery.ts` 作为独立单元入口及画廊实现参考。仅审阅复用，不修改它们。
- 既有 `apps/client/assets/demo/` 含旧 Demo 场景、Prefab 和图像，身份与批准版本不同，不复用其资源作为本场景底板，也不复用旧 UUID。
- 优先沿用 `UnitSampleGallery` 的入口/退出方式以及当前工程已有的视口与触控基础能力；如源码审计发现与隔离 Lab 输入冲突，Feature 实现时再提交 Tech Review，不能在本概要中推断已有通用镜头组件。
- 不新增第三方依赖，不在本任务引入通用相机框架或跨单元重构。

## 3. 结构与镜头方案

建议只增量建立：正式背景 Prefab `STREET_BASE_01`（四张 Sprite，固定层序和同尺寸布局）、独立示例1 Lab Scene `apps/client/assets/labs/menu/scn_unit_menu_scene1.scene`（引用该 Prefab 并承载输入/镜头控制；本文件尚未创建，需 Client Brief 与 QA Plan 获用户批准后才实施）、菜单 Lab 控件（通过公开镜头命令调用拖动、缩放、重置状态，不进入正式背景 Prefab）。现有 `UnitSamples.scene`/`UnitSampleGallery.ts` 仅增加独立场景的导航入口与切换，不承载场景画面或镜头运行职责。目录、文件名和待创建资源列于同版 `SCENE_PREFAB_PLAN.md` 与 `ASSET_HANDOFF_PLAN.md`。

镜头状态采用 `{cameraX, z}`，沿 Tech v0.2 公式按有效竖屏视口重算覆盖比例、水平边界和四层位置。缩放锚点使用扣除适用安全区后的有效视口中心，垂直镜头中心固定；缩放后重新夹取 `cameraX`。视口或 DPR 改变时从视口参数重新计算几何边界，不把一个 Web 模拟尺寸写死在 Prefab 中。重置及离开再进入清除拖动、双指缩放和惯性状态并恢复用户最终批准的初始状态。

### 待审镜头候选（不是已锁体验规格）

| 参数 | Client 候选 | 依据与限制 |
|---|---|---|
| `zMin` | `1.00` | Tech 定义的适高覆盖几何下限 `sCover=max(Vw/2172,Vh/724)`；低于 1 可能在上下露出未绘区域。若特定竖屏的横向覆盖条件不成立，应报告阻塞并请求技术/美术决策，不夹出负区间。 |
| `zMax` | `1.80` | Gate2 浏览器候选预览出现过的探索上限；作为开工方案的可复核候选，尚未有 Creator/Web 体验确认，也未获用户批准。若视觉检查显示过度裁掉桥区，应由 Client/Tech 提交新的同尺度视图依据。 |
| 初始 `cameraX` | `0` 源像素 | 以全画布水平中心为起点。获批重组图的主桥接近画布中轴，且 Product 要求桥区可辨、没有要求首帧显示月亮；此候选应在 Creator 首帧截图中确认桥区语义后再锁定。 |
| 初始 `z` | `1.00` | 以最大竖向场景范围呈现作为首帧候选，随后用户可放大；与初始 `cameraX=0` 共同待用户批准。 |

严格区分：`zMin=1` 是 Tech 几何下限约束；`zMax=1.8`、初始 `{cameraX:0,z:1}` 是体验候选。用户批准 Client Brief 前不把它们写成项目正式参数。Tech 建议 S03 在近景有效移动至少 100 个逻辑显示像素时，位置公式偏差不超过 1 逻辑显示像素；本概要引用该待批准测量建议，不宣称完成测量。

## 4. 输入、视口和生命周期

- 鼠标主键水平拖动与浏览器设备模拟单指拖动更新同一 `cameraX`；鼠标滚轮/明确 Lab 缩放控件与设备模拟双指缩放更新同一 `z`。是否使用 DevTools 多点触控及详细输入来源由后续 QA 测试计划提出，本概要不锁测试矩阵。
- 输入起点命中 UI/Lab 区域时由 UI 捕获整个指针序列，不传给背景；背景手势开始后 UI 按钮仍优先处理新指针。松开、指针取消、移出浏览器、其中一根双指落入 UI、手势切换或点击重置时清空旧基准，避免镜头跳变；场景不加惯性，降低边界与取消处理复杂度，若用户要求惯性需另行说明边界策略。
- 边界始终按当前有效视口计算并夹取；松手维持合法区域。窗口缩放或模拟分辨率切换结束后以新视口重算覆盖范围，并保留可见场景位置的最近合法值。
- 进入场景获取已登记的正式资源引用并恢复最终批准的初始镜头；退出取消事件订阅与指针状态，释放本场景拥有的临时对象。具体资源缓存/释放策略服从现有工程生命周期约定，先审源码再定实现。

## 5. 协议与平台影响

不涉及 API、服务端、存档或配置表。当前开发和计划运行环境限定为 Web 浏览器中的多个模拟手机竖屏分辨率；不是实体手机测试。Creator 精确版本已从工程配置核对为 3.8.8。具体浏览器、版本、操作系统、模拟视口、DPR、渲染后端与输入模拟矩阵须在运行验收前由 Tech/Client/QA 提案并获用户批准；本 Brief 不锁定矩阵，也不要求微信/抖音容器或实体设备。

## 6. 性能与资源风险

- 单场景四张 2172×724 RGBA 全画布纹理。Tech 的 RGBA8 面积估算为 `4×2172×724×4 = 25,160,448 bytes`（约 23.99 MiB），只表示未压缩像素面积，不代表运行时峰值、构建纹理格式或达标结果。
- 最大宽度 2172 超过部分 Web 后端/纹理格式的 2048 上限；需在后续真实 Creator 构建及获批 Web 矩阵检查，不能凭静态工程配置声称兼容。如果目标后端不支持，停止替换/缩图，提交浏览器与渲染后端证据及分片/格式方案、视觉影响供审查。
- 四层各一 Sprite，固定显示，无每帧创建对象、定时器或持续动画。镜头只在输入、重置和视口变化时更新状态/节点变换；避免每帧轮询和 GC 分配。观察实际 DrawCall、纹理解码/加载、Web 回退格式、透明过绘及过滤边缝。
- 性能数值预算尚未批准。本概要不锁 FPS、帧时间、DrawCall、内存阈值和降级值；验收前另提交 Web 多模拟分辨率矩阵与性能预算，未批准前只能记录原始数值，不能判 `PASS`。
