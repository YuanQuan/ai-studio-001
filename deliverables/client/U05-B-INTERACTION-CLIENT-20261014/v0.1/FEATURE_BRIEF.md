# U05 台面选料与顾客反馈：客户端功能概要 v0.1

状态：首份实现前概要，待 Tech Lead 对实现边界与生命周期意见。上游 UI v0.1 交互规格已获用户批准；Art 当前只有资源需求/生产计划，顾客新脸与静态局部净底的实际资源尚未 Gate2 批准。本文只冻结客户端实现建议，不代表新资源接入、Creator 构建或新交互运行已完成。

## 1. 目标与范围

在当前 U05 Lab 中，将选料呈现从“立即进入杯内”调整为台面三个无热区视觉槽；同类重选替换、撤销清对应槽。点击“确认”时，以单一单调时刻对现有 `submitCup(run, nowMs)` 判定一次，保存本单不可变显示快照，再由独立表现事务播放台面至杯内的约 650ms 合成和对应结果流程。错误留当前顾客/订单供重做；正确非末杯按完整离场、下一客入场流程；最后一杯保留已判胜利；到时与主动退出按已批规则中断或离场。

订单杯整组缩放至 0.78。顾客/表情同一移动组在固定窗口 mask 内完整移动 381 源像素；时间、奖励、截止、存档和产品规则不变。旧 `setExitHandler(handler)` 及 `onExit` 兼容保留。

本轮代码允许范围仅 `apps/client/assets/labs/u05/` 及本 Task deliverables。新脸图、窗口/台面净底、动画片等 Gate2 前不复制到正式客户端、不绑定为已可用视觉资源、不部署覆盖 8876 旧服务，也不宣称新版素材实际试玩通过；Gate2 后的正式资源接入与新产物实跑由 Master 后续授权。

## 2. 现有能力复用

- 复用 `milk_tea_state.ts` 的 `Run`、`submitCup`、`expireRun`、`remainingSeconds`、`settleWin`；业务状态唯一决定判定与奖励，表现层不二次提交或自行结算。
- 复用现有三类原料配置/素材、杯壁和 183×233 `CUP_*` 透明画布；杯层继续关闭 Sprite trim。现有资源仅用于已获批内容，不能替代尚未批准的台面净底和顾客新脸。
- 复用 `milk_tea_lab.ts` 输入热区、BMFont、按钮、原有退出确认/重试/结算入口及生命周期清理；只扩展 U05 私有组件，不新增公共框架、依赖或改 Gallery/package/业务配置。
- 上游输入身份为 `tasks/U05-B-INTERACTION-SPEC-20261014/ARTIFACT_APPROVAL_v0.1.json` 中批准的 UI v0.1；Art `ASSET_REQUIREMENTS.json` 是 Gate1 需求，不能当 Gate2 资源批准；Tech `TECH_REVIEW.md` 明确代表片段/遮挡与运行仍待测。

## 3. 结构设计

建议在 `U05MilkTeaLab` 增加与业务 `Run` 分离的可序列化内存表现状态 `PresentationTransaction`：`epoch`、事务阶段、创建/阶段起始单调时间、不可变订单/三类 ID/结果快照、阶段序列及所需显示状态。输入处理先检查是否有活动事务及状态是否 `playing`；“确认”只取一次 `nowMs`，在调用 `submitCup` 前复制订单索引和三类选择，在同一 `nowMs` 调用一次 `submitCup`，以返回结果补齐快照并锁定再入。未选齐不建事务。事务阶段只消费快照，不读已清空或已推进的 `run.selected/orderIndex` 来重绘旧杯。

保留一组稳定的表现节点（台面茶/奶/料、工作杯层、订单杯、顾客身体+脸节点组、固定 mask、气泡）；节点创建/资源绑定与 `render()` 页面状态重绘分开。普通输入或状态边界可重绘交互 UI；活动动画期间不得重建整棵表现树。`update()` 仅在活动事务中采样单调 elapsed 并更新固定节点的位置/透明度/脸状态；不在每帧创建 Node、Graphics、Label、闭包或 Tween。阶段边界触发一次文案/UI刷新，计时标签仍按秒更新。动画完成后销毁或复用临时对象，禁用态保持原尺寸。

表现时间线遵循批准规格：合成三项交错淡入/移动至 650ms；正确非末杯开心至950ms、旧客 950–1400ms 完整离场、下一客 1400–1850ms 完整入场，到时解锁；错误失落至1000ms，保持原客并清杯、恢复中性和输入；末杯胜利表现不可被之后的 deadline 反判。超时优先中止非末杯新客队列，失落0–300ms、完整离场300–750ms；退出确认期间时钟继续，确认退出则废弃当前视觉事务、中性完整离场后回选择页且不发奖励。

每个新局/重试/返回/退出/销毁使旧 `epoch` 失效并取消/清理 pending tween、timer 与加载回调；任何回调在写状态前检查 epoch、组件有效性及当前 run 状态。超时与确认竞争时，继续由现有 `submitCup` 的同一 `nowMs` 判定顺序和 `expireRun` 语义决定结果；视觉队列只响应业务状态，不自创胜负规则。目标杯整组（内容、杯壁、吸管、遮罩）围绕 `(653,416)` 同比缩至0.78，不改变气泡位置。

槽位源坐标 `[345,1150,90,84]`、`[467,1150,90,84]`、`[589,1150,90,84]`；顾客停靠 `[309,484,332,301]`，窗口 mask `[260,278,490,505]`，完整移出左上 x=-72、位移-381；订单气泡独立于 mask。表现资源路径抽象为 U05 本地接口，由批准后的稳定 UUID/资源登记绑定；Gate2 之前不引入计划资源路径或伪占位图。

## 4. 协议与平台影响

不涉及网络、API、服务端、配置 schema 或跨端字段；不改 `Run` 的业务判定、deadline、奖励和结算语义。时间计算沿用单调 `performance.now()` 兼容回退，浏览器后台节流时恢复后根据绝对 elapsed 采样终态，不补放已过期队列。Creator 3.8.8 Cocos API 和当前 Web Mobile 为实现路线；此概要阶段不做新构建，也不覆盖旧 8876 来源。

## 5. 性能影响

- 持续工作仅一个组件 `update()`；无活动事务时不做表现采样。活动时每帧只更新既有节点变换/opacity/状态，阶段事件与帮助/计时文案分开，文案不每帧生成。
- 三个台面对象、杯层及顾客/脸组为固定节点；动画事务按 ID 复用节点，避免每帧整 root 重建、GC 和 tween/timer 堆叠。不会新增粒子、Shader、骨骼系统或大型依赖。
- 额外 DrawCall/纹理数量依赖 Gate2 具体资源及图集，当前未知；优先复用已批准图集并在接入后统计。未批准脸/净底不以系统字体或程序图形冒充正式美术。
- 异步资源加载去重并纳入组件生命周期释放；事务 epoch 与组件销毁 guard 阻止迟到回调改新局或访问销毁节点。
- 小屏保持完整 B 画面 contain，表现槽不新增热区；窗口裁剪仅包顾客身体/脸，气泡和订单杯不进 mask。

## 6. 日志与调试

沿用独立 U05 Lab，不新增调试入口或持久化字段。仅对资源加载/绑定失败和无效事务阶段记录带稳定标签 `[U05 Presentation]` 的中文诊断；每次新局 epoch、重复确认被忽略、资源未批准不可用等可在验证模式下观察，正常体验避免逐帧日志。不得通过 DevTools 状态注入冒充真实交互验证。

## 7. 测试与验证

编码后先做纯表现状态与业务桥接测试：三槽 add/replace/undo；确认快照在 `submitCup` 清空选择前冻结；重复确认一次提交；错杯重做；最后杯判胜后跨 deadline 保持胜；非末杯事务中超时不进入下一客；退出确认中超时优先；退出/重试/销毁使旧 epoch 无效；资源迟到回调不触及销毁对象。核现有业务模块与配置哈希不变。

在新资源 Gate2 前，只运行可独立的静态/状态测试，Creator/Web/实际新版试玩标为 `NOT_TESTED`；尤其不部署覆盖 8876。Gate2 批准且 Master 后续授权后，才对隔离 Creator 3.8.8 构建与真实浏览器操作做三槽布局、杯快照、mask 边界、四脸时间线、错杯留客、完整顾客进出、小屏目标辨识、超时与退出回归，并分别登记构建身份和证据。手机触控、原生及性能需在其目标环境另测。

## 8. 风险与 Tech Lead Review

主要风险是 `render()` 当前重建 root 子树会销毁绑定节点；视觉状态和业务状态即时推进的时序不同；绝对 deadline 与长动画/页面节流竞争；Cocos `Mask` / `UIOpacity` 与裁剪坐标实际序列化/节点锚点；Gate2 前缺台面净底和新表情资源，无法验证最终画面。

请 Tech Lead 在批准编码前确认：
1. 稳定节点树与现有 `render()` 重建边界如何切开，是否有更合适的 U05 私有职责拆分。
2. 事务 snapshot/epoch 与单调时序的状态接口、超时和退出竞争是否保持 `submitCup` 唯一判定。
3. Cocos 3.8.8 固定父节点矩形 Mask、目标杯整组缩放、脸/身体同组裁剪的实现细节及需避免的序列化风险。
4. 每帧只写既有节点属性、阶段边界刷新文案的性能与清理策略是否足够。
5. Gate2 前仅代码/状态测试、禁止实际新版资源试玩/覆盖8876的交付边界是否满足本任务技术验收。
