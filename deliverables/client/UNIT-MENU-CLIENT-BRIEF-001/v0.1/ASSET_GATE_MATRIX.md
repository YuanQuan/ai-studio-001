# 七项菜单｜正式资源接入门禁矩阵 v0.1

这是编码前的**依赖清单**，不代表资产已制作或 Creator 已导入。五份专业 v0.2 是本开工包的获批输入；每一批实际图片仍需 Art/Tech **该次出图之前**的双签、正式产物专业 Review 与用户批准。Client/QA 开工包本身还须联合用户批准。资源缺证时禁止将旧九项、概念图、审阅 SVG、程序形体或临时字体作为正式新菜单资源。

## 1. 每批资源统一检查点

| 门禁 | 必备证据 | Client 动作与失败处理 |
|---|---|---|
| G0 已批准语义和规格 | Product v0.2 + 适用 Tech/Art/UI/VFX v0.2 的 `USER_APPROVED`、稳定对象 ID | 对照本批范围；变更先走上游评审，不改场景语义自适应 |
| G1 出图前联签 | 每次源版本/导出对应 Art 与 Tech 记录：参考/IP、图片和字体许可、状态/方向/骨骼分件、像素范围、alpha/pivot、图集尺寸/页数、材质/合批、内存、Creator 工具版本 | 无双签或签认晚于输出即拒绝该导出作为正式资源；返工后重新联签 |
| G2 正式源和导出 | 可编辑原创母版、逐帧/骨骼或静态分层源、导出参数、真实 PNG/atlas/骨骼数据、源/导出 hash、版权许可；实际结果与 G1 一致 | 核文件真实存在及状态；概念/旧 Demo 禁止导入 `units/`；不以文件名相似判同源 |
| G3 资产批准 | 该批 Artifact 专业 Review 通过、用户明确批准对应版本；变更源/帧数/页数/字体/工具需重新签认及必要审批 | 未批准项只显示“资源未就绪”，不接正式运行；其他已批准项可独立推进 |
| G4 Creator 导入 | 3.8.8 工程实际导入日志、`.meta` UUID、Prefab UUID/依赖 UUID、动画/材质/混合与字体引用；实际帧裁切、骨骼版本和单页检查 | 导入失败或 UUID 分叉时阻止入口放行；不以引擎模块开启推断导入成功 |
| G5 双入口运行 | 对象独立入口与组合入口相同 Prefab UUID、资源 UUID/hash、状态逻辑；仅允许位置/朝向/Lab 开关覆盖；目标环境截图/录屏和状态清理 | 有分叉、错层、残留、镜像问题即返工；未来主体第三入口当前 `NOT_TESTED` |
| G6 目标设备与 QA | 构建 commit、源/资源版本、设备型号/系统/比例、安全区、后端、纹理格式/回退、冷/热加载、帧时/DrawCall/纹理/过绘记录及 QA TEST_REPORT | 未测不标 `PASS`；硬阈值须先随获批设备清单确定，超限定位后复测 |

字体单列来源、具体文件和商业使用/嵌入/分发/修改许可；对原字形做改造不等于有授权。所有参考图只用于视觉方向，不复制受保护外观或直接裁切。版权/IP 状态不明时停在 G1/G2，不能由运行验证替代授权。

## 3. 导入后逐项核对与 QA 对齐

幽灵 atlas 页数由实际逐帧尺寸与排图确定，**不**套骨骼单页规则。骨骼一页也不等于一 DrawCall；记录材质、混合、遮罩、Sprite/骨骼切换和 VFX/UI 插层。PNG 压缩体积不是显存数据，按真实纹理格式/回退与 GPU 记录计算。Creator 自动裁切/trim 必须实查脚点和两向座点。

正式导入时产生资源登记：`stableID`、Task/Artifact 版本、源母版路径/hash、导出路径/hash、Art/Tech G1 签认、权利条目、Creator UUID/Prefab UUID、依赖 UUID、允许实例覆盖、独立入口、组合入口、未来主体状态。静态/骨骼/帧图/UI/VFX 均登记。该登记可作为 G5 扫描输入，不代替 QA 实际录屏和性能原始数据。

验收追踪：菜单路由/空景 `A01–A03/B01`；店 `B02`；孟桃 `B03`；幽灵及凳 `B04/C`；树花灯 `B05`；共享 UI/对话 `B06–B07`；组装遮挡 `B08–B09`；所有 G0–G6 对照 `D00–D07`。产品禁止新增经营/剧情规则 `D07` 以文案和依赖扫描确认。QA 计划应给每项 Creator 与目标环境的真实证据格式；现在只有设计，运行证据、性能通过与第三入口均为 `NOT_TESTED`。
