# 百鬼夜市 Demo｜客户端功能概要

版本：v0.2｜任务：CLIENT-BRIEF-DEMO-001｜Owner：Client Agent｜状态：修订待专业复评。v0.1 保留为历史退回稿

## 1. 目标与正式输入

在 Cocos Creator 3.8.8 + TypeScript 中建立可运行的竖屏 Demo：较初始视口更大的夜市地图可拖拽、双指缩放；唯一目标破败摊位可确认修复并出现一名店长；可爱鬼怪顾客从左上奈何桥进入，沿石路经过夜市，从右下桥离开。界面只包含修复提示、确认、关闭与完成提示。重新进入场景回到破败初态。

正式输入为已获用户批准的 [产品规格](../../../product/DEMO-001/v0.1/DEMO_PRODUCT_SPEC.md)、[技术设计 v0.2](../../../tech_lead/TECH-DEMO-001/v0.2/TECH_DESIGN.md)、[美术方向](../../../art/ART-DEMO-001/v0.1/ART_DIRECTION.md)、[资产包 v0.2](../../../art/ART-ASSET-DEMO-001/v0.2/ASSET_MANIFEST.md)及其 [拼装说明](../../../art/ART-ASSET-DEMO-001/v0.2/ASSEMBLY_GUIDE.md)、[UI 规格](../../../ui/UI-DEMO-001/v0.1/UI_SPEC.md)。`PRODUCT-001` 概要仍在用户评审中，不作为本 Demo 的实现输入。

本任务只产出编码前概要。资源、经济、订单、存档、服务端、路径寻路及图中其他按钮均不进入 Demo。

## 2. 现有能力与工程入口

仓库现有 `client/COCOS_VERSION=3.8.8` 和 `client/README.md`，没有 Creator 工程、可复用脚本、组件、Prefab、图集或运行场景。`apps/client/` 是唯一可运行的 Creator 工程根目录；现有 `client/` 仅存 README 与版本标记，不作为另一个工程入口。后续工程 README 要写明从仓库根目录打开 `apps/client/` 以及 Web 构建输出路径，QA 也只使用此入口。新工程不引入公共框架；当实际第二处复用出现时再抽取公共能力。工程版本以 Creator 编辑器及项目设置双重核验，使用内置引擎。

计划目录：

```text
apps/client/
├─ assets/
│  ├─ scenes/DemoScene.scene
│  ├─ scripts/demo/{DemoSession,CameraController,GestureRouter,StallHitTest,StallPresenter,CustomerFlow,DemoUI}.ts
│  ├─ prefabs/{TargetStall,BackgroundStall,BridgeEntry,BridgeExit,YamaPalace,Customer,Keeper}.prefab
│  ├─ textures/{ground,landmarks,characters,ui}/
│  └─ tilemaps/NightMarket/
└─ settings/、project.json 等 Creator 生成的工程文件
```

工程由 Creator 3.8.8 新建空白 2D 项目后放入该目录，编辑器创建 `DemoScene`、TileMap、Prefab 和资源元数据，不手工伪造 `.meta`。保留可提交的工程源；排除编辑器缓存、构建产物和本机路径。先做 Web 预览，再构建移动目标；本任务不执行这些步骤。

## 3. 场景、资源与依赖方向

`DemoScene` 按技术设计布置 `WorldRoot/GroundTileMap`、`LandmarkRoot`、`WalkwayRoot`、`ActorsRoot`、`WorldCamera`、`ScreenCanvas`。四类 256×128 PNG 组成等距地表；两桥、阎罗殿、背景破败摊位和目标摊位作为独立 Prefab。以已批准资产包 v0.2 的 `scenes/`、`props/`、`characters/` 为唯一正式运行图源，按地表、地标、角色分组导入并检查 alpha 与至少 2 px 透明边，保留原件路径与导入映射。概念图和 UI 评审图不直接切作运行纹理。

地图暂以 18×18 个 256×128 等距 Tile 作为首轮拼装网格，世界可显示矩形覆盖边缘水面与岸边装饰。数量是 Demo 拼装起点；导入后以竖屏最远缩放仍不露空白为准调整。两桥锚在石路两端，阎罗殿为远端地标。目标摊位的两套 PNG 按同一底部中心锚点重合，`HitArea` 只附着目标 Prefab，`StaffAnchor` 位于柜台前侧。其它破败摊位无交互组件。角色脚点与地标底边共享世界坐标，按脚点等距深度排序；屋檐和桥栏杆另设前景遮挡节点，集成时复核穿行。

`DemoSession` 是本轮修复状态的唯一写入者，`RUINED→RESTORED` 只成功一次。`GestureRouter` 管理触摸状态并把已确认的轻点交给 `StallHitTest`，后者只发打开 UI 的意图。`DemoUI` 发送修复命令，`StallPresenter` 订阅状态、切换两套摊位视觉并确保 `StaffAnchor` 只有一个店长实例。`CustomerFlow` 只读取固定世界坐标路径与本地演示参数，不依赖相机、UI 或摊位状态。关闭面板不修改 `DemoSession`；重新进入场景重新创建状态。

路径点在编辑器沿可见石路标定为 `Entry → MarketTurnA → TargetFront → MarketTurnB → Exit → BeyondExit`。`Entry` 位于左上桥道路连接点，`Exit` 位于右下桥，`BeyondExit` 在桥后可见地图边界外；顾客到最后一点才回收。具体世界坐标、地图可显示包围矩形、初始镜头、最远/最近倍率、摊位命中多边形和 `StaffAnchor` 偏移按第 8 节开工前校准门槛锁进本 Brief 的校准附录，再由 Tech Lead 复核；不能仅延至实现报告。生成间隔、移动速度和活跃上限为本地 Demo 调试参数，不成为正式顾客配置。

## 4. 相机、输入与 UI

正交相机只拍摄世界；`ScreenCanvas` 固定屏幕坐标。每次拖拽或双指缩放后，用地图可显示矩形、当前视口半宽和半高钳制相机中心；最远倍率必须让整个视口仍被地图覆盖，最近倍率保证目标可辨认且附近通道可见。使用手势起点、触点 ID 和位移阈值区分轻点与拖拽；第二指加入立即取消轻点候选，双指中点尽量保持指向的地图位置。缩放后重新建立单指基准，避免镜头跳动。点击命中由当前相机将屏幕坐标转成世界坐标后再测 `HitArea`。

阈值、倍率和阻尼是设备标定参数：首轮以 8 逻辑像素轻点容差和 2 指距离变化识别缩放作调试起点，按第 8 节在业务代码前锁定实际数值；真机手势录屏再复核适配结果。UI 控件优先消耗触摸，打开卡时地图不接收卡内手势；卡外轻点可关闭但拖动不关闭。修复按钮按下后立刻禁用，`repair()` 成功才退出卡并显示约 2 秒结果条；重复点击只重计已完成提示，不再生成店长。

UI 以 390×844 逻辑像素为设计基准，底卡宽 `min(屏宽−32, 430)`，按钮命中框至少 44×44；顶部控件距安全区下缘至少 12 px，底卡距底部安全区上缘至少 16 px。目标提示圈挂世界锚点并随视口裁剪。短屏打开底卡若遮目标，在合法相机范围内微调镜头使目标和店长锚点保持可见，关闭后恢复。UI 图稿只作布局与色彩参考；资产包未包含 UI 九宫格或按钮切图，首轮可用 Creator 内置图形和文字按已批准配色搭建，正式美术件若另行交付再替换，不新增功能。

## 5. 协议、平台与运行验证

本 Demo 不调用网络、协议、账号、平台 SDK 或持久化 API。Web 是主要开发入口：Creator 3.8.8 打开 `apps/client/`，运行编辑器预览，随后通过编辑器构建 Web Mobile，用本地服务器在手机浏览器打开构建 URL；记录 Creator 版本、构建配置、浏览器和设备。微信／抖音小游戏是项目架构目标平台，但本任务的产品验收没有要求平台 SDK 功能；后续若需渠道构建，仅通过 Creator 对应构建目标，真机路径和兼容问题单独记录，不让 `wx.*`/`tt.*` 进入 Demo 核心脚本。

当前只读环境检查：注册表显示本机安装 `Cocos Dashboard 2.2.2.1515`（`D:\CocosDashboard\`）；常见 Creator 3.8.8 安装目录、命令入口和桌面／开始菜单快捷方式未发现；`client/` 只有版本文件和说明。Dashboard 安装不证明 Creator 3.8.8 编辑器可用。工程准备前需在 Dashboard 中核实或安装 3.8.8、确认可新建/打开工程并成功 Web 预览；未通过前不能声称 Demo 可运行。移动端需至少一台可用于竖屏触控与性能采样的目标手机、可访问本地 Web 构建的网络环境。

## 6. 性能、日志与可复现调试

每帧只更新活动顾客和手势中的相机；静态地标与装饰不挂 `update()`。顾客采用少量 Prefab 对象池，复用时重置位置、路径索引、朝向、透明度、动画和调度。动画采用资产包两帧 `walk_01/_02`，按美术说明先用 4–6 FPS；静态店长不持续计算。持续顾客生成用一个调度器，移动计算复用向量/缓存路径段，避免每帧临时分配。地表与角色分组图集；带透明的大地标、前景遮挡与 UI 底卡需观察 DrawCall 和 Overdraw。水波、灯光、树叶动态不在当前已批准资源包内，不作为此 Demo 验收项。

Web 先记录功能录屏与控制台，再在目标手机记录初始/修复后、相机两端倍率、持续客流和拖动场景的 FPS、帧时间、DrawCall、纹理内存、活动顾客数与加载耗时。代表手机先按可重复访问、至少 60 Hz、支持竖屏触控 Web 构建的规则选择；正式手机性能测试前落盘厂商、型号、芯片、RAM、系统、浏览器、分辨率和刷新率。已提议的 `project/quality/PERFORMANCE_BUDGET.md` v0.1 尚待用户批准；获批后按其三轮、每轮稳定运行 60 秒及冷/热加载口径采样，在批准前不把候选数字当验收门槛。主流中高端手机 60 FPS 是验证目标，实际对象上限与图集尺寸由测量决定。若性能不足，依次减少装饰动画、降低同屏顾客上限、压缩远景贴图或降低远处角色动画频率，但保留完整地图、修复、店长和至少一名完整顾客路径。

稳定日志标签：`[DEMO/SCENE]` 场景与资源导入失败，`[DEMO/INPUT]` 手势状态异常，`[DEMO/STALL]` 修复状态／店长重复阻断，`[DEMO/FLOW]` 路径点缺失或池化复用异常。日志正文用中文，含固定错误码与关键节点名，不在每帧输出。独立调试入口放在仅开发构建可见的 `DemoDebug` 面板或编辑器场景参数中：重置场景、显示路径锚点与相机边界、调节本地客流参数、显示活动角色数与 FPS；正式演示 UI 不出现调试按钮。
