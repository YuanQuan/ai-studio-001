# 七项菜单单元样例｜页面状态与触控优先级 v0.1

任务：`UNIT-MENU-UI-SPEC-001`。以已批准 Product `FLOW.md` 和 `ACCEPTANCE.md` 为状态语义来源；以下仅定义可见界面反应，动画完成事件与镜头实现由 Tech/Client 决定。

## 1. 导航和菜单

| 当前状态 | 触发 | 画面反应 | 返回/异常 |
|---|---|---|---|
| 七项菜单默认 | 点击某卡 | 按压态后进入对应单元，显示当前编号/标题 | 快速双击只进入一次；不可进入时禁用并说明 |
| ③角色入口 | 点击③ | 展示 3A 孟桃、3B 幽灵两个子项 | 返回顶层仍是七项，不插入第八卡 |
| 单元默认 | 返回 | 清理当前 Lab 控件/浮层；回顶层菜单 | 对话打开时先关闭浮层，再按返回规则处理 |
| 任意单元 | 重置 | 显示“复位中”；收到完成后回当前项初始状态 | 失败显示原因及重试，不能假显示成功 |
| 组合 | 返回再进 | 同第1项空底板与初始镜头，全部可切换对象关 | 不沿用上次开关、动作、光影或对话进度 |

## 2. 操作状态

| 状态 | 文案/组件 | 行为 |
|---|---|---|
| `normal` | 主操作“开始演示/预览效果” | 资源就绪时可点 |
| `pressed` | 按钮微下沉并增深暖色 | 仅手指按压期间；移出取消时恢复 |
| `selected` | 橙色细框 + 选中标记 + 当前文字 | 适用于左/右、五动作和对象开关 |
| `disabled` | 灰纸 + “不可用”提示 | 缺板凳的坐姿、缺正式资源的预览等；不能偷偷执行 |
| `loading` | “准备中/复位中”及节制动效 | 等待资源/状态确认，避免多次提交 |
| `busy` | “演示中”，当前动作选择可见 | 重复点击不会排队产生多个动作 |
| `error` | “资源未就绪/查看原因/重试” | 不出现空白贴图、错误身份卡或假完成 |

第2项预览忙碌与第3A项孟桃工作忙碌各由真实对象状态驱动；UI 不从按钮点击推断动画已经结束。第3B项左右切换与五动作切换同时可观察最后有效选择；坐姿中移除板凳，方向/状态显示应与已安全退出的顾客一致。第4项对象隐藏时开关状态与附属特效一起归零。第7项各开关互不改写，若店铺或孟桃移除，则完整双对象身份卡隐藏或调整为仅真实存在者，不能残留双人关系说明。

## 3. 对话状态

| 状态 | 可见内容 | 下一操作/冲突 |
|---|---|---|
| `closed` | 场景可操作；无对话浮层 | 点击“查看孟桃对话”打开 |
| `firstLine` | 孟桃名/头像槽、示例标记、第1句、“继续”“关闭” | 对话层吞下拖拽/缩放；继续到第2句 |
| `secondLine` | 玩家侧标识、第2句、示例标记、“结束/关闭” | 结束关闭，不进入分支或奖励 |
| `closing` | 浮层撤出、场景输入恢复 | 动画未结束时防二次关闭 |
| `error` | 对话资源错误与关闭入口 | 不显示空姓名/空正文，重置可回 closed |

第6项专用“演示文案 · 非正式剧情”标识须跟随两句文字；截图与运行均可辨。对话壳未来复用不自动复用本示例触发和正文。

## 4. 手势命中顺序

1. 对话浮层或系统安全区控件处于活动状态时，先消费触控，场景不接收镜头手势。
2. 命中菜单卡、顶栏、身份卡周边可交互控件、底部托盘/开关/滑动列表时，由 UI 层消费；身份卡本身仅展示，不拖场景。
3. 命中清晰空出的场景区时，1/7 项才接收水平拖拽及缩放；其他项是否允许镜头操作以各自获批技术方案为准。
4. 多指跨越场景与控件边界时不得同时缩放并误触状态控件；具体事件捕获和释放由 Client 落实，QA 用目标设备录屏核验。

一次性手势指引只在 Lab 首次进入相关项显示，关闭后不遮挡店铺/幽灵；完整可访问提示仍可从 Lab 帮助打开。目标设备必须核对刘海/圆角/系统手势区、中文长度、按钮命中、镜头焦点和对话对比度。
