# 七项菜单单元样例｜UI 规格 v0.1

任务：`UNIT-MENU-UI-SPEC-001`。状态：专业评审候选，待 Art 视觉 Review、Master 评审和用户审批。本版以已 `USER_APPROVED` 的 `UNIT-MENU-PRODUCT-001 v0.1` 为产品语义输入，遵循 `project/ART_GUIDE.md` 的非像素可爱中式夜市方向。此前 `UNIT-PILOT-UI-SPEC-001 v0.1` 仍在 `USER_REVIEW`，只作复用候选和差异核对，不当成已批准 UI 输入。

## 1. 信息架构

七个顶层入口固定为：①空场景与镜头、②店铺效果、③角色效果、④场景其他元素、⑤UI 界面、⑥孟桃对话、⑦组合场景。③进入后再选 `3A 孟桃店长` 或 `3B 幽灵顾客`；这两个子项不占第八个顶层位置。菜单标题、编号、用途短句与可进入状态必须同时可读。初版只允许选奶茶店、孟桃和一名幽灵；“未来可切换”采用相同组件承载未来选项，不绘制或暗示其他店铺/店长现已可用。

| 页面/层 | 用途 | 共用或 Lab 专有 | 源组件 |
|---|---|---|---|
| 七项菜单 | 进入独立单元与第③项子入口 | 仅 Lab | `LAB_MENU_ITEM`、`LAB_NAV_BAR` |
| 单元顶部 | 返回、当前项名称、重置 | 仅 Lab | `LAB_NAV_BAR`、`LAB_ACTION_BUTTON` |
| 单元底部/侧边 | 状态选择、开关、镜头复位、可折叠诊断 | 仅 Lab | `LAB_CONTROL_TRAY`、`LAB_TOGGLE`、`LAB_SEGMENT` |
| 场景可触控区 | 镜头水平拖拽与缩放，供 1/7 项使用 | 由 Lab 暴露，世界行为由 Client 管理 | 无持久覆盖控件；一次性提示仅 Lab |
| 奶茶店身份 | “奶茶店”“店长 孟桃”，只在内容真实时显示 | Lab、组合与未来主体共用 | `MT_IDENTITY_CARD` 唯一母版 |
| 孟桃对话 | 孟桃与玩家一轮演示对话，打开/继续/关闭 | 对话容器可复用；示例文案与触发仅 Lab | `MT_DIALOGUE_SHELL` + 演示文案数据 |
| 文案状态 | “演示 · 待机/工作中/复位中”等测试说明 | 仅 Lab | `LAB_STATUS_BADGE`，不写入共用身份卡 |

菜单之外所有按钮、诊断、镜头指引都是演示控件，不进入主体游戏正式玩家 UI。身份卡只有固定的店铺/店长身份，不能因为 Lab 工作演示而添加“营业中”“已出杯”“收益”等含义。组合项中一方对象缺席时不显示“奶茶店／店长孟桃”的完整双对象卡；具体显示策略由 UI/Client 依据实体存在状态实现并由 QA 验证。

## 2. 720×1280 竖屏布局候选

当前 Creator 工程设计画布为 720×1280。所选第一街是横向长景；本任务不决定主体最终横竖屏方向，先以现有竖屏设计画布做可读性和触控冲突验证。三个 SVG 使用 720×1280 逻辑尺寸的页面组（`menu-and-lab.svg` 中两页并列）。图中背景与人物形块是自绘**布局示意**，不是可导入的生产 Sprite，也不裁切已批准概念图。

| 区域 | 候选范围，含义 | 触控行为 |
|---|---|---|
| 系统安全区 | 顶部及底部 inset 由设备提供；图样默认留 32 逻辑单位 | 不放关键按钮/文字 |
| 菜单页标题区 | y≈56–184；“百鬼夜市 · 单元样例”与范围说明 | 不响应镜头手势 |
| 菜单卡区 | x≈28–692；两列或一列自适应，七卡全屏可滚动，卡最小触控目标 48×48 | 点卡进入，滚动不误进 |
| Lab 顶部导航 | 安全区下约 y≈42–132；返回、当前项、重置 | 事件由 UI 消费，不能透传世界拖拽 |
| 场景手势区 | 顶部导航下至操作托盘上；具体镜头见 Tech/Client | 单指水平拖场景、双指缩放的建议交互；鼠标拖/滚轮作为调试映射须 Client 确认 |
| Lab 底部托盘 | 操作控件高约 176–240，避开底部安全区；控件可折叠 | 控件按下、滑动和多指动作不透传镜头 |
| 对话覆盖层 | 场景上层；文字与按钮在底部安全区上方，顶部留出可见角色 | 打开时锁定场景拖拽/缩放与底层控件，关闭后恢复 |

上述尺寸只是设计起点，需在实际设备安全区、缩放模式、字体字宽和横向街景裁切下复核。不能为容纳菜单拉伸店铺或改变美术视角。菜单内容超出可视区时纵向滚动；卡片文字允许最多两行短句并留足行高，不缩到无法读。横屏如果后续获批，保持同一信息序与组件源，另做适配样张和用户审批。

## 3. 各单元控件与操作反馈

| 入口 | 可见控件 | 禁用/异常 | UI 不决定的内容 |
|---|---|---|---|
| 1 空场景 | 返回、镜头复位、一次性“左右拖动／双指缩放”提示 | 手势进行中禁误触复位；边界由场景提示而非假动画 | 镜头倍率、实际边界 |
| 2 奶茶店 | 一次动效/光影预览、重置、店铺选择（仅奶茶店可用） | 播放中预览键 `busy`，缺正式资源时不可假称可播放 | 动画时序、光影计算 |
| 3A 孟桃 | 启动工作演示、重置，共用身份卡 | 工作中 `busy`、复位中 `loading`、失败 `error` | 骨骼事件与重入规则 |
| 3B 幽灵 | 左/右方向段控件；移动/跑动/高兴/沮丧/坐姿五状态；重置 | 坐姿无板凳时禁用或给出明确回退；动作切换期间显示当前有效选择 | 翻转、挂点、座点、位移 |
| 4 元素 | 树、花草、灯笼各自开关和效果预览 | 单个资源未就绪只禁该项；隐藏后状态文字更新 | 动效/VFX 时序 |
| 5 UI | 共享身份卡与 Lab 控件状态浏览 | 展示 normal/pressed/disabled/selected/loading/error 样态 | 主体游戏未定义的 HUD |
| 6 对话 | 打开、继续、关闭、重置；显著“演示文案”标记 | 关闭或返回清空进度；文本未就绪不出现空白假剧情 | 正史文案、任务、分支 |
| 7 组合 | 店/孟桃/幽灵/板凳/树/花/灯开关，镜头复位，场景重置；可调测试位置 | 依赖项移除时 UI 即时失效/回退；折叠面板让遮挡可观察 | 自由摆店玩法、自动经营 |

返回、重进、重置与 `busy/disabled/loading/error` 的详细状态见 `SCREEN_STATES.md`。所有按钮最小触控目标候选 48×48 逻辑单位，相邻目标净间距候选不小于 8；需真机验证。世界手势仅在场景区响应；点击身份卡或开关不移动镜头。对话开启时其浮层抢占所有命中事件，不能让场景拖拽在背后继续。顾客骨骼整体左右翻转时，方向标签、文字、身份卡、气泡和按钮置于独立 UI 层，保持正向，不跟随骨骼节点镜像。

## 4. 对话界面范围

对话壳提供：孟桃身份名、头像槽位、玩家侧标识、正文区、继续/关闭及 Lab 复位。只有一轮示例，两句文字沿用获批 Product：

1. `【演示文案，非正式剧情】孟桃：你好，欢迎来看看奶茶店。`
2. `【演示文案，非玩家设定】玩家：好的，我先四处看看。`

运行样例和审阅样张均显示“演示文案 · 非正式剧情”标识。第 1 句阅读后按继续展示第 2 句；之后关闭，不生成对话分支、选择奖励、好感度、任务或存档。表情若需要沿用获批孟桃源资源，不能从旧 Demo 截图裁切头像；生产前须 Art 确认可用头像或同源角色截图规则。浮层对比背景可读，关闭后场景保持打开前状态并恢复镜头输入。

## 5. 复用资源与许可

| 资源/组件 | 唯一源与复用范围 | 差异理由/门禁 |
|---|---|---|
| `MT_IDENTITY_CARD` | 一份边框/纸底、杯吸管小图标、中文文案键；2/3A/5/7 与主体接入共用 | Lab 附加的演示状态标签独立，不改公共卡 |
| `MT_DIALOGUE_SHELL` | 同一对话底板、姓名框、正文排版、关闭/继续控件；本版只放孟桃示例 | 正式游戏未来若使用须另批内容与触发，不复制演示文案 |
| `LAB_ACTION_BUTTON`、`LAB_TOGGLE`、`LAB_SEGMENT` | 七项菜单和单元控制共用外形与状态图；具体文字/图标可替换 | 仅 Lab；不得被误装入主体 UI |
| `LAB_NAV_BAR`、状态徽标 | 七单元共用返回/重置/当前标题与测试状态 | 所有状态用“演示”区分，主体无该诊断层 |
| 牌匾字与角色“孟” | 属 Art 场景/角色资产，UI 不从场景图裁切 | 即使文字相同，也分别核验字体与使用许可 |

图片生产前记录参考来源、授权范围与相似性，禁止直接描摹参考或复用旧 Demo 的截图/程序形体。SVG 内的卡纸、木框、杯图形为 UI 方案示意，进入 Creator 仍须 Art/Tech 出图前签认，不能当生产资产。

**系统字体候选**：Noto Sans CJK SC，官方来源 `https://github.com/notofonts/noto-cjk`，其 `Sans/LICENSE` 载有 SIL Open Font License 1.1，核对日期 2026-10-02；本版 SVG 仅指定字体族并回退本机 sans-serif，未打包字体文件。后续生产须锁定具体字体文件/版本、保存 OFL 与版权声明，核对游戏运行、嵌入、分发及改造许可，交 Art/Client 复核后才可集成。**美术字体**：当前无获批文件或许可，不用生成图中的中文字形冒充字体；如选用现有字库作改造，仍须核验修改及分发许可，改造本身不取得授权。许可未知者不得进正式资源。

## 6. 交接与验收

Art 对冷夜蓝/暖灯橙/木棕浅纸、圆润非像素边框、杯吸管小标识和文案可读性签视觉 Review；UI 不改主体美术方向。Tech/Client 决定 Cocos Canvas、手势优先级与安全区实现，验证 Lab 与主体引用同源公共组件；镜头数值属于 Tech。QA 按获批 Product `ACCEPTANCE.md` 验证七入口、3A/3B、双向状态控件、对话示例标记、复位和手势互斥，实机取证。若现有竖屏画布无法同时保证街景及文字可读，回到跨角色适配评审，不能由 UI 单方切换屏幕方向。
