# 七项菜单单元样例｜UI 规格 v0.2

任务：`UNIT-MENU-UI-SPEC-001`。产品输入：已获 `USER_APPROVED` 的 `UNIT-MENU-PRODUCT-001 v0.2`。本版沿用获批 v0.1 的七项菜单、交互结构与孟桃演示对话，修订顾客显示方式及正式资源门槛。本文是制作规格，**不代表正式图像、字体或 Creator 组件已经完成**。

## 1. 七项信息架构

| 编号 | 顶层入口 | UI 能做的操作 | 边界 |
|---|---|---|---|
| 1 | 空场景与镜头 | 返回、镜头复位、手势提示 | 场景区响应左右拖动与缩放；无店铺、角色、独立物件 |
| 2 | 店铺效果 | 奶茶店单项选择、动效／光影预览、重置 | 不出现未制作店铺 |
| 3 | 角色效果 | `3A 孟桃`与`3B 幽灵顾客`两个子项 | 子项不计入七个顶层入口 |
| 4 | 场景其他元素 | 树、花草、灯笼分别开关和预览 | 缺正式资源时仅禁对应操作 |
| 5 | UI 界面 | 展示共用身份卡及 Lab 控件状态 | 无经营 HUD、售价、收益或订单 |
| 6 | 孟桃对话 | 打开、继续、关闭、重置 | 一轮显式标记的演示文案，无分支 |
| 7 | 组合场景 | 店、孟桃、幽灵、板凳、树、花、灯分别开关；镜头与场景复位 | 与独立单元引用同一正式资源、组件与状态 |

七项共用 `LAB_NAV_BAR` 和必要操作托盘，只在 Lab 出现。`MT_IDENTITY_CARD` 是奶茶店／孟桃的公共信息组件；`MT_DIALOGUE_SHELL` 是可复用容器，演示文案与 Lab 触发不属于未来主体的正式剧情。其他店铺、店长、顾客仅保留可替换入口概念，不在此版制作或列为可用项。

## 2. 页面布局和触控

当前 Creator 设计画布按 **720×1280** 做布局候选，未锁定主体游戏方向。标题与控件避开设备安全区；顶栏约 `y=42–132`，底部操作托盘约高 `176–240`，剩余清晰区域供场景观察和镜头操作。菜单可纵向滚动，七卡的标题、编号与短句始终可读。关键触控目标起点为 `≥48×48` 逻辑单位，相邻目标净距起点 `≥8`，均须按真机字体字宽、手指命中和安全区复验，不作为最终固定技术数值。

输入优先级为对话浮层 → 菜单／顶栏／托盘与可交互卡片 → 场景空白区。对话打开时锁定底层镜头拖拽和缩放；关闭后恢复。UI 滑动、按钮与多指跨界不能同时驱动镜头。1、7 项的场景空白区才承接已批准的左右拖拽／缩放语义，具体手势实现、镜头边界和缩放倍率由 Tech／Client 正式规格确定。空背景和组合场景引用同一底板；UI 不另画背景作为可运行场景。

## 3. 角色与场景显示边界

`3A` 展示孟桃的常态／工作演示状态和共用身份卡；孟桃动画仍归骨骼资产。`3B` 的幽灵顾客改为**一个方向的原创序列帧显示节点**，另一个方向只对该节点做水平翻转。UI 的左／右段选和移动、跑动、高兴、沮丧、坐姿五态选择，仅发送审阅意图并显示已生效状态；逐帧画面、位移、板凳接触和循环由 Art／Tech／Client 验证。UI 不再要求或描述顾客骨骼。

方向文字、状态标签、按钮、身份卡、对话框、气泡、牌匾与孟桃腰牌属于独立节点或场景资产，**不随顾客序列帧显示节点翻转**。场景世界光影、地影、坐点与板凳也不附在翻转根节点上。左右×五状态在 Lab 中可分别选择并显示，不能用技术上能镜像代替视觉检查。

## 4. 孟桃对话

对话容器显示孟桃姓名／头像槽、玩家侧标识、正文、继续、关闭及醒目的“演示文案 · 非正式剧情”。内容只使用产品已批的两句示例：

1. `【演示文案，非正式剧情】孟桃：你好，欢迎来看看奶茶店。`
2. `【演示文案，非玩家设定】玩家：好的，我先四处看看。`

状态依次为关闭 → 第一句 → 第二句 → 关闭。重置或返回清除进度；关闭后恢复打开前的场景状态和镜头输入。头像槽是布局要求，不能直接裁旧 Demo／概念图充作正式头像；正式同源头像由 Art 资产审批确定。

## 5. 正式资源、复用与交付证据

所有将进入运行单元的公共 UI 底板、杯吸管图标、身份卡、对话容器及状态图须拥有同一可编辑母版、稳定资源 ID／版本和正式导出；独立样例、组合入口与未来主体接入共用。Lab 导航与诊断控件仅由七菜单 Lab 复用，不进入主体玩家 UI。可切换场景对象是否出现决定身份卡的真实展示：缺奶茶店或孟桃时不能仍显示两者同时在场的完整卡。

v0.1 三张 SVG 仅证明结构与状态的审阅构想，见 `VISUAL_REFERENCE_INDEX.md`，不得裁图或改名冒充生产资源。每次正式 UI 图片输出前，Art 与 Tech 联合核对原创性／许可、显示尺寸、九宫格或分层方案、透明边、图集面积、合批、目标设备内存；Client 核对稳定引用及同源使用。字体必须锁具体文件、来源与运行、嵌入、分发、修改许可；修改字形本身不等于取得授权，未核验的字体不嵌入正式包。详见 `RESOURCE_REUSE_AND_RIGHTS.md`。

正式验收需要 Creator 中可编辑组件与资源引用、独立和组合双入口一致性截图／录屏、目标设备安全区和中文字形可读性证据；未来主体实际接入后再复验第三入口，当前不宣称已测。若 720×1280 画布不能同时保证街景、牌匾、腰牌和对话小字可读，交 Art／Tech／Client 做适配评审；UI 不自行改变主体屏幕方向或美术视角。
