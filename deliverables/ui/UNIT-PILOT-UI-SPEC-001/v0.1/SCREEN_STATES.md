# 孟桃单元 UI 状态和交互 v0.1

以下是 UI 可观察状态，不设定角色动画 clip 时长或经营规则。`DemoStartRequested` / `DemoResetRequested` / `DemoStateChanged` 是待 Tech Design 评审的候选接口名。

| UI 状态 | 身份卡 | Lab 标签/主按钮 | 进入条件 | 退出条件 |
|---|---|---|---|---|
| `PREPARING` | 奶茶店／店长 孟桃 | 演示 · 资源检查中／主按钮禁用 | Lab 首次装载或资源重新检查 | 资源就绪进入待机，失败进入错误 |
| `IDLE` | 奶茶店／店长 孟桃 | 演示 · 待机／启动工作表现可点 | Lab 加载完成或恢复完成 | 收到一次有效启动意图 |
| `STARTING` | 不变 | 演示 · 准备中／主按钮禁用 | 启动请求已发出，等待共享适配器确认 | 适配器报告工作动作开始或错误 |
| `WORKING` | 不变 | 演示 · 工作中／主按钮禁用 | 适配器报告工作表现开始 | 报告工作动作结束、复位或错误 |
| `RETURNING` | 不变 | 演示 · 返回待机／主按钮禁用 | 报告工作动作结束 | 适配器报告常态恢复完成 |
| `RESETTING` | 不变 | 演示 · 复位中／主按钮禁用 | Lab 发出重置请求 | 适配器报告初始态恢复或错误 |
| `ERROR` | 不变 | 演示 · 资源未就绪／启动禁用，或具体失败和重试 | 资源缺失、动作失败、复位失败 | 资源就绪、再次有效操作或重新进入 Lab |

Lab 的状态标签不渗入主体 UI。主体只有静态身份卡；真实经营状态以后另立产品/视觉版本。错误文案必须描述 Lab 诊断，不出现「经营失败」「订单失败」。

## 操作时间线与重复触发

1. Lab 开始时先展示 `PREPARING` 的资源检查反馈，资源就绪才进入 `IDLE`；资源不存在进入 `ERROR` 并提供明确诊断。
2. 待机点「启动工作表现」发送一次候选 `DemoStartRequested`。点击当帧按钮进入不可再次触发的提交态；实际 `WORKING` 以适配器确认而非按钮动画为准。
3. 工作期间第二次点同一目标不再发送事件；无堆叠动作/反馈。动作结束后经过 `RETURNING`，常态恢复完成回 `IDLE`，可再次触发。
4. 点「重置」发送一次候选 `DemoResetRequested`，进入 `RESETTING`；UI 只显示处理中。重置成功回 `IDLE`；失败显示诊断和重试选择。实际中断/恢复顺序由 Tech/Client 确定。
5. 若状态回调迟到或资源卸载，UI 以当前共享适配器的有效状态为准，不凭本地计时器伪造完成；具体事件版本和过期回调过滤由 Tech Design 定义。

## 验证场景

- 在主体入口只见一张身份卡；Lab 见同版身份卡与独立控制；切换入口文案、图标、框线资源一致。
- 观察工作→返回→待机，全程「演示」前缀存在，主按钮禁用/恢复与实际状态一致。
- 快速连续点击启动只产生一次有效意图；工作中重置后状态可回收，无残留「工作中」标签。
- 缺少角色或店铺资源、动画异常时不显示假成功；错误位清晰、可读、不会覆盖对象。
- 以当前 Creator 720×1280 竖屏设计画布为主样张，检查安全区、缩放与实际字库字体度量：身份文字完整、点击目标不重叠、店铺牌匾与孟桃脸可见；其他窄屏实际机型另测。横屏仅为候选加测，不能据此改变主体相机。
