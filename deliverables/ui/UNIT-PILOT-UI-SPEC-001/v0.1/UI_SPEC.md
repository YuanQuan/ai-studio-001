# 孟桃奶茶店单元｜共用身份 UI 规格 v0.1

任务：`UNIT-PILOT-UI-SPEC-001`。状态：专业评审候选。依据：已 `USER_APPROVED` 的 `UNIT-PILOT-PRODUCT-001 v0.1`、`UNIT-PILOT-ART-CONCEPT-001 v0.5`，以及 `project/ART_GUIDE.md` 的已选非像素夜市场景。效果图是可编辑 SVG 示意，不是可直接进入 Creator 的生产贴图。

## 1. 信息边界与界面结构

主体游戏与单元演示共用同一身份卡定义 `MT_IDENTITY_CARD`：仅显示店铺类别「奶茶店」和在岗店长「孟桃」，可选显示两者关系「店长」。文字不表示已开店、营业、收入、等级或顾客服务。店铺牌匾仍是场景资产 `MT_S_PLAQUE`，身份卡是界面资源；两者文字相同但各自遵守 Art 的牌匾与 UI 审核，不从概念图裁切文字制作 UI。

主体入口挂载这张身份卡，不显示演示状态、按钮或诊断。独立单元 Lab 入口复用同一身份卡组件与图形资源，在其右侧另挂 `MT_LAB_CONTROL_PANEL`。Lab 的状态标签始终带「演示」前缀，例如「演示 · 待机」「演示 · 工作中」「演示 · 返回待机」，不把动作演示说成营业或实际出品。Lab 专用控件不进入主体入口的 prefab/场景节点树。

| 层级 | 元素 | 用途 | 来源／复用范围 |
|---|---|---|---|
| 场景层 | 店铺、孟桃、场景反馈 | 展示对象与骨骼动作 | Art/Client 另行批准的独立对象；示意图只画概括形 |
| 公共 UI 层 | `MT_IDENTITY_CARD` | 展示「奶茶店」「店长 孟桃」 | 单元 Lab 与主体游戏引用同一 UI 组件、图形母版与文案键 |
| Lab 状态层 | `MT_DEMO_STATUS` | 以「演示」明确动作状态 | 仅 Lab；可嵌在身份卡旁，但不改变公共卡的语义 |
| Lab 操作层 | `MT_LAB_CONTROL_PANEL` | 启动工作表现、重置 | 仅 Lab；与主体 UI 分开的节点/资源入口 |
| Lab 诊断层 | `MT_LAB_DIAGNOSTICS` | 显示事件、状态和资源就绪反馈 | 仅 Lab；不对玩家显示性能或资源字段 |

图稿：`screens/identity-portrait-adaptation.svg` 以当前 Creator 720×1280 设计分辨率为样张，同屏对照主体入口与 Lab；`screens/identity-work-state.svg` 是横向展示板，便于近距离检查共用卡和状态层，不代表项目已选横屏；`components/identity-card-states.svg` 汇总公共卡、演示状态和按钮状态。对应的 `-preview.png` 为 Master 使用本地工具从 SVG 渲染的审阅预览，SVG 是可编辑源，PNG 不是 Creator 生产资源。场景在示意图中引用 v0.5 关系概念，仅作视觉与遮挡参照，不裁切为生产 Sprite。

## 2. 布局与尺寸候选

当前 Creator 设计分辨率为 **720×1280 竖屏**，先按此完成主样张与布局核对。项目尚未批准主体游戏的最终画布方向或相机取景；当前第一街 2172×724 横景只是视觉参考。独立 Lab 可以用专门调试取景展示完整店身，不得以 Lab 镜头替主体定相机。安全区以设备系统提供的 inset 为准。身份卡放在上方安全区的独立 HUD 带，店铺牌匾与孟桃脸进入场景可见区；不能在狭窄竖屏把卡压在牌匾上。Lab 控制面板放在场景下方的独立操作带，诊断折叠，禁止覆盖角色双手、机器与柜台。主体若已有统一信息栏，公共卡进入该栏槽位，不叠加第二张卡。位置变化不生成第二套皮肤。

| 候选指标 | 数值／规则 | 验证点 |
|---|---|---|
| 公共卡 | 在 720×1280 设计画布中候选宽 264、高 88，内部横向留白 16；允许内容增宽不截字 | 竖屏 720×1280 主样张、不同实际像素密度核对 |
| 公共卡安全间距 | 离屏边至少 16 逻辑单位，加设备安全区 inset | 刘海、圆角、手势区不压字 |
| 主身份字号 | 店铺 22、店长 16 逻辑单位候选 | 中文在实际设备清晰且不溢出 |
| 状态标签 | 最小高 30，和身份文字保留 8 间距 | 「演示」可辨，不与姓名合成一词 |
| Lab 按钮 | 点击目标至少 44×44 逻辑单位、两目标净间距至少 8 | 单手点击与误触验证 |
| Lab 面板 | 竖屏位于场景下方，两按钮横排；安全区不足则纵排，诊断折叠 | 不侵占店铺/孟桃焦点 |

竖屏场景取景候选：上方 HUD 带只容身份卡，中段完整展示店铺经营外形与角色工作位，下方仅 Lab 存在操作带。场景关系图的横宽原始比例要由游戏相机独立定取景，不通过拉伸或硬裁切改变店身比例。横屏 16:9 仅列为可选加测：若后续决定支持，卡与 Lab 操作区重排且仍不得挡牌匾/角色；本任务不作主体方向决定。

所有数值是 UI 设计候选；正式 Canvas 缩放模式、设备像素倍率、安全区 API、字体实际度量须由 Tech/Client 实测后签认。不能为了凑图稿裁掉孟桃、店铺或前柜遮挡。

## 3. 交互与状态

`MT_IDENTITY_CARD` 是信息展示，不可点击。Lab 「启动工作表现」和「重置」只发送测试意图；UI 不决定动画时长、重入策略、骨骼事件或资源预载方式。候选意图 `DemoStartRequested`、`DemoResetRequested` 仅供 Tech Design 评审，未批准前不作为 Client 正式接口。状态变化由共享演示状态适配器推送；UI 不从单个按钮点击自行推断动作已完成。完整状态和异常见 `SCREEN_STATES.md`。

启动操作：待机且资源就绪时触发一次；接收开始后按钮暂时禁用并显示「准备中」或「演示 · 工作中」。动作结束进入「演示 · 返回待机」，收到恢复完成后回到「演示 · 待机」。工作或准备过程中重复点击不会产生第二个可触发按钮动作。重置始终是 Lab 级操作，发出后显示「复位中」，收到完成后回到待机；失败则保持可见错误与重试入口。实际事件先后和中断行为由 Tech/Client 定稿。

主体游戏不显示这些测试状态，也不把 Lab 的工作动画当正式经营事件。未来主体若需要经营状态，应由经批准的产品规则、新状态资源和同一组件的新版本定义。

## 4. 资源、复用及字体

身份卡使用一份边框/纸底母版、一份杯吸管小图标母版、一份文案键（店铺/店长）和统一状态标签皮肤。Lab 按钮复用项目按钮状态结构，图形仍从当前 Art 材质语言派生；不复制旧 `UNIT-SAMPLES-001 U08` 修复卡。身份卡不裁切店铺牌匾、不复制概念画中的奶茶杯字形。具体图标、九宫格边距和 Sprite 生产包由 Art 与 Client 在正式资源阶段确认。

字体候选：`Noto Sans CJK SC`（简体中文，正式文件版本待锁），来源 [Noto CJK 官方仓库](https://github.com/notofonts/noto-cjk) 及 [Sans 目录许可](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE)，2026-10-02 核验。该目录为 SIL Open Font License 1.1；[SIL 官方许可正文](https://openfontlicense.org/open-font-license-official-text/)允许按条件使用、嵌入、随软件分发与修改，分发字库需附版权声明及 OFL 文本，修改版不得擅用保留字体名，也不能把字体单独售卖。本版 SVG 仅声明字体族，由查看设备自行回退；未嵌入或分发字体文件。进入 Creator 时应锁定实际字体文件/版本、复制随附许可、核对字形覆盖与字体资源体积，并由 Art/Client 复核。美术字暂无定稿候选；店铺概念生成的「奶茶」字不得直接作为正式字体或界面字形。修改任何现成字体都不自动解决授权。

## 5. 交接与验收

- Art：核对冷蓝环境、木棕/浅纸卡与暖橙强调、圆润非像素线条、杯吸管唯一标识、孟桃角色身份；签视觉一致性 Review。此图不授权生产图集。
- Tech Lead：评审共享状态适配器和 Lab 意图接口，确定独立入口与主体入口引用关系；本 UI 文档的事件名仅是候选。
- Client：从同一公共组件和资源索引实例化身份卡，主入口不得导入 Lab 面板；实机核对适配、字形与点击目标。
- QA：按批准版核对文案、待机/工作/返回/复位、失败与重复触发；截取主体入口和 Lab 的相同卡资源版本证明。正式用例由 QA 所有者另交。

当前交付止于 UI 规格和可编辑图稿。产品未定义的订单、价格、金币、养成、饮品品类和功能入口不在本界面中。
