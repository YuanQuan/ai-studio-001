# 百鬼夜市 Demo｜UI 规格

版本：v0.1｜任务：UI-DEMO-001｜状态：待专业评审

## 目标与页面结构

竖屏主场景只覆盖一次摊位修复验证。场景常驻一个贴近目标摊位的细虚线提示圈与“点击修复”短提示；点击目标后显示底部确认卡，包含标题、简短说明、“修复”与“关闭”；修复成功后显示短暂“修复完成，店长已到位”提示。已修复摊位再次点击只显示“已修复，店长已到位”。无资源、时间、经营菜单、缩放按钮。

交互顺序：待修复 → 轻点目标摊位 → 确认卡 → 关闭回待修复，或修复 → 营业摊位与单名店长出现 → 短结果提示 → 已完成常态。重新进入 Demo 回待修复。

## 布局与适配

- 设计基准 390 × 844 逻辑像素，适配其他竖屏长宽比；图稿是比例示意，正式像素以 Cocos 设备测量落地。
- 屏幕 UI 挂 `ScreenCanvas`，与世界相机隔离；缩放、拖拽时卡片与提示条维持屏幕坐标。目标提示圈挂世界锚点，随摊位移动、缩放并受可视范围裁剪。
- 顶部安全区下缘到任何常驻控件至少 12 px；底部确认卡下缘在系统安全区上方 16 px。卡片宽度 `min(屏宽 − 32 px, 430 px)`，左右各至少 16 px；高度以内容自适应，建议不超过可用高度的 30%。
- 初始相机应让目标摊位出现在画面中上部。确认卡从底部出现时不遮住目标摊位与其旁店长锚点；若相机拖到目标接近底部，打开卡时在卡片上方保留目标可见空间，必要时平滑微调相机中心，关卡后恢复；此微调由 Client 在实景验证，不影响地图边界。
- 提示圈不得覆盖顾客石路，指向目标摊位而不是邻近背景摊位。目标移出视口后提示随世界锚点消失，不在屏幕边缘增设新按钮。
- 所有独立按钮命中框至少 44 × 44 逻辑像素，视觉可小于命中框。文字与底色对比应在实际屏幕上复核。

## 输入优先级与状态

| 情况 | UI / 输入结果 |
|---|---|
| 单指按下目标，移动未超过 Client 标定点击容差后抬起 | 打开确认卡；不能在按下瞬间触发 |
| 单指移动超过容差 | 地图拖拽，取消点击候选；不弹卡 |
| 第二触点加入 | 双指缩放，取消点击候选；不弹卡 |
| 手势起于卡片或按钮 | UI 消耗触摸，地图不拖动、不缩放、不命中摊位 |
| 打开卡后点关闭／卡外非目标区域 | 关闭卡，摊位仍破败；卡外关闭只在抬起且未拖动时触发 |
| 点可用修复按钮 | 只发送一次 `repair()`；立即进禁用／处理中，阻止连点；成功后卡片退出，展示短结果提示 |
| 修复后再点目标 | 显示已完成短提示，不打开修复卡、不生成店长 |

修复按钮常态为暖橙色；按下态降低亮度并缩小约 2%，抬起恢复；禁用／处理中态为低饱和灰橙并屏蔽事件；已完成态只用于结果提示，不保留可点击的“修复”按钮。关闭按钮常态为深靛底米白图标，按下态加浅米白底层。结果提示停留约 2 秒，支持重复点击后重新计时；无模态遮罩，顾客仍可见。

## 组件与资源边界

`screens/repair-flow.png` 展示初始、确认、完成三态；`components/repair-controls.png` 展示按钮和提示状态。两图为可评审的结构和配色概念，不是可直接集成的游戏资产。绘图源 `mockups.py` 可重生成 PNG。Art 提供 UI 图集中的卡片底板、按钮底板、细虚线提示、图标与提示条视觉件，UI 保持锚点、文案和状态；Client 使用自身 UI 系统接入，无指定新框架。视觉资产大小、九宫格边距由 Art 与 Client 根据目标设备确认。

## 验收检查

QA 应在窄屏与较长屏、含刘海与底部手势条设备检查：按钮不入安全区；卡片不遮目标与顾客主要通道；拖拽起于目标不弹卡；双指缩放不弹卡；卡片手势不穿透；关卡后状态不变；连点只修一次；修复后目标只显示已完成提示。
