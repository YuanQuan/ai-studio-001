# U03 单店展示与六店切换｜UI 规格 v0.1

任务：`U03-SHOP-UI-SPEC-001`。输入：已获 `USER_APPROVED` 的 `U03-SHOP-SCOPE-001 v0.1`、`U03-SHOP-ART-PLAN-001 v0.1`，以及 `project/DECISIONS.md` 的 `DEC-U03-SHOP-008` 和 `project/ART_GUIDE.md` 第 6 条 U03 范围更新。本稿为界面结构与交互规格；图中店铺轮廓、控件形状、色值和文字排版均是**审阅示意**，不是获批的正式图形、牌匾、字体、切片或 Creator 资源。

## 1. 页面与信息层级

入口为单元菜单中的 `U03 六店店铺`；返回回到实际已实现且获批的菜单。每次进入将当前序号置为 `01`，只展示 `01 奶茶店` 一间。展示页从上到下为：顶部返回与“U03 店铺示例”标题；中央单店展示视窗；下方当前店身份 `01/06 奶茶店`；底部“上一店”和“下一店”两个循环控制。当前身份是诊断性 UI 文本，不充当美术牌匾。画面内牌匾属于该店的同源美术资产，实际位置由 Art 逐店决定，UI 不在店体上再叠一块公共牌。

固定顺序：`01 奶茶店 → 02 糖画摊 → 03 炭烤摊 → 04 理发店 → 05 花灯铺 → 06 投壶铺 → 01`；反向按同一环循环。页面不提供六店缩略图或并排卡片，不会同时露出邻店。示意图见 `screens/u03-shop-layout.svg`；控件状态见 `components/shop-switcher-states.svg`。

## 2. 切换规则与反馈

- 每次有效点击只提出一个目标序号。当前店图、图中牌匾及当前身份文字共同构成一个“已呈现店”状态；目标三者均可用时一起替换。任何帧不可出现旧店图配新名称、旧牌匾配新店或双店叠放。
- 已呈现店存在时，切换中的完整旧店保持可见，顶部或底部用独立状态字提示“正在切换至 02 糖画摊”；身份栏仍显示真实可见的旧店。连续按“上一店/下一店”时，从**最新待处理目标 `desiredIndex`** 继续按六店环计算，而不是每次从可见店 `presentedIndex` 重算。例如可见 `01` 连按两次“下一店”，待处理目标依次为 `02→03`；可见 `01` 按一次“下一店”再按一次“上一店”，目标 `02→01`，此时撤销待切换并继续显示完整 `01`。最新有效目标覆盖较早尚未完成的请求，只有目标完整就绪后才提交其图/牌匾/名称；在提交前身份栏始终指向 `presentedIndex`。连续快速点按不产生跳过后误标、重复叠层或无店空白；具体预载与提交机制由 Tech/Client 规格决定。
- 首次进入且 `01` 尚未可显示时，中央为纯中性加载状态，写“01 奶茶店正在加载”，无任何假店图或假牌匾；此时只显示返回，前后切换禁用，不显示“重试”。加载成功才显示 `01`；只有加载明确失败或超时进入错误态后，才出现针对失败目标的“重试”。正式资源尚无 Gate2 批准、来源/字体权利未清或未导入时，菜单入口应标“资源未就绪”并禁入；不能用示意 SVG、全景裁块或旧概念图冒充已完成 U03。
- 若某目标资源在运行中缺失/解码失败，保留已呈现的完整旧店，状态字写“02 糖画摊暂不可用，仍显示 01 奶茶店”，记录 `failedTargetIndex=02` 并把 `desiredIndex` 复位到 `presentedIndex`；“重试”仅重试该失败目标，不从可见店重新计算或误试其他店，目标成功才原子提交。错误后若改按前后切换，重新从已呈现店递推，清除旧失败提示。若首次 `01` 失败，只显示带原因与返回/重试的中性错误面板。字体/图权利未清属于接入前门禁，不作为玩家可正常浏览的第七种店。
- “上一店”“下一店”在完整资源可切换时可用；短暂按下给视觉和触觉可判别反馈，禁用时同时降低强调并显示原因。切换中允许再次提出目标以满足快切；处理中的请求不把未呈现目标写作当前。返回随时可用，返回时取消未提交请求；再进始终回到 `01`。
- 本页不额外加“重置”控件，以保持两控件与身份栏的可读空间。重新进入复位是正式操作。无手势滑动、经营动作、自由镜头、商品/等级/收益、NPC、动效和音效入口。

## 3. 竖屏布局候选与安全区

以当前工程 `720×1280` 设计画布为候选；以 `390×844` 作为小竖屏审阅候选，均须在实际可见区域与设备安全区复核，并非已测目标设备。使用安全区内的锚点布局：顶部标题/返回占约 `120` 设计单位，底部身份及控件占约 `210`，中央余量专供单店。示意 720 画布中单店视窗候选为 `x=44–676, y=170–1000`，主体和牌匾保持至少 `24` 设计单位的内部安全边；该值是评审起点，后续以实际六店测量调整。脚线一致、按店源的真实宽高比等比 `contain`，不裁顶、不拉宽小摊、不把所有店做同宽。最宽的瓦房与最高的竖牌均需在同一窗口内完整显示。

返回目标靠顶端安全区，两个底部控制靠底端安全区；真实布局基于 `visibleRect ∩ deviceSafeArea` 计算，不仅靠 1280 固定像素。控件命中区候选至少 `96×88` 设计单位，相邻净距候选至少 `16`；在 `390` 宽按固定宽缩放时约为 `52×48` 屏幕像素，仍须按实际 DPR、系统手势区及手指命中复验。标题/身份文字不得用缩到无法辨认来强塞，必要时留更多上下空间给牌匾；如果六牌中任一在 390 宽无法读，向 Art/Tech 提交尺度或构图调整，不私自裁店、放大牌匾或改美术挂位。

UI 遮挡规则：所有常驻按钮与身份栏位于展示容器外，不覆盖六种挂位——奶茶窗檐、糖画伞右杆、炭烤棚左柱、理发门额、花灯上梁偏左、投壶侧挂。加载/错误字层只在无可呈现店时占中央；已呈现店上的切换反馈放在容器外。六店最终 PSD/PNG 的实际透明边与最外缘牌匾位置由 Art 实图和 Tech 投影计算复核；本稿 SVG 不能证明最终无遮挡。

## 4. 资源与职责接口

U03 只消费同一店的图/牌匾整体身份及稳定 ID，不从用户全景裁块，也不单独将牌匾文字烘进 UI。`MT_SHOP_01` 与 U03 奶茶候选资产 ID 的唯一映射由 Tech/Art 在首图前确定；UI 当前以顺序与中文身份描述，不新建正式资产 ID。六店图片、牌匾、字形及公共底景的来源、PSD、导出、Gate2 和真实 UUID 由 Art/Tech/Client 登记，UI 不把计划路径写成已接入。

可复用候选：菜单导航语义、返回按钮、状态字和 `LAB_ACTION_BUTTON` 的普通/按下/禁用反馈沿用已批 `UNIT-MENU-UI-SPEC-001 v0.2`；“上一店/下一店”共用**一套**控件状态规范，U02 若后续实现同类单元导航也引用相同语义与资源。U03 当前店身份条独有 `01/06` 与名称组合，无需另做六个姓名图。`MT_IDENTITY_CARD` 含奶茶/孟桃身份，不合适代替六店通用身份，避免把其他五店误标为孟桃店；对话容器和七菜单尚未实现的全部组件不自动视为运行资源。Lab 控件仅属 Lab，未来主体展示店铺时按同源店资产但另审主体 UI 关系。

正式字体必须登记具体文件名、版本、来源、许可文本及运行、嵌入、分发、改造范围；目前 U03 未锁任何字体。示意 SVG 使用字体族回退渲染仅供审阅，不可作为正式字稿。美术牌匾字由 Art 按已批六种方案生产并核权，UI 文字以身份含义对应，但不从美术图中抠字。色彩候选和权利边界见 `COLOR_SYSTEM.md`；任何正式 UI 图片仍需独立通过视觉资源 Gate1/Gate2，UI 规格批准本身不授权图像入包。
