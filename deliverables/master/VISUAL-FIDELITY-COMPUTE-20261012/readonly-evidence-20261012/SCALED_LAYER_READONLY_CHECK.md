# 已有缩放分层资源的只读补充核验

本记录是原目标的补充证据，不修订已批准的通用契约或旧资源审批；没有重新导出、写入或修改任何图片，没有生图调用。灯笼的预算例外另行登记，不消费其修正额度。

6组 AD/XJ 默认微笑立绘此前仅记录缩放为0.75。现已从存档 `build_batch.py` 和 `validate_batch.py` 找到实际处理设置：RGBA LANCZOS，主体1024²裁切至768²，脸和前景256²至192²，位置取清单所记整数坐标。使用本机 Pillow 11.3.0 / numpy 1.26.4 在内存复算，6组各3件，共18件全部与当前交付文件解码后的RGBA逐像素一致；记录中的输入hash在核验前后相同。这个结果证明本次环境中的源到导出可复现。

同一部件先整体合成，再用相同RGBA LANCZOS缩放，与现有“逐层缩放、按整数位置重组”不是同一结果。下面只比较同一批当前源、同一背景和固定处理顺序，不把不同管线的差异伪称为无损：

| 组别 | 源到三件导出复现 | 可见RGB变化像素 | 最大单通道差 |
|---|---|---:|---:|
| AD_S0 | 3/3 全RGBA零差 | 10152 | 131 |
| AD_S2 | 3/3 全RGBA零差 | 8891 | 30 |
| AD_S3 | 3/3 全RGBA零差 | 10714 | 104 |
| XJ_S0 | 3/3 全RGBA零差 | 15660 | 145 |
| XJ_S2 | 3/3 全RGBA零差 | 15841 | 177 |
| XJ_S3 | 3/3 全RGBA零差 | 8160 | 139 |

这个对照发现了采样/整数定位次序的实际差异，不能单独归因于某一种操作。原尺寸源合成与PSD的RGB合并缓存自身也有1至2通道单位的差异，已在第二份JSON单列；PSD合并缓存不含alpha，不作为透明度权威。RGB整图在背景上缩放与RGBA对象缩放后叠背景的差异也不能混算。

结论：18件导出可复现，六组缩放重组仍不能按零差异目标判通过。旧图原件和既有批准不变；没有事后放宽误差，也不自动重做已批准资源。后续若需要修改这条资源生产路线，应由Art/Tech先固定目标显示尺度、保真区域、合成与采样顺序，以及半透明和支点的处理，再按既有方案/具体版本门禁制作最小代表片段。不能为了追求零差直接把整体图盖在可编辑层上。

证据：`SCALED_LAYER_READONLY_CHECK.json`记录18件像素复算与输入/工具hash；`SCALE_ORDER_DIAGNOSIS.json`区分PSD合成缓存和缩放次序对照。两轮计算各耗时 0.826 / 0.552 秒，整体人工分析历时未单独计量，不称为完整制作耗时。该核验不证明实际引擎、局部编辑语义、序列帧或骨骼动画已通过。
