## 1. 首样反馈如何进入本批

01 奶茶的实际源为 1254² RGBA，按比例置入已签 1024² 母版后 alpha 框 `(124,150,866,900)`，脚点 `(512,900)`；不依赖模型恰好输出 1024。两张候选 PNG 重组与透明样张 RGBA 差异 0；十层 PSD（九工作层加一隐藏来源层）可由 Pillow 重开，并经独立图层标志解析、PSD 实际通道重组和只改 `sign_glyph` 的局部探针验证；平面源语义分层只包含可见像素，没有隐面。黑/灰/白底检查发现右灯少量暖红半透明细点与白底偏灰地影。390 宽候选以完整 1024 画布展示 316 CSS px 时，奶/茶字高 `27.16/29.32` CSS px、9px 源笔宽约 `2.78` CSS px；若用记明 `sourceRect` 的等比 trim 则更大。以上是**静态审阅证据**，不是 Creator 或设备性能实测，Tech 后验尚未给出。

本批五店从第一张候选起改进四点：①牌底依店型做手工木纹/糖色/熏木/纸折/竹筋，不用同一平整矩形换色；②牌匾避开经营线索与窗棚/灯群，在计划挂位先预留空间，避免奶茶样张牌体压住白布中央的情况扩大到其他店；③生成源的透明外缘在黑、灰、白和深蓝四底逐一检查，暖灯/火焰/糖画亮线周围若有明显脏边则在当前候选局部修边，禁止为边缘瑕疵重生整店替换既定画面；④独立 PSD 的可见像素语义分割优先按伞、棚、瓦屋、架体的真实对象轮廓做掩码，保留原件和所有补洞说明，不以机械横切层冒称完全可移动对象。Tech 如退回奶茶样张，先依退回原因修订本批受影响参数并重新 Art/Tech 签认，不能按本旧稿直接开五店。

## 3. 工具、画布、字形与层

工具沿首样：内置 `image_gen`，对本次已登记附件以视觉参考方式**逐店独立生成透明主体**，完整保存每次实际提示词、模型原始输出、选图理由、路径/版本/SHA；出现伪字、邻店、人物、大 LOGO 或改变类别轮廓时先拒该候选。获选后只对当前店候选定向改局部，不因小瑕疵重画整体。每店生成源可有不同原生像素，但正式 PSD 画布统一 **1024×1024、8 位 RGBA**，无拉伸等比置入；左上源坐标和共同逻辑脚点 `foot=(512,900)`。店体宽/高允许自然差异，伞车不拉成瓦屋；参考候选非透明框上限 x约 `72..952`、y约 `150..900`，不是强迫各店填满上限。某源若无法在该画布以无裁顶、无扭曲、留足牌边的方式安置，先停该店并重签画布/尺度方案。

每店用全画布同坐标透明图层。建议 PSD 可见组：`ground_contact`、`body_structure`（房可进一步分 `body_roof/body_facade`；摊架按 `umbrella/canopy/rack`）、`operating_objects`、`light`、`front`、`sign_hardware`、`sign_board`、`sign_glyph`；实际无内容的层不伪造。完整模型平面源和转换预览保存在该店 `source/shop_0x/` 外部审阅文件；若无法直接形成 PSD，用只读调用的 `bggg image2psd assemble` 把当前**全画布语义层**写入该店独立 PSD。记录每个可见像素掩码与补洞，拆前店图与拆后复合逐像素或注明最多 1/255 的 alpha 舍入差；被前件遮挡的隐藏面不可从平面图自动恢复，不能宣称原生完整结构可编辑。做一处牌字层修改、重新组装、重开 PSD，核其他区域未变。正式样张和后续源图的哈希/版本不原位覆盖已存证据。

**每店 PSD 另须嵌入底层 `reference_source`**：它是已归一的该店完整原始源图，隐藏且标为非导出，不计入运行候选；外部 PNG 备份不能代替这一个 PSD 内层。`bggg image2psd assemble` 负责写入含来源层的 PSD，本任务内局部脚本再按 `visible = not bool(flags & 2)` 设置所有实际工作层 flags=0、`reference_source` flags=2。交付前由与修补器分离的 PSD 图层记录解析器核名称、顺序、眼睛状态，并直接读 PSD 的工作层 RGBA 通道重组透明图，与同尺度样张比较；不能只凭缓存的扁平 RGB 预览判断。首样错误 flags 版已隔离在 `source/psd_work/shop_01/history/`，其缺陷和修复见 `EDITABILITY_REPORT.md`、`INDEPENDENT_VISIBILITY_REPORT.json` 与 `PSD_RECOMPOSITION_REPORT.json`。各店都须保留原始输出/源 PNG、可见层与隐藏来源层的 SHA、局部编辑探针及可编辑边界说明；任一隐藏来源层误显示、工作层误隐藏或复合超出本批容差，停止该店出片并修正后重新验。

原创字形沿 `LETTERING_SOURCE_AND_LICENSE.md`，02–06 每块两字分别保留字符路径与整体 SVG，纸芯/木牌/绳结/文字分 PSD 层。全画布 **保守**候选按 UI 390 视口展示 316 CSS px：两字各自实际源 bbox 高度计划≥80 px，最细墨笔/浅刻有效宽≥8 px，即约 `24.7` CSS px 字高、`2.47` CSS px 笔宽；静态实图必须逐字实测，并核最小字与牌底颜色反差。横牌两字并排、竖牌上→下正读，不因限定宽度把字压扁。若自然店体与此牌尺度冲突，先试板体位置/内部字号和同源等比展示；涉及改变已批牌形/挂位或 UI 安全区时请 Master 组织受影响锚点 Revision，不单方调整。

## 4. 候选切片、投影与资源上界

每店预期最多两张候选运行 PNG：`body` 合并房/摊体、经营物、静态光及接地，`sign` 合并牌底/字/挂件；PSD 内仍保留这些对象独立层。以 02–06 的 `source/shop_0x/`、`psd/shop_0x_*.psd`、`preview/sample_exports_or_candidates/` 分类留档，**正式 `exports/` 在 Art/Tech/Client 切片讨论和六店生产后再按实际版本统一导出**。如果牌背后的遮挡关系不能用两图按正序复合成立、必须加 `front` 第三图或需公共地景，先停这店并对输出上限/层序重签。PNG 可在保持同源 `originalSize/sourceRect/offset/foot` 映射的情况下 trim，六店同尺度核对仍以原 1024 母版和统一脚线为真值；不从 PSD 扁平不透明预览导 Sprite。

1024² RGBA8 一张未压缩约 4 MiB，两张最多约 8 MiB/店；本批五店约 40 MiB，六店在全常驻情形约 48 MiB，只是静态展开面积估算，不含 mip、图集 padding、CPU/GPU 双份、背景、压缩回退，也非现有 Web 预算 PASS。首样实际 PSD、PNG、alpha 和 Tech 样张后验应先修正这个估算，Tech 全量预签需写预计纹理页/最大同时持有/目标 Creator 3.8.8 Web 环境及仍未测项。不能凭同图集承诺单 DrawCall。任一店的第三张运行候选、额外动画或显著更大纹理须重签。

每店提交 720×1280 与 390×844 的**静态同尺度**完整图与等比 trim 对照：六店在各视口同一逻辑脚线、同一宽度约束，不把各店都放大到自己填满容器。记录 CSS 视口、候选 safe box、实际显示缩放、DPR（有运行环境才填）、店体和牌匾投影宽高、两字 bbox/最细笔宽、alpha 四边裕量及 UI 遮挡。奶茶样张采用完整 1024→316 的 390 保守审阅；后续五店先按同法判 24/2 候选线，另给 trim 不变形对照。**不能用局部放大图代替实际单店全视窗可读证据。** 最终 Creator/目标设备的真实 safe area、texture settings、帧时和内存仍由后续 Client/Tech/QA 实测。
