# U03 六店首张拟正式样张同批制作预案 v0.1

**预签批次**：`U03-SAMPLE-A`，仅 `01 奶茶` 一店。此文件、同目录 `RIGHTS_PROVENANCE_ADDENDUM.md` 与 `LETTERING_SOURCE_AND_LICENSE.md` 共同构成不可拆开的同批输入；Art 与 Tech Lead 必须分别对这三份文件的**相同 SHA-256**签认。已批准 Product、Art Gate1、Tech、UI 均为 v0.1；用户对本次附件允许商用改编的独立声明已在审批日志登记。本预案的签认只解锁首样制作，不批准样张视觉、其余五店、切片 Gate2、Creator 接入或 QA。任一输入、工具、画布/脚点、生产路径、输出范围变化，在受影响新图前重签。

## 1. 首样对象、视觉和生成方法

先做唯一代表样张 `MT_SHOP_01`：蓝灰瓦顶、木质工作窗、浅色窗棚、瓶罐及冲泡设备、深蓝夜色与暖橙开口光。**屋顶大杯和吸管全部消失**；瓦行、正脊、檐阴、边缘夜色与透明边须连续，不以覆盖块掩盖残留。工作窗上檐下做短圆角木框浅杏纸芯横匾，准确写「奶茶」，可选小杯辅纹但屋顶不再有标识。画风、轮廓比例以已批视觉锚点与本次附件为准；图中不得有相邻店、阎罗殿、桥、人物、鬼、商品 UI、动效或经营状态。

图像工具固定为内置 `image_gen`：以已登记用户附件作为**视觉与构图参考**，要求独立单店透明背景位图；不裁用户全景、不拿旧 `v0.4` 或历史孟桃概念像素直接拼接。先求无文字、无商标、无屋顶杯/吸管的完整店体，窗口上檐为后续独立横匾留位；模型出现伪字、杯形屋顶尖峰、相邻摊位或风格偏离则退该候选并做定向编辑，不靠事后遮盖蒙混。每次调用保存实际提示词、工具模式、输入路径和哈希、原始输出路径/哈希；只选符合锚点的源图复制到本任务 `source/shop_01/`。不得以生成式中文字直接作正式牌匾。

六牌字稿采用本任务的原创逐笔路径，具体来源纪律见 `LETTERING_SOURCE_AND_LICENSE.md`。首样仅绘「奶茶」与其牌底、挂件；牌底、文字、挂件分别保存中间源并在 PSD 分层。若为去除模型生成的空牌或瑕疵需编辑当前候选图，使用同一内置图像编辑工具定向修改并保留前后文件；不以重生成整店取代已通过的单店候选局部修订。其余 02–06 仅在样张 Art/Tech Review 双通过及全量预案复签后开始。

## 2. 画布、脚点、展示阈值候选

首样工作母版候选为 **1024×1024、8 位 sRGB RGBA**，左上像素原点，固定逻辑脚点 `foot=(512,900)`，原始图片正向，不做反向翻转。主体非透明外接区域预期在 `x=72..952, y=150..900` 内；横匾和屋顶均在其内，四边保留可复核透明余量。店宽可按原瓦屋自然比例，禁止为填满画布横向拉宽；源工具的实际输出若不是可无拉伸安置在此画布，暂停并重签尺寸/排版，不偷偷裁顶、缩小笔画或改变脚点。首样 PSD 所有语义层均保留同画布坐标。

审阅使用 UI 候选 `720×1280` 设计视窗的单店容器 `x=44..676, y=170..1000`，内部 24 设计单位安全边；另用 `390×844` 小视口候选，先按实际安全区和可见宽度重新求等比 `contain`。首样目标是完整瓦顶、牌、工作窗和接地均同屏、控件不盖牌；**候选**牌匾单字在较小视口投影高度至少约 24 CSS px、最细有效墨笔至少约 2 CSS px（源字高建议≥72 px、细笔≥8 px，按 342/1024≈0.334 的候选缩放估算）。这只是预签检查线，实际 CSS 视口、DPR、safe area、`view.getVisibleSize()` 与字形对比度必须实测；测不到或读不清就标 `REVISE/NOT_TESTED`，不能报视觉 PASS。两视口使用相同逻辑脚线及同一店图源；未来主体实际镜头另测。

## 3. PSD 语义层与导出边界

首样至少保留 `reference_source`（不导出、仅溯源）、`body_roof`、`body_facade`、`interior`、`sign_board`、`sign_glyph`、`sign_hardware`、`light`、`front`、`ground_contact` 等可独立选取的可见对象边界。可将确无内容的层组标 `EMPTY_NOT_USED`，不填伪造层。先用透明全画布语义 PNG 和独立字稿/牌底源构成 manifest，再只读调用 `bggg-creator-image2psd/scripts/image2psd.py assemble` 在本任务目录生成 PSD、合成预览和全画布层图；若原始单店图是平面位图，语义切层和补洞范围逐层记录。平面图无法恢复被屋檐、前柜遮住的隐藏面，必须在编辑报告中写出不可编辑区域；`split-colors` 不冒充屋顶/店体语义分层。对 PSD 做打开/重新保存/修改一处牌匾字层/重导出验证，核其余区域未变、alpha 和整体视觉未变；不可验证即样张不通过。

首样运行导出候选最多 **2 张 PNG**：`exports/tex_mt_shop_01_body.png`（屋顶、店体、经营陈设、前件、静态暖光和接地的已确认合成）及 `exports/tex_mt_shop_01_sign.png`（完整牌底、原创文字和挂件）。两图共用 1024² 源坐标和脚点，导出时可按实际非透明框紧缩文件矩形，但须在 `CUT_MANIFEST` 留 `sourceRect/originalSize/offset/foot` 以准确重组；若 trim 引起字牌/瓦缘变形或黑边，先保留全画布 PNG。PSD 层仍独立可修。切片前 Art、Tech、Client 另讨论实际层序、遮挡和是否维持两图；首样导出仅为评审候选，不能作为 Gate2 已批资源给 Client 接入。若需要第 3 张运行纹理、单独动态灯、公共地景或额外新资产，先重签范围。

## 4. 目标环境、预算与实测

本批目标核查环境为 Cocos Creator **3.8.8 Web** 候选运行链与两竖屏视口；此阶段尚无 U03 Creator 导入和目标真机。1024² RGBA8 每张未压缩展开量约 **4 MiB**；两张候选导出每店理论上限约 **8 MiB**，若六店全常驻则该算法的静态上界约 **48 MiB**，均**不含 mip、图集 padding、CPU/GPU 双份、场景/背景或实际压缩格式**，也不是设备 PASS。PSD 多语义层是制作源，不进入运行包。Tech 首样前评估该上界、可能的图集页、Web 上最大纹理尺寸、最坏同时加载数量和加载策略；样张后再按实际 alpha 包围盒、PNG 文件头、Creator 导入设置、纹理驻留和投影像素修正全量预算。不能以“同图集”推定单 DrawCall。

首样实图检查须有：屋顶去标局部与补瓦近景；奶茶窗口与牌匾正读；PSD 全层清单、编辑试验；透明边在黑/灰/白底预览；两张 PNG 按同脚点重组与 PSD 合成预览的逐像素/视觉差异；`720×1280`、`390×844` 同尺度全店投影、实际牌字投影和控件安全区；源图与导出 SHA-256。Art 按 `VISUAL_ANCHORS.md` 逐项标 `PASS/REVISE/NOT_TESTED`，Tech 根据实际 alpha、贴图面积、页数和展示尺度单独结论。样张 Art/Tech 两份 Review 通过后，还要另签全量六店预案，才可扩至 02–06。

## 5. 交接身份与停止条件

01 顶层唯一正式逻辑 ID 为已批 Tech v0.1 的 `MT_SHOP_01`；`U03_SHOP_01_MASTER/VISUAL` 仅是它的源/导出追踪身份，不另造 U03 专用 Prefab。实际 PSD、导出及未来 Creator 计划路径均在 `project/ASSET_HANDOFF_REGISTRY.md` 保留 `PLANNED_NOT_IMPORTED`，没有真实 `.meta`/UUID 时写待生成。其余五店顶层 ID 分别 `SHOP_02`–`SHOP_06`，不在首样批出图。

任一来源声明撤回或出现相反合同证据；使用许可不明字体、外部图片/纹理；原始 image_gen 图无法形成无屋顶大杯的独立完整店；PSD 可编辑边界/透明边不成立；字牌在小视口不可辨；1024² 画布、脚点或两图候选无法容纳已批视觉时，停在首样并报告 Master/Tech。任何改变已批六牌文字、店型轮廓或冷暖主次的方案先走受影响视觉 Revision。Gate2 由用户对**真实切片与同尺度重组**另行明确批准；本预签不能代替。
