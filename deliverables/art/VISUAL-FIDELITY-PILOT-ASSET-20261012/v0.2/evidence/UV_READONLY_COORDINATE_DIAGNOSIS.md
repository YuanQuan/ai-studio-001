# 灯笼 UV 坐标只读定位

实际核查自 2026-10-12 22:15:29 +08:00 开始；只读 Scene、TS、Effect、Creator 3.8.8 引擎源、导入产物与既有截图，未改文件、构建或操作 UI。数值明细见同名 JSON。

当前 body 为 1024×1024、全幅 rect、无 trim/旋转/atlas；pilot 新建的 frame 共享该纹理并设 `packable=false`。Creator `sprite-frame.ts` 对未旋转全幅 frame 令图顶 UV `v=0`、底 UV `v=1`，`simple.ts` 将该 UV 写入顶点。mask 128×256，非零源 bbox `[200,533,249,598]`，四边为零，库内 PNG 与源字节一致。运行日志保存的 frame 为折叠的 `Object`，未保留实际四角数值，所以下述屏幕换算仍是近似。

按 Scene/TS 的位置与 0.56 Sprite 缩放、720/1280 可见比例粗算，源灯笼中心 `[224,565]` 应在屏幕约 `[549,306]`；其纵向镜像 `[224,459]` 对应约 `[549,272]` 的屋檐。当前 Shader 用 `(1-uv0.y)*1024` 取源 y。实测播放差异中心约 `[544.83,271.46]`、bbox `[527,255,561,289]`，因此**纵向反转仍有强证据**。若只按非零 mask 49×65 像素乘 0.315，粗投影约 15×20 屏幕像素；实测 34×34、929 变化像素，不能仅靠一像素线性滤波外延解释。差异最大通道 30，且 263 像素只增亮、332 像素不同通道有增有减；在固定像素/固定合成、alpha 不变、强度≤1 的单纯 RGB 变暗公式下，这些增亮也无法解释。截图状态 `0.93` 不是每个采样像素同一时刻的精确 uniform 测量，不能据它反推实际着色器数值或单点亮度上限。

结论是“一行 y 改为 `uv0.y*1024`”仍是最小**候选**，并非已证实的完整修复；实测 bbox 大小、929 变化像素、增亮像素与最大通道差 30 超出粗模型的具体原因均为 `UNKNOWN`。若将来获得新的源码修正授权，应先在同一固定构建/画面记录 frame 实际四角 UV、纹理尺寸与 mask 采样/材质实例，再以灯笼中心及其镜像两点检查屏幕映射；只改一个变量后重新核动态非零区域、增亮像素、暂停/复位、alpha 与 Draw/纹理预算。若仍异常，停止并报告具体证据，不扩成新重构。当前累计修正 `3/3` 已满且用户仅授权先前语法两处，故此轮不应用任何 UV 补丁；动态 ROI 保持 `REVISE`，性能未测项仍 `NOT_TESTED`。
