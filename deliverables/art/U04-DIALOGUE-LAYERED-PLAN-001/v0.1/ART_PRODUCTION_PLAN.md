# U04 六店长分层对话资源制作方案 v0.1｜Gate1 待用户审批

## 范围与基线

沿用 `U04-DIALOGUE-PREVIEW-001/v0.2/mengtao_dialogue_u00_preview.png` 的前景半身像、上方六店长标签、底部名字与对白框的**横屏布局关系**；U00 背景从当前工程已导入的五层实际纹理和六店构建取得。预览图的背景由 imagegen 局部重绘、裁成约 16:9，文字也为生成字，均不得裁出或用于正式资源。主视觉对照拟用 `1280×720` 横屏物理画幅，与预览比例相近；这不是 Cocos UI 坐标或当前运行支持结论。现工程 `720×1280 FIXED_WIDTH` 是设计分辨率设置，具体横屏坐标、可见范围和安全区须后续 Client 在实际构建中核实，本方案不改场景设置或扩做纵屏适配。对照时使用同一 U00 场景、同视窗及实际显示尺度。六人既有批准图版只作身份与阶段外观基线；本方案不批准任何新图片。

人物来源精确到 `U04-MANAGER-PORTRAITS-001/v0.3/APPROVED_COMBINATION_MANIFEST.json` 的 30 项路径和 SHA-256：孟桃、阿棠、阿灯、小锦为 v0.1，阿角、阿炭为 v0.3。`Product U04-MANAGER-PERSONALITY-001/v0.3/PRD.md` 的身份、店铺、0/1/2/3 魂成长语义保持；本轮仅制作已选的 0／2／3 魂可见图，不新增 1 魂图。每阶段半身像独立定稿，不能把另一阶段五官机械复制后宣称成长成立。

## 结构、切换与文件

- 每人每阶段一份完整多图层 PSD，共 18 份。每份包括原图参考锁定层、衣装/身体与后发、去除旧眼眉嘴后的干净脸底、五个表情组（组内眉、眼、嘴分别可编辑）、必要的前发/眼镜遮挡、位置标尺与导出说明。原批准图不得直接破坏；修改区、补洞像素和 PSD 可编辑范围逐版记录。
- 每阶段导出一张透明半身基底 PNG、五张仅含表情的透明 PNG（眉眼嘴可在源 PSD 独立调整，输出可合并为**局部脸部覆盖片**）、必要时一张前发/眼镜遮挡 PNG。不能用五张完整半身图轮播冒充表情层。眼镜、耳饰、发型、体型与衣装按阶段留在各自层；遮挡顺序为身体/后发 → 干净脸底 → 当前表情 → 前发/镜框及固定饰件。前发无覆盖时不强造空图。
- 同一人同一阶段五表情共用画布坐标、脸部中心、双眼/嘴锚点及 pivot；若裁成不同矩形，必须逐张保存 rect/offset 到阶段画布的映射，PNG 透明边和裁剪偏移登记在导出清单。切换不跳脸、不露旧五官、不割断发丝。换店长或阶段时整体换其基底、表情、遮挡套件，但保留另两轴状态，并按新套件取相同表情语义。索引必须覆盖 `6×3×5=90` 个可显示组合，禁止落到错误店长或阶段。
- 五种表情按 `高兴 / 惊讶 / 悲伤 / 微笑 / 生气` 固定语义。高兴为明显提眉、眼神发亮与更开放的嘴形；微笑为收敛眼弧和轻扬闭/小开口嘴，两者在小视窗仍能区分。惊讶有眼睁大、眉抬与口形变化；悲伤有眉眼压低但不抹去人物身份；生气有眉眼收紧而不改变角色人格。各表情随该阶段眉形、眼神、脸型重新校准。

示例控制分三条独立选择行：**店长行**含孟桃/阿棠/阿炭/阿角/阿灯/小锦六项；**魂阶段行**含 0/2/3 魂三项；**表情行**含高兴/惊讶/悲伤/微笑/生气五项。任一行变化时保留其余两行已选值，半身基底、脸部片、必要遮挡及显示姓名按新组合同步；若显示阶段字样亦随阶段更新。正文仅用已有简短示例文案，不添加剧情、玩法或新魂规则。三行是功能要求，具体控件布局由 UI/Client 后续按现有预览关系落实，不在本方案新增界面方向。

## 九宫格对话框

对话框为单独透明 PNG 与多图层 PSD，复用 v0.2 的深夜蓝底、暖金细边视觉；名字、对白、六标签文字、箭头和任何跨越可拉伸中心的固定纹饰均作为独立 UI 节点或独立固定装饰资源，不烘进九宫格中心。若角云纹跨越切分线，拆成固定角饰图层/PNG，角饰随对应角定位但不拉伸。六标签的选中态属于可复用标签组件，不烘在对话框纹理。

**拟制作参数，待样张与 Tech 预签定稿：**面板源图 `512×256 px`，左上角为 `(0,0)`，竖切线 `x=48,464`，横切线 `y=48,208`；Insets 为左/右各 48 px、上/下各 48 px。四角保持源像素比例；横边只沿 x 伸缩、竖边只沿 y 伸缩，中心可双向伸缩，所有连续金边在交界处无接缝。几何最小尺寸 `96×96 px`；文字可用的布局最小尺寸暂定 `384×192 px`，低于它需换行/缩短文本或调整布局，不挤压四角。面板视觉缩放系数由实际视窗确认，不能把本源图像素直接当屏幕实测。

样张须用同一原图切分坐标，在 `384×192`、`768×256`、`1024×384` 三种面板目标大小重组，并置于同一 U00 背景和角色显示尺度，核四角圆/云纹、边框粗细、边与角连续、背景透明和文字避让。`384×192` 只是拟定布局下界，不保证任意长度文字容纳；以拟定 `1280×720` 横屏物理画幅作主视觉对照，检查长文本换行、溢出、固定角饰遮挡及可见安全区。现工程设计分辨率与此不同，实际运行宽屏可见范围须 Client 后续构建核实；其他屏幕方向布局适配不在本轮范围，记 `NOT_TESTED`。Tech Lead 确认 Creator `Sprite.Type.SLICED`、border/inset 单位和实际 SpriteFrame 设置；最终采用的切线、最小尺寸与 Creator 导入值记录到资源清单。若九宫格不能保留 v0.2 框的关键效果，先修订方案送审，不在产出时暗改布局。

## 批次、预算与门禁

Gate1 用户明确批准本 v0.1 方案后，Art 与 Tech Lead 在首张图前对**同一批次**的来源、PSD 结构、实际裁剪/偏移、九宫格边界、画布、图集和预计驻留量预签。先做**孟桃 0 魂**一组同尺度样张：一个干净半身基底、五局部表情、必要前发遮挡、PSD 及 U00 同尺度重组；并做九宫格面板的三尺寸重组样张。批准角色源 `1024×1536` 存在低 alpha 软晕，须逐张核原图透明边、去旧五官后的补洞与发丝/脸缘接缝，不能假设自动抠除成功或直接把原图当干净 Sprite。Art 逐锚点看实图，Tech 核真实 alpha、尺寸/页数与成本；通过后复签全量方案，再扩至其余 17 阶段。失败样张留档，不能扩批。

估算起点：PSD 源可沿既有 `1024×1536` 参考画布，半身输出先按不超过 `768×1024`、脸部局部片不超过 `256×256` 试算；18 张基底约 54 MiB、90 张局部片约 22.5 MiB 的 RGBA8 理论全展开量（未计最多 18 张前发/镜框遮挡、面板、图集空隙/页、mipmap，也不代表运行时会同时加载），不是运行占用实测或性能通过。实际裁剪、页数、同时加载策略和目标设备预算须 Tech 预签并用样张修正；不能为节省资源牺牲已批准轮廓和五表情辨识。

全量完成后记录每个 PSD、PNG、源版本、SHA-256、导出映射、同尺度重组与 90 组合清单。若由本组织 Agent 自行切图，依现行契约以真实切片、重组效果和清单**直接送用户 Gate2 审核**；Gate2 对具体版本明确批准前，Client 不得正式接入。接入后再按实际 U00 画面与资源指标核验；本单元示例由 Owner 留证，不形成正式 QA 通过结论。
