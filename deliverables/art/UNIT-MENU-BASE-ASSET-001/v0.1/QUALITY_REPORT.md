# STREET_BASE_01｜资源质量报告 v0.1 REV2

## 实际输出和可复验结论

原创可编辑 SVG 与 16 张独立纹理已真实输出，42 个放置实例由 `LAYER_MANIFEST.json` 记录。最终母版 SHA-256 `7ffa5218b2cee135242242b026c23f5dfb3b99b170486751206e949916ba09d2`；导出全景 SHA-256 `f817b9fae511223a3aeddb8626d1ef1ddcab409ad656fd263423be767e47ee46`。PNG 总基础量 `8,847,360 B / 8.4375 MiB`。`tools/verify_layers.js` 对实际 16 PNG 的尺寸、SHA-256、alpha bbox 与 manifest 一一比对，`QA_STATIC.json=PASS_STATIC_CHECKS_ONLY`；REV2 相比 round1 仅 `bridge_back` 与三张 `distance_*` PNG 改变，其他 12 张真实 hash 不变。

天空 32×1024 所有像素 alpha=255 并横向覆盖 3072×1024；最终全景与 7 张 720×1280 镜头裁图 alpha 全为 255，无透明漏边。`bridge_back` 局部 `(256,260)/(256,320)/(256,380)` 三点 alpha=0，透出支流；地面 x1280..1792 中央缺口未放铺地，支流 y640..896 与前河 y832..1024 重叠。街/河/岸四处纹理复用边界的平均 RGB 邻接差分别约 0.04/0/0（0–255 标尺）；桥两端 x1280/1792 为材料构造接缝，y480..745 平均邻接差约 13.81/13.55，需在 Creator 手机缩放后确认是否过于突兀。这些是静态像素检查，不能替代视觉或运行判断。

## 视觉审阅与保留风险

round0 首次出图失败：桥坡/石街之间矩形暗缺口，云平底、规则纹理；round1 缺口消除但桥像整块高墙，远山单层。两次均完整封存在 `audit/round0/round1/`，先有各自 Art/Tech 修订双签再修改源/出图。REV2 在同一 16 纹理中把两端改成与街同调铺地、中央拱面收窄，并增加桥顶铺地走道带与缓坡石阶线；远山改曲线峰和深浅雾层。全景、桥局部和中/西/东竖屏裁图可看出连续通路与真拱洞。背景仍刻意安静，为后续独立店、顾客、树灯和特效预留位置；**空景单独观看的插画层次仍明显弱于含店/灯的用户参考**，不能以“同配色”断言最终组合画风已验证。桥顶在 720×1280 缩小后可行走坡感仍需要顾客动画走桥、正确前后遮挡实测。

候选竖屏 `s=1.35` 可见世界宽约 533px，初始中心 x1536 只覆盖桥，不能同时看到两侧未来店铺。`viewport_init_west/east` 仅证明同底板两侧观察点可裁出内容；新增对象时的镜头定位或跳转、手拖/缩放和 UI 事件隔离由 Client/QA 后续实现验证，菜单 1/7 需同源 reset。尺寸 1.25 最小缩放在 720×1280 设计视窗恰好覆盖画布高度，真实安全区/DPR/滤波可能露边，Client 应以实际视口复算留采样余量。

未测试：Creator 3.8.8 导入与 SpriteFrame/Prefab UUID、目标设备最大纹理/压缩/解码峰值/显存/DrawCall/帧时间、顾客走桥、未来店/树/灯叠放与主体第三入口同源。不能把 16 张纹理、`8.4375 MiB` 基础量或静态裁图推断为目标机性能/完整游戏验收通过。
