## 2. 画布、层与视觉样张

为同尺度审阅，建议维持**逻辑世界候选 3072×1024、约 3:1**，只在编辑源中绘制中央代表区域并保留未来全景坐标；样张审阅裁窗候选为中央约 `1536×1024`，包含桥两端街、支流水口、前河及足够远景。该裁窗是**审阅合成图**，不是运行时一张 1536×1024 背景纹理；实际坐标和是否需要更宽以容纳偏右月光由 Art/Tech 在签字前决定，不能直接沿用旧 v0.1 石桥比例。另输出按 720×1280 候选视窗的中心显示模拟，供判断桥是否像墙；这不是 Creator 真机通过结论。

编辑层语义从远到近：`UB_SKY` 夜色与月 → `UB_DISTANCE` 至少可辨远/中/近山雾 → `UB_WATER` 前河与桥下支流 → `UB_GROUND` 石地及可走坡面 → `UB_BANK` 石岸厚度 → `UB_BRIDGE_BACK` 拱洞后壁/远桥栏 → 将来对象脚点层 → `UB_BRIDGE_FRONT` 桥前缘/近栏 → `UB_RAIL_BACK/FRONT` 依顾客路径拆分。月光反射作为固定静态水面关系分层，不等于可关闭的店灯或灯笼 VFX；是否有未来动态水效由 VFX 另案。中央桥洞必须为真实透水透明口、支流与前河连通；坡面要与两侧街砖可见地接平，正面墙高度不能让中心手机裁图失去步行桥识别。

## 3. 纹理/内存/合批草排，先不锁全量页数

本批只需要**样张源和供审美的合成预览**；审阅合成图不计作运行贴图。为 Tech 评估，样张按可单独导出的天空/山雾、石街/岸、桥前/后、水及栏前/后语义组草排，优先尝试每张运行候选纹理最大边 `≤1024`，并记录每组实际 alpha bbox、世界放置、重复次数与材质。旧 v0.1 的 16 张纹理/8.4375 MiB 仅是失败版实数，**不是本版必须压回的质量上限**。样张阶段先报告真实可见像素面积和若以 RGBA8 计算的基础量；全景扩展后的纹理数/总面积、压缩/解码峰值须由 Tech 依据新样张另做容量方案，不可在无图时虚称测得。

背景静态层、桥前/后片、将来角色/VFX/UI 的交叉渲染会因纹理、材质、透明混合及层序断批；复用源块、共用图集和一次 Draw Call 是不同事实。本样张不得为了追求旧 16 纹理或单次合批而删除 B1–B3 的山雾、石材或水光层次。若预计纹理/内存超目标设备限制，Tech 用候选大小与质量影响量化说明，Master 呈用户决定，不由 Art 单方扩页或技术单方扁平化。

## 4. 双签与完成后证据

Art 本版只签认可审美目标、原创方案和排除范围。Tech 需明确认可/修订样张画布与裁窗、可编辑源格式/导出链许可、层语义/桥洞 alpha、每候选纹理最大边、内存计算方法、断批风险和 720×1280 候选裁切。Tech 结论写 `TECH_PREFLIGHT.json` 并以同版、日期、文件路径引用本预案；若提出会削弱桥/山/水视觉的限制，先回 Art 修订和用户审批，不直接 `APPROVED_FOR_EXPORT`。
