# U01 五层重绘｜分区新绘首图预案 v0.3

状态：供 Art / Tech Lead **首图前对同一 SHA-256 预签**。上游 `U01-FIVE-LAYER-REDRAW-PLAN-001 v0.3` 已 `USER_APPROVED`；本文件只规定新的内置工具试产方法，不改变 3840×1024、五层身份或已批准构图。旧资源 v0.2 的 S01/S02 失败样张及预签保留，不视为本版样张。

## 视觉与来源

以项目已批四层 PSD 的 `overall_from_psd.png` 作视觉身份参考，不复制旧像素放大成新细节。蓝夜暖灯、月、雾山远楼、柳、中央石拱桥、灯船与右牌楼保留；本轮新构图必须让天空可见高度增加、河水可见面积减少、近景石板街道加宽并向左右铺开，桥及通桥道路纵深不压扁。未批准的酆都城文字、桥牌和引魂幡不加入。参考仅用本项目既有用户授权文件；新外部图片或字体须另做来源/许可检查和受影响预签。

## 为什么改为原生分区

内置 `imagegen` 两次完整画面输出均实测 2172×724：第一次引用旧 2172×724 合成图，第二次引用准确 3840×1024 的透明扩绘参考，结果仍是 2172×724。它没有可由本流程指定的确定输出尺寸参数。继续对整幅图重复要求 3840×1024 没有新依据。`bggg-creator-image2psd` 已实测可写入和回读 3840×1024 栅格多层 PSD；它只能放置/缩放已有像素，不能补出新细节。

本轮只试 **在内置工具实际得到 2172×724 原生新绘分区时，以 1:1 像素原位放入 3840×1024**。分区不是将一张旧图裁成多块；各窗口分别生成新内容，保存完整原始结果、提示词、参考关系、尺寸、SHA-256 和位置。`bggg assemble` 的 manifest 使用 `fit: none`、`remove_background: none` 及明确 `x/y`；不得用 `contain/cover/stretch` 冒充近景细节，也不写自定义 Python 羽化/拼图脚本。工具返回其它尺寸、可见模糊、重复纹理或新画不符合视觉锚点即停线评估，不在本版自动改尺寸。

## 原位几何与桥的保护

全画布坐标为左上原点，宽 3840、高 1024。暂定五个 **2172×724** 窗口，表内坐标是试产的准确放置值；实际图像大小必须先读回确认。

| 窗口 | 左上坐标 | 覆盖矩形 | 用途 |
|---|---:|---:|---|
| 上左 | (0, 0) | x 0–2172，y 0–724 | 天空、远景左段 |
| 上右 | (1668, 0) | x 1668–3840，y 0–724 | 天空、月与远景右段；与上左重叠504像素 |
| 下左 | (0, 300) | x 0–2172，y 300–1024 | 左延路、柳、岸线 |
| 下中 | (834, 300) | x 834–3006，y 300–1024 | **完整中央桥、桥前进深线及较宽石板街道** |
| 下右 | (1668, 300) | x 1668–3840，y 300–1024 | 右延路、牌楼、岸线 |

下中窗口最后叠放，桥体与通桥进深线必须完整处在它的内部安全区；可见左右接边在 x=834 与 x=3006，远离中央桥。下左/下右先放、下中后放，中央左右与侧窗分别有1338像素重叠。上下窗口重叠424像素，最终可见接边和层顺序须依据实图选在不切断身份元素的位置；不得只靠覆盖把明显错位或色差藏进 PSD。上行两窗之间的接边也必须逐处检查。任何锚点跨接边冲突、天空色阶跳变、栏杆/石缝/岸线断线或四窗交区鬼影都判 `REVISE`。若需要修接缝，仅用内置 `imagegen` 对该分区作定向编辑、保留修订前后图；新方法、尺寸或图层范围超出预签时先复签。

## 样张顺序与停线关口

1. Art/Tech 分别对**本文件同一 SHA**及 `TOOLCHAIN_AUDIT.md` 预签，确认批准版本、来源、几何、图层、目标格式、预算与停止条件。首图前仅授权下中 S03 一张原生分区样张；预签不是尺寸或视觉已通过的声明。
2. 用内置 `imagegen` 生成 S03 **下中窗口**，采用新构图说明和旧画视觉锚点。旧图可作为风格/身份参考，不要求工具输出整幅3840×1024，也不把旧桥放大。保存工具原始图到本版 `source/`、完整提示词及来源；核尺寸必须为本方法预设的2172×724，实看桥、桥前纵深、近景石路面积、河水减少、蓝夜暖灯、近景细节及无未批文字。单张只能证明自身，左右/上下全景关系和拼缝标为 `NOT_TESTED`。
3. 仅当 S03 的 Art 逐锚点视觉检查与 Tech 像素/清晰度检查均通过，生成 S04 **下左窗口**，用 S03 作构图和光色接续参考；内置 `imagegen` 负责画面编辑。用指定 `bggg assemble` 将两张原图按表中坐标和 `fit:none` 置于 3840×1024 临时预览/栅格 PSD，未覆盖的区域保持透明。检查 x=834 可见接边的道路、栏杆、柳/岸线、水纹及色光连续性，1:1 与目标手机视窗都看；两张原图仍必须各为2172×724。任何明显接缝、桥被边界切割、低清晰度或外延路不连续即停，不扩其余窗口和五层。
4. 两窗样张通过后，Art/Tech 对实图及**全量扩批预案再次同版复签**，才生成上左、上右、下右。完成 3840×1024 完整场景后核上/下、右侧接边与交区，和旧基线及新构图逐项同尺度比较。只把通过的完整场景用于后续 L01–L05 语义分离；五层同画幅 RGBA、L04 补水草旧位、L05 独立水前草，保留未裁源。分层/alpha 与原位一致性另过 Art/Tech 样张关口后，再由指定 `bggg` 转成五栅格层 PSD 和 PNG。

## 交付、预算与限制

五张 3840×1024 RGBA8 基础展开量 `78,643,200` 字节（75 MiB）；临时分区、未裁层、PSD、mipmap、CPU/GPU副本和运行峰值额外计算，目标平台实际支持及运行仍 `NOT_TESTED`。Tech 需在预签标明这一估算与后续 Creator/设备复核点。透明裁减只对完整镜头连续域证明恒被不透明覆盖处进行；证明不足不裁。最终保存每块原图/版本/提示词/坐标/alpha、完整未裁图与层源、PSD回读、五张 PNG、同尺度重组、手机视窗和逐项差异证据。由本组织自行切图时按规则直接送具体版本 Gate2 用户审核；批准前不交 Client 正式接入。

本方案最大未知是内置工具能否按“局部窗口”而非整场景作画，以及跨块结构和光色能否自然衔接。拼成3840×1024只证明**几何覆盖**，不证明3840宽的新绘清晰度、全景连续、五层可拆或运行合格；这些必须用实际样张逐关口证实。一次S03或S04失败后保留实图与失败原因，由Master决定修订方法或请求用户选择，不无限重复同一指令。
