# 骨骼对象单页图集草排与联合签认 v0.1

本表只为**正式绘制前**检查是否有合理单页路径。图格坐标是草排容器，不是实测分件、打包结果或运行 Draw Call。每骨骼对象全部附件只准一张独立图集页；静态店身走静态资源链。候选尺寸 `MT_CHAR_01` 1024×1024、`MT_SHOP_MOTION_01` 512×512，均须以实际纹理像素边界、目标机屏幕投影及压缩能力复核；一页放不下时先减空白/改画法/压备用件，仍不成立才提交 Art+Tech 变更页尺寸与设备风险，不能暗增第二页。

## 角色页：1024²候选

坐标 `(x,y,w,h)` 从左上起，单位为候选 atlas 像素。表内每格**已预留四周各 8px 空边**，有效画面最大为 `(w-16,h-16)`，切片尺寸和该空边尚未真实测量。格子互不重叠；空边可供挤出边缘色与纹理过滤安全区。镜像关系不代表可以只画左侧：真实图形与布纹/光方向须分别验收。部件旋转摆动的屏幕外包围盒另测，不能由静态格子推出。

|---|---|---|
| `MT_S_AWNING_L` | `(0,0,160,192)` | 上卷边、背面、内侧压边 |

三片不复制一个纹理后强行镜像已绘阴影；若材质与褶皱实际可共用，必须人工对照左/中/右边界并记录共用映射。帘轴在静店 BACK，不进本页。当前纸牌、杯标、机器、两灯、纸盒都是静态，不给动态页增新附件。布帘左右极值的画面外包围盒和与匾/角色的碰撞范围需通过骨架试摆实测。

## 每页生产测试矩阵与签认条件

| 必填实测项 | 美术提交 | Tech/Client复核与通过依据 |
|---|---|---|
| 实际切片边界与动作极值 | 源图每片 `(w,h)`、pivot、旋转最大角、透明图与 bind/极值/恢复帧 | 自动 pack 一页、导出 atlas 页数=1；极值无露底/遮眼/穿柜 |
| 清洁 alpha 与过滤 | 去半透明背景暖晕；透明像素扩边候选至少 2px，格内保留 8px 外空边；注明直通/预乘模式 | 在目标 Cocos/Spine 导入组合下逐帧看黑边、白边、光圈；压缩后再次复查；最终扩边由真实采样定 |
| 采样/trim | 源保存完整非破坏层；首导候选关闭旋转 trim 以核对锚点，稳定后可按工具兼容情况试用 | 导出文件、纹理/骨骼引用、锚点/透明范围一致，稳定重导不会改变骨骼名与 attachment ID |
| 色彩/材质/混合 | 统一 sRGB 色材、无额外烘光、多贴图依赖与未授权字体；记录备用表情/手型 | 实际材料、混合、裁剪/stencil、层级不能使单页对象拆批；若拆批记录原因与修复方案 |
| 纹理与设备 | 页尺寸候选、实际 PNG 文件字节、透明面积、颜色边缘；在 720×1280 设计分辨率 Lab/主体分别记录“孟”字、奶茶牌和握杯动作投影像素 | 按确认目标设备测试格式/压缩后视觉、纹理内存、峰值占用、GPU/CPU帧时及 Draw Call；三名未看放大图的评审在 100% 原生尺寸识别重点；无法取得设备则不签最终预算 |
| 双入口同源 | 唯一源哈希、导出哈希、版本号，店身 BACK/FRONT同基点 | Lab 与主体同一资源/Prefab ID 及版本引用，改源重导后两入口一致 |

本轮仅 Art 的视觉方案可签审阅、Tech 对**前置检查矩阵**可签技术可实施性；**真实出图放行签字**要等逐片源、Spine 编辑器/版本、自动 pack、Creator 导入和设备证据。`engine.json` 启用 `spine-3.8` 只证明项目配置，不证明本机已有编辑器或已导出。单页是材质/批次优化必要约束之一，不承诺一次 Draw Call。
