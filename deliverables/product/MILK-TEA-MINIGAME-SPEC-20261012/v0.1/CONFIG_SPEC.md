# 奶茶小游戏配置业务字典

版本 v0.1｜Product 人工源表 DRAFT，数值与此前未定边界均为 `PROPOSED`。文件：`project/config/source/MILK_TEA_MINIGAME_v0.1.xlsx`。该工作簿只含 MG01，不是运行配置。稳定 ID 一经批准不得复用给别的语义。技术类型、跨端可见性、导出和存档兼容待 Tech Lead 评审。

四张逻辑表每行都有 `status=DRAFT` 与 `export_enabled=false`。`export_enabled` 是业务内容是否允许导入运行配置的独立门禁草案，当前全部关闭；它与 `xp_enabled`、`level_enabled`、`soul_enabled`、`spirit_enabled` 等解锁条件开关没有关系。后者只在该解锁记录成为获批运行数据后决定门槛是否参与 AND 判定，不能因为 `xp_enabled=true` 就导出 DRAFT 记录。实际导出契约仍需 Tech Lead 评审。

`MG01` 是本稿产品模块 ID，不冒充现有工程的店铺 ID。当前工程奶茶店 ID 为 `MT_SHOP_01`；两者的正式绑定关系及引用校验待 Tech Lead 对现有店铺目录评审后确定，本工作簿不创建虚构的运行 `shop_id` 字段。

| 工作表 | 主键与业务含义 | 主要字段与约束 |
|---|---|---|
| 难度阶段 | `stage_id` 唯一，形如 MG01_EASY_1 | `tier_id`、`stage_no`、`xp_from` 为阶段起始累计熟练度；`recipe_dims` 必须 3/4/5/5/5；`orders_target` 正整数；`time_sec` 简单留空，中等以上正整数；`options_per_dim` 2–4，且不超过各维度可用原料数；`xp_reward` 同档两阶段相同，高档逐档增加。每档阶段2起点高于阶段1，阶段2为上限。 |
| 解锁条件 | `tier_id` 唯一；简单为初始开放 | `prev_tier_id` 指向上一档；`xp_enabled`、`level_enabled`、`soul_enabled`、`spirit_enabled` 为开关；对应 `*_min` 为门槛。上一档通关恒必需，开启的四项全为 AND。魂数 0–3，魄数 0–7，分别校验。全部关闭只检查上一档通关。 |
| 原料 | `ingredient_id` 唯一 | `dimension` 为 TEA/MILK/TOPPING/SWEET/ICE；`name` 为用户可读名；`sort_order` 决定阶段备选基础顺序。每维至少四个可用项，供五档阶段配置。茶底、奶类、小料每杯恰好各选一项，不增加多小料组合。 |
| 配方 | `recipe_id` 唯一 | `tier_id` 指向难度；`min_stage_no` 为配方开始可出题的阶段（1或2）；五个原料引用分别对应五维。简单的甜度和冰量留空，中等冰量留空，困难以上五维均填写。每档阶段1有两条、阶段2新增一条配方，不跨档引用未启用维度。订单展示名为 `drink_name`；配方内容由这些引用决定，不用显示名解析。 |

`tier_id` 固定为 EASY/MEDIUM/HARD/HELL/NIGHTMARE。每档阶段根据点击“开始制作”时对应店长的累计熟练度选择当前阶段；低于阶段2起点一律选阶段1，达到后选阶段2，之后封顶。阶段1的 `xp_from` 是普通成长排序参考，不是隐藏解锁条件；若关闭熟练度解锁门槛并满足上一档通关及其他启用条件，即使 XP 低于该档阶段1的 `xp_from`，也能进入并使用阶段1。阶段、目标、配方池和备选数在一局内锁定，通关经验带来的升级从下一局生效（`PROPOSED`）。选项池按原料表 `sort_order` 的前 `options_per_dim` 项形成；仅 `min_stage_no` 不高于当前阶段的配方可出题，所有配方引用必须位于其可出题阶段的备选池。阶段2新增的第3／第4顺位原料会成为新增配方的正确答案，不只是干扰项；旧配方的正确原料仍在池内。阶段1从两条配方、阶段2从三条配方出题；抽取可重复（`PROPOSED`），不把配方记录数等同本局杯数。正式出题算法及随机种子留 Tech 设计。

本稿提案熟练度阶段阈值分别为：简单 0/20，中等 50/75，困难 120/150，地狱 220/260，噩梦 360/410。下一档熟练度门槛为 50/120/220/360；此为仅启用熟练度条件时的默认草案，适合按通关数逐步推进，未被用户批准。每档通关经验 10/15/22/30/40；跨档严格增加。阶段2有限封顶。店长等级、魂数、魄数开关在本稿默认为关闭，对应门槛数值只是关闭状态下的占位，不是已批准门槛。工作簿每条记录均标 `DRAFT`，整本不得作为运行输入。

数值理由（`PROPOSED`）：只启用熟练度门槛时，简单 5 次通关得到 50 XP；随后中等从 50 到 120 差 70，15 XP／局约需 5 次；困难从 120 到 220 差 100，22 XP／局约需 5 次；地狱从 220 到 360 差 140，30 XP／局约需 5 次。实际累计经验可溢出门槛，故不是固定每档恰好五局。噩梦阶段2上限 90 秒、3 杯，每杯 5 次选项点击加一次交杯，至少约 18 次核心点击；90 秒只是首轮可完成性假设，尚无运行和平衡测试，不宣称最高档已经验证可完成。

关键字段空值与范围（均待技术类型评审）：`stage_no` 仅 1 或 2；`xp_from`、`xp_reward`、各 `*_min` 非负；中等以上 `time_sec` 必填且大于 0，简单必须留空而非填 0。`initial_open` 仅简单为 true；简单 `prev_tier_id` 留空，其他档必须引用紧邻上一档。关闭的解锁门槛不参与解锁判断，但占位数值仍须符合范围，其中魂数 0–3、魄数 0–7。每行 `status=DRAFT`、`export_enabled=false`；由这些字段不能推断任何草案记录可导出。

正式导入前应核对 ID 唯一、引用存在、启用维度和空值、选项池涵盖配方引用、阶段阈值单调、计时边界、五档奖励递增及解锁开关／门槛合法。具体字段类型、运行配置生成和权限由 Tech Lead 审查后确定。`CONFIG_VALIDATION.md` 记录本版人工源表检查结果。
