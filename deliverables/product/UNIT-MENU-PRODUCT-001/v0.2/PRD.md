# 百鬼夜市｜七项菜单单元样例产品规格 v0.2

任务：`UNIT-MENU-PRODUCT-001`。状态：`DRAFT`，待专业影响评审、Master 评审及用户审批。日期：2026-10-03。v0.1 已获用户批准并保留历史；本版只修订最终资源交付性质与幽灵动画方式，七项菜单和既有语义不缩减。

## 1. 目标、依据与版本边界

本版将用户新提出的七项菜单样例落实为可单独观看、操作、重置和验收的展示范围。单元产物最终应能在 Cocos Creator 中独立打磨，并由组合场景及未来主体游戏复用同一源对象、表现状态、UI 和特效。菜单用于检查表现与接入，不模拟完整经营玩法。

- 原始范围：[七项用户输入](../../../../project/unit_tests/UNIT_MENU_SCOPE_INPUT_v0.1.md)。本版覆盖七项全部顶层菜单，不延续已取消的 `UNIT-SAMPLES-001` 九项列表。
- 已批准语义：[孟桃奶茶店最小产品规格](../../UNIT-PILOT-PRODUCT-001/v0.1/PRODUCT_SPEC.md)及其 `ARTIFACT_APPROVAL.json`：孟桃为奶茶店在岗店长；她是孟婆外孙女、叛逆甜品控、不想继承汤铺、想开自己的奶茶店；展示常态和一次演示工作表现。此处不改动上述语义。
- 已批准视觉基线为当前[项目美术指南](../../../../project/ART_GUIDE.md)及孟桃概念 v0.5。平视角顾客只需左/右；**`DEC-UNIT-FINAL-ASSET-004` 最新决定把幽灵从骨骼改为一个方向原创序列帧，另一方向对同源帧水平翻转**。店铺和店长仍按实际单视角，其他动态对象仍按骨骼原则；最终画面延续未加宽、非像素夜市风格。美术指南中的旧幽灵骨骼文字须由 Art 后续修订，不以旧句覆盖新决定。
- [七菜单范围提案](../../../../project/changes/CP-UNIT-MENU-SCOPE-001.md)的产品范围已获用户批准，工程/资产契约仍待专项审批；[新资源变更提案](../../../../project/changes/CP-UNIT-FINAL-ASSET-FLIPBOOK-002.md)与本版 `CHANGE_IMPACT.md` 记录最新覆盖，不能把提案视为真实资源通过。
- 四份 `UNIT-MENU` 专业 v0.1 中，UI 结构/交互版获用户批准；Tech、Art、VFX 含幽灵骨骼冲突而整版 `REJECTED`，保留历史并修订。此前 `UNIT-PILOT` 四专业 v0.1 仍不得被当作本版新增幽灵/场景正式输入。具体状态以对应审批记录为准。

## 3. 七个顶层菜单

| 编号及菜单名 | 本项独立验证目标 | 最小可操作内容与结果 |
|---|---|---|
| 1 空场景与镜头 | 看见只有固定背景的夜市基底并验证镜头 | 左右拖拽移动视野；放大/缩小视野；回到初始镜头。没有店铺、店长、顾客或第 4 项可切换物件 |
| 2 店铺效果 | 验证孟桃奶茶店自身的外观、动态部件和光影 | 常态/一次动效预览/重置；可比较灯照亮的区域、邻近材质上的明暗与投影变化；店铺切换入口当前只有奶茶店 |
| 3 角色效果 | 分别验证孟桃店长与幽灵顾客 | 子入口 3A 孟桃骨骼常态/工作表现/重置；3B 幽灵顾客的左右朝向和移动、跑动、高兴、沮丧、街边板凳坐姿，并可逐项切换/重置 |
| 4 场景其他元素 | 分别验证带动态/特效的树木、花草、灯笼 | 每类独立显示/隐藏、预览动作或特效、重置；不将它们烘进第 1 项背景 |
| 5 UI 界面 | 独立检查可复用的正式 UI 与菜单测试 UI 的边界 | 展示奶茶店／店长孟桃身份信息的共享组件和关键状态；样例导航、诊断、动作按钮仅在 Lab 入口；不增加经营 HUD 或未经批准的系统页面 |
| 6 店长与玩家对话 | 查看孟桃对话界面、示例文案与关闭流程 | 仅孟桃头像/名字、玩家侧标识与一轮示例文字；打开、继续/关闭、重置；示例不成为正史剧情或商品承诺 |
| 7 组合场景 | 在第 1 项的空场景基底上逐项动态装配对象，检查遮挡与同源 | 可加入/移除奶茶店、孟桃、幽灵顾客、板凳和第 4 项各类元素；可触发其已批准表现、改变顾客可测试位置、查看与桥/栏杆/店铺前后关系；可选显示第 5 项共用身份 UI 和第 6 项对话浮层 |

公共菜单的进入、返回、重置、当前样例标题与状态提示属于基础导航，**不计作第八项**。每项返回再进入后应有可预测的初始状态；切换样例不把先前动作、特效或对象开关残留到新入口。Lab 控制不混入主体游戏正式 UI。

### 3.1 空背景与镜头

背景基底仅容纳持续存在的天空、远景、地面、河岸/水体、桥、栏杆等场景基础层，须符合已选夜市视觉方向。可独立开关的奶茶店、孟桃、幽灵顾客、板凳、树木、花草、灯笼及各自特效不得预先绘入这个基底。若某个远景装饰看起来与可切换对象同类，Art 须在资产清单明确区分且不能造成“已关闭却仍出现相同对象”的验收歧义。

拖拽以玩家可见的**水平方向平移**为结果；缩放以画面视野明显变大/变小为结果，始终能回到初始视野。鼠标/触控的具体手势、镜头最小最大值、边界与分辨率适配由 Tech/Client 制定，产品验收关注可控、稳定、不露出未制作区域、不因 UI 操作误拖场景。基底同时作为第 7 项唯一组合底板，不另造一张看似相同的背景。

### 3.2 店铺与孟桃

第 2 项与第 3A 项分别展示**独立对象**，第 7 项再让二者共处。奶茶店保持复古木砖瓦、浅色木框牌匾、奶茶杯吸管小标识、奶茶机/价目表/纸盒原料等已选概念元素；牌匾和内容的正式字形须经许可与小屏可读性检查。店铺身形使用退回加宽稿之前的比例。孟桃只在腰牌保留“孟”字；其店长身份与四项已批准角色种子不变。

需要动态的孟桃及店铺可动件按骨骼动画交付，每个骨骼对象的图像附件各落在一张图/图集。静态店身可继续静态分层。第 2 项至少有一处可读的店铺动效与一处可读的暖灯光影变化：明亮区域、邻近材质的暗部/投影须有可对照变化，不能仅换灯笼图标或开关发光点；既能独立观察，也能与第 3A 项工作演示协调。工作演示是“启动—动作—反馈—回常态”一轮，不意味着真实售卖或奖励；反复触发不叠动作、不残留反馈。店铺与孟桃只制作实际使用视角。未来切换其他店铺/店长时保留独立对象及共用展示接口的意图，由 Tech 决定实现，不预造其他内容。

### 3.3 幽灵顾客与板凳

第 3B 项先做**一名代表性、可爱且不恐怖的原创幽灵顾客**，以平视镜头提供左、右两个朝向，并切换以下五类状态：移动、跑动、高兴、沮丧、坐在街边板凳上。移动和跑动要有可见的位移及状态区别；高兴和沮丧要以动作/表情区分；坐下须有接近座位、落座、坐姿稳定以及离座/重置的可辨认过程。顾客**不使用骨骼动画**，用一个方向的原创透明序列帧及可编辑源制作上述表现，另一方向仅对同源帧水平翻转。需循环的移动、跑动等以每动作约 4–6 帧作为预算起点，逐一检查首尾自然衔接、轮廓体量和位移可读；这不是五状态总共 4–6 帧。高兴/沮丧可以是一次动作加保持帧，坐姿可以是进座、稳定、离座过渡，不强制它们都循环或都用 4–6 帧。坐姿所需板凳为独立可复用场景道具，不把凳子画进顾客帧图。

**左右两朝向是顾客本样例的正式覆盖要求**；不再要求北/东/南/西四向。产品验收采用左/右 × 五类状态的展示矩阵；坐姿也需在两朝向下与板凳接触合理。水平翻转是既定资源约束，但技术上可翻转不等于视觉自动合格：镜像后字形、非对称挂件、手势、光影方向、帧图原点与接触点、板凳坐姿/座点均须经 Art/Tech/QA 实看。先调整原始设计，让两向镜像都成立；不该翻转的文字/UI 与顾客帧显示节点分离。若仍需为另一向新增专属绘制帧/附件，应作为显式变更经用户审批，不得仅凭 Art/Tech 签字扩成第二套方向美术。动作切换时前一状态退出、下一状态进入、朝向与坐点保持可解释；连续快速切换、返回、重置不能留下复制幽灵、错位坐姿或残留表情。这里不定义顾客 AI、寻路、消费、情绪数值或与店铺的经营关系。

### 3.4 场景其他元素

第 4 项至少提供树木、花草、灯笼三类可分别开关的**样例对象**。每类可看见其独立效果：树/草可轻摆、灯笼可轻晃或产生柔和灯光；静止物不强制虚构动画，但本项每类都要有可辨认的动态或伴随特效供验证。具体动作、发光层级、数量、纹理尺寸和性能降级由 Art/VFX/Tech 审批。凡决定动态的树木、花草、灯笼使用骨骼方案并遵守每骨骼对象一页图集；其特效与对象可一起隐藏，不留孤立光斑。树木、花草、灯笼保持可爱地府夜市视觉，不加入恐怖叙事或未批准玩法。

### 3.5 UI 与对话

第 5 项的正式共享信息只承接已批准的“奶茶店／店长孟桃”身份及必要演示状态；无新订单、售价、收益、属性、好感等经营信息。组件、图标、状态尽量维护同一源，独立样例和组合/主体入口复用。第 6 项对话界面只演示孟桃与玩家的一轮文字交流、阅读与关闭，不增加选项分支、语音、任务、奖励或持久记录。示例占位文案可以是：

> 【演示文案，非正式剧情】孟桃：你好，欢迎来看看奶茶店。
>
> 【演示文案，非玩家设定】玩家：好的，我先四处看看。

实际交付时示例标记须在 UI 样张/评审材料中可见，运行样例至少让审阅者知道内容是演示；正式写作仍另行审批。姓名、杯子标识、牌匾、美术字体、系统字体均按项目版权与许可规则核验。直接修改既有字体外形不能代替授权。

### 3.6 组合场景与遮挡

第 7 项从第 1 项**同一背景底板和镜头行为**开始。操作者可按任意顺序动态添加和移除第 2、3、4 项的对象；可见对象使用各单元同一源资产、动画状态、UI/VFX资源及定义，不能导出“组合专用扁平图”或复制一套行为。至少能分别观察顾客经过店铺前沿、孟桃与前柜、幽灵靠近/坐在板凳、树/灯/花与前后景、桥或栏杆交界等遮挡。允许用测试位置控制辅助观察，但不把它定义为主体游戏自由摆放玩法。

对象开关独立；若关闭坐姿依赖的板凳，坐姿必须安全退出或切到不依赖板凳的状态，不能悬空。移除店铺或孟桃后，共用身份卡不得继续误称画面中同时存在二者。移除对象时连带清除该对象的未结束动画/特效；重置恢复统一的空底板与初始镜头。组合入口如展示第 6 项对话，仅作可关闭浮层，不改变场景对象的状态或世界规则。

## 4. 资源、复用及出图门禁

**单元实际运行输出就是未来主体游戏可复用的最终正式资源和功能**：独立入口、组合入口与未来主体必须引用同一已批准视觉源、正式导出、对象状态逻辑、可共用 UI/VFX 与资源版本；不能制作只供演示的一套视觉资源，再为主体重绘。Lab 的菜单按钮和诊断控制可以只在 Lab。单元阶段每项“完成”须有原创可编辑母版、来源与许可、正式 Creator 资源/稳定引用、运行画面、目标设备及独立/组合双入口一致性证据；主体尚未接入时，以稳定资源身份、依赖契约和正式工程可复用性验收本阶段，主体实际引用同一资源 ID/版本列为后续接入复验，不得声称三入口已实测。概念图、审阅 SVG、旧 Demo 图片/Prefab/程序形体及一次性占位图都不能充作最终交付。

孟桃、店铺动态部件及选定动态场景元素仍按骨骼动画制作，**每个骨骼对象**的所有图像附件各落在一张贴图/图集中。幽灵是明确例外，不做骨骼，也不套用“骨骼对象一页”；它的透明序列帧如何共用图集、材质及实际页数由 Art/Tech 按帧尺寸、透明边、合批和设备测量共同签认，不由 Product 硬定一页。单页不等于一 Draw Call，帧数少也不自动保证合批或性能。

**每一次正式出图前**，Art 与 Tech Lead 共同检查并记录参考版权、原始尺寸、左右朝向/五状态清单、幽灵每动作的帧图和循环缝/过渡/保持帧、翻转可用性及非镜像 UI、透明边、图集面积及留白、贴图内存与预期批次；其他骨骼对象另核分件包围盒与单页。未经联合确认的资源不得标为可集成正式资产。新顾客帧图、三类场景元素、对话 UI 均须各自资产清单和签认，不能沿用孟桃 v0.5 概念出图预检代替。

同一正式资源应同时服务独立单元、组合入口和未来主体游戏，支持分别打磨而不产生两套外观/状态逻辑。具体 Creator 项目数、Prefab/Scene、资源 ID 与升级路径由 Tech Lead 审批。UI 复用组件/图标/状态资源；图片和系统/美术字体在生产前分别核验来源、商业使用、嵌入、分发、修改许可与相似性，来源不明不得集成。

## 5. 平台、异常与未决事项

镜头操作、顾客左右序列帧、其他对象骨骼动画、图集及 UI 必须在计划发布的目标设备上可读且可控。当前 Creator 项目存在竖屏 720×1280 设置，而参考街景是横向长画幅；镜头裁切、拖拽边界、牌匾/腰牌/对话小字和板凳坐姿需做真机或目标环境取证。本 PRD 不单方面决定横竖屏切换、具体视野倍率、帧率、图集页数、坐标数值、性能阈值或编辑器/Spine 制作工具版本。

缺正式资源、未通过许可、骨骼作者工具与版本不匹配、幽灵帧图循环跳变/透明边错误、图集或显存超限、左右翻转/坐姿无法合理呈现、真机画面不可读时，相关项不得以占位图或 Web 单端截图充作完成。未来主体接入时若不能引用同一资源 ID/版本，接入复验不得通过，须修正接入而非重做一套。若约 4–6 帧预算不能达成自然循环或状态辨识，由 Art/Tech 提出审阅方案并经用户批准后调整，不静默增加大量帧或改回骨骼。其他问题明确标记阻塞/未测，交相应专业修订。未来新店/店长/顾客、完整经营和故事对白另立范围。

## 6. 阶段和审批

Product 本版与 [验收条件](ACCEPTANCE.md)、[操作流程](FLOW.md)、[变更影响](CHANGE_IMPACT.md) 同版提交。Tech、Art、UI、VFX、Client、QA 对此 Draft 做**影响评审**，不代表其正式下游制作获准。Master 审阅并呈用户；Producer 记录本版 `USER_APPROVED` 后，受影响的专业规格须逐阶段修订、评审并分别获用户批准，之后才能制作正式序列帧/骨骼、接入 Creator 并由 QA 验证。v0.1 的旧顾客骨骼语句仅作历史，不再作为生产输入。
