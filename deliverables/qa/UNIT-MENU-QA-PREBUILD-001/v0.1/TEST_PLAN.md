## 1. 本轮批准的范围与执行门禁

本计划与 Client `FEATURE_BRIEF.md` 一起组成**编码前开工包**；两份均经专业评审、用户明确批准后，才进入正式客户端编码。正式图片或字体另需逐批 Art/Tech 出图前签认、生产资源审批；文档审批不等于运行通过。Client 实现、实施报告及其审批完成后，QA 对具体构建执行 `FUNCTIONAL`，产出 `TEST_REPORT.md`、原始证据与缺陷闭环。需要发布候选时另立 `RELEASE` 范围和平台/真机/实际弱网矩阵；本计划不授予发布结论。

执行顺序：①核已批准输入与正式资产清单；②固定 Creator 构建、环境和源资源版本；③跑功能、状态、边界、快速切换与关联回归；④按固定视口做 Visual QA；⑤按获批预算做适用性能实测；⑥汇总 PASS/FAIL/NOT_TESTED、P0/P1/P2、专业 Review；⑦用户确认 `TEST_REPORT`。缺源、缺许可、缺构建、缺环境或缺阈值时对应项为 `NOT_TESTED/BLOCKED`，不可由旧 Demo 或截图推断通过。

## 3. 幽灵十格与动画专项

单方向原创透明帧的 `move`、`run` 分别以约 4–6 帧为制作预算起点，核 **末帧→首帧**连续性、每帧体量/统一原点/脚点、alpha 边、姿态差、位移速度和可读性；这不是五态总帧数上限，也不为情绪与坐姿强制等长循环。`happy`、`sad` 可一次动作加保持；`sit` 须有接近、进座、稳坐、离座/复位。每一朝向独立取移动、跑动、高兴、沮丧、坐姿五格，共十格；每向连续跑“移动→跑动→高兴→沮丧→进座→稳坐→离座→重置”。另测中途转向、快速切态、坐姿转向、板凳移除、返回重进、世界位移与阴影/座点不随 `VisualRoot` 镜像。字形/Logo 不反读，非对称附件及手势需 Art 目视确认。旧两帧 Demo、旧概念板、骨骼替代和第二方向绘件均不可充数。

## 4. 平台、性能和环境冻结

现工程为 Creator 3.8.8、设计画布候选 `720×1280`，横向长街与竖屏裁切存在风险；这不是最终发布平台或设备清单。Tech/Product/Client 在实际执行前须锁 Web 功能环境及拟发布微信/抖音等平台范围、至少一台可重复接触的代表设备与低端机候选（厂商、型号、芯片、RAM、OS、刷新率、DPR、屏幕比例和安全区），并确认是否纳入本次 `FUNCTIONAL` 的目标设备实测和之后 `RELEASE` 专项。设备尚未指定时记录“待定”，不把桌面 Web、模拟器或开发工具的通过外推为真机通过。

每条原始证据记录：构建 commit/hash、Creator 精确版、素材版本/hash、Prefab/资源 UUID、平台与运行容器、设备档案、视口/DPR/安全区、渲染后端、实际贴图压缩及回退格式、冷热进入、镜头中心/倍率、同时对象/动作/VFX/UI、采样时长。覆盖负载 A 空底板、B 加店光影、C 加孟桃/幽灵/凳、D 加全动态场景与 UI、E 逐项移除/重进；多轮记录 FPS、p50/p95/p99 帧时、DrawCall 平均/峰值、纹理页数/尺寸/实际格式及可核 GPU 内存估算、JS/资源缓存和加载峰值、输入延迟/卡顿与回收。PNG 文件大小不能代替纹理占用；同图集不能推导为一个 DrawCall。`project/quality/PERFORMANCE_BUDGET.md` 仍是旧 Demo v0.1 候选，**不可直接用作七菜单硬阈值**；Tech Lead、Product、Client、QA 应在目标设备和正式资源确定后将本功能阈值、采样轮次、可接受降级写入获批预算/补充计划，然后才做数值 PASS 判定。必要性能未测不得整体通过。

## 5. Visual QA 和质量判定

固定相机、视口、DPR、语言、字体文件、目标设备、对象位置、动作触发和可控随机项；截图与短录屏注明批准规格版本、实际构建与资源哈希。店灯分常态/亮峰/回落，同时观察灯罩、邻近墙柜受光及地面暗影；树花灯各自开关；角色两向十格；桥/栏杆/前柜/凳的局部遮挡；UI 的 normal/pressed/selected/disabled/loading/error；对话两句和焦点恢复。差异图与截图是发现偏差的证据，最终观感由 Art/UI/VFX 按批准规格评审。重大视觉偏差的 P1 边界仍以用户/项目最终确认规则为准，不能擅自更改分级。

P0/P1 未关闭时不可通过，P2 如延期须在报告列出。所有测试结论按具体构建与资源版本有效；正式资产、Prefab、图集、字体或构建改变后做影响分析和受影响项重测。
