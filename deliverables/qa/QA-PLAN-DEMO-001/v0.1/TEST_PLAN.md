# 百鬼夜市 Demo｜测试计划

版本：v0.1｜任务：QA-PLAN-DEMO-001｜阶段：`FUNCTIONAL`｜规则：`studio-workflow-v2-policy`

## 依据与目标

本计划用于正式编码前审定验证范围。功能以已批准的 `deliverables/product/DEMO-001/v0.1/DEMO_PRODUCT_SPEC.md` 为准；地图、状态和性能方法参考已批准的 `deliverables/tech_lead/TECH-DEMO-001/v0.2/TECH_DESIGN.md`；视觉与交互参考已批准的 `deliverables/art/ART-DEMO-001/v0.1/ART_DIRECTION.md`、`deliverables/art/ART-ASSET-DEMO-001/v0.2/ASSET_MANIFEST.md` 和 `deliverables/ui/UI-DEMO-001/v0.1/UI_SPEC.md`。批准状态见 `project/APPROVAL_LOG.md`。

目标是验证一张可拖拽缩放的竖屏夜市、唯一摊位一次性修复及单名店长、顾客从奈何桥经夜市到右下离场桥的连续路线，以及最简 UI。测试结果在实现完成后另行出具；本计划不表示任何用例已执行。

## 验证范围

1. **功能与交互（本地 Web）**：初始竖屏视野、地图边界、单指拖拽、双指缩放及缩放后的拖拽/点击；地图点击与手势、UI 输入优先级；关闭、确认、连续点击、再次点击、重启初态；背景摊位不可修复。
2. **顾客路线（本地 Web）**：持续生成至少两名顾客，逐个从左上奈何桥进入、沿石路穿过夜市、越过右下桥离开；镜头移动和修复前后保持世界路线；不穿建筑、水面，不在画面内突然消失。检查桥栏、屋檐等前景遮挡顺序。
3. **视觉与 UI**：在固定视口、DPR 和相同镜头位置截取破败/修复后同构图、按钮状态和安全区；记录一段不中断的入口→经过→出口及修复流程录屏。对照已批准 Art/UI 文件做结构、状态和风格判断；概念图不作为逐像素通过标准。截图差异只用于发现偏差，结论需 Art/UI 专业复核。
4. **性能适用性**：本 Demo 的大地图、透明地标和持续移动角色使帧率、帧时间、draw call、纹理内存、活跃角色数及加载耗时均适用。先在 Web 记录功能性能，再用目标手机实测 60 FPS 目标。初态与修复后、缩放两端、持续客流和边拖拽边运行分别采样；同机、同构图、同负载至少重复三次，保留原始采样和明显卡顿时间点。具体判定阈值待批准预算确定，缺失时性能记 `NOT_TESTED/BLOCKED`。

## 证据与报告

执行时将截图、连续录屏、控制台日志、性能采样放入版本化 QA 证据目录，并在 `TEST_REPORT.md` 登记：用例 ID、输入 Artifact 版本、构建哈希、环境/设备、视口与 DPR、步骤和时间、结果、证据路径、缺陷 ID。视觉证据记录所对照的 Art/UI 版本、差异、严重度和专业 Review 结论。功能、视觉、性能分别给出 PASS/FAIL/NOT_TESTED，不把 Web 结果替代目标手机结果。P0/P1 阻塞，P2 明示。测试报告与缺陷提交后按审批流程处理。

## 不测试范围

本 Demo 无服务端、网络、账号、经济、资源消耗、订单、广告、社交、永久存档和付费，因此不设 Server 用例，也不测这些系统。此阶段不覆盖广泛机型/平台发布兼容性和实际弱网专项；正式发布需另立 `RELEASE` 范围。灯光、水面、树叶等高级动态效果也未纳入本 Demo 产品验收。
