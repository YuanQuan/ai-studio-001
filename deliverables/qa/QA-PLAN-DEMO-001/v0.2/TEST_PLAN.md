## 依据与目标

功能依据为已批准的 `deliverables/product/DEMO-001/v0.1/DEMO_PRODUCT_SPEC.md`；技术依据为已批准的 `deliverables/tech_lead/TECH-DEMO-001/v0.2/TECH_DESIGN.md`；视觉依据为已批准的 `deliverables/art/ART-DEMO-001/v0.1/ART_DIRECTION.md`、`deliverables/art/ART-ASSET-DEMO-001/v0.2/ASSET_MANIFEST.md`、`deliverables/ui/UI-DEMO-001/v0.1/UI_SPEC.md`。批准状态见 `project/APPROVAL_LOG.md`。性能测量口径引用待审批的 `project/quality/PERFORMANCE_BUDGET.md v0.1`，预算获批前其中数值仅为候选优化目标，不能作为 QA 硬性通过标准。未批准的 PRODUCT-001 概要不作为本任务依据。

目标是验证一张可拖拽缩放的竖屏夜市、唯一摊位一次修复及单名店长、顾客从奈何桥经夜市到右下离场桥的连续路线，以及最简 UI。本计划不表示用例已经执行。

## 验证范围

本地 Web 功能验证包括初始视野、边界、单指拖拽、双指缩放及手势冲突；关闭、修复、连点、背景摊位不可修复、重启初态；至少两名顾客依次从左上奈何桥沿石路穿过夜市，越过右下桥离开，镜头移动时路径持续。桥栏、屋檐、摊位和水岸处检查脚点与遮挡，不允许穿越建筑/水面或画面内消失。

Visual QA 在固定视口、DPR、镜头位置和同一状态下截取破败/修复后、按钮状态、安全区截图，并保留修复流程和顾客完整路线连续录屏。对照已批准 Art/UI 版本检查结构、状态、风格；概念图不逐像素比对，自动差异只辅助发现问题，最终由 Art/UI 专业复核。

## 性能测量

本 Demo 的大地图、透明地标和持续移动角色使帧率、帧时间、DrawCall、纹理内存、活跃顾客数及加载耗时均适用。功能阶段在本地 Web 记录诊断数据；目标手机 60 FPS 必须真机实测。手机环境未确定或不可用时标 `NOT_TESTED`，Web 数据不能替代。

按性能预算 v0.1 的场景分别测：初态默认镜头、修复后默认镜头、最近/最远倍率、持续客流达到 Client 预先锁定的正常活跃上限、持续客流同时拖拽/缩放。每个场景等待资源加载并稳定后连续采样 **60 秒，同条件重复 3 次**；操作场景保留 60 秒手势录屏。每轮记录平均 FPS、帧时间 p50/p95/p99、>33.3 ms 和 >50 ms 帧数及时间点、DrawCall 平均/峰值、纹理内存估计来源和局限、顾客峰值。首次进入冷缓存与二次进入热缓存的加载耗时分开各重复 3 次，从场景请求到目标摊位、道路、桥和 UI 齐备且首帧可操作。保留原始时间序列/导出数据，注明工具来源与精度；不得把 JS 堆内存当作 GPU 纹理内存。

预算中平均 FPS ≥55、p95 ≤20 ms、冷启动 >5 秒等为当前候选优化或观察目标。预算获批后按其判定性质报告“达到/未达目标”和原因；不得将候选数值静默转成产品硬性通过门槛。可复现卡死、输入无响应或路径跳变按功能缺陷处理。若进行降级，仍要检查地图、镜头、修复店长和至少一名完整顾客路线。

## 证据与报告

执行时将截图、连续录屏、控制台日志和性能原始采样放入版本化 QA 证据目录，在 `TEST_REPORT.md` 登记用例 ID、输入 Artifact 版本、构建哈希、环境/设备、视口与 DPR、步骤和时间、结果、证据路径、缺陷 ID。视觉证据记录参考版本、差异、严重度和专业 Review 结论。功能、视觉、Web 性能和手机性能分别给出 PASS/FAIL/NOT_TESTED，不汇总未测为通过。P0/P1 阻塞；P2 明示。

## 不测试范围与门禁

本 Demo 无服务端、网络、账号、经济、资源消耗、订单、广告、社交、永久存档和付费，因此不设 Server 用例，也不测这些系统。本阶段不覆盖广泛机型/平台发布兼容性或实际弱网专项；正式发布需另立 `RELEASE` 范围。灯光、水面和树叶等高级动态效果不在本 Demo 验收内。

本计划须与 Client 的 `FEATURE_BRIEF.md` 一起完成专业评审和用户审批，再进入正式编码。实现及报告获相应审批后才执行正式 QA；缺少环境、设备或已批准预算时可执行不受影响的部分，并将其余项目标为未测或阻塞。
