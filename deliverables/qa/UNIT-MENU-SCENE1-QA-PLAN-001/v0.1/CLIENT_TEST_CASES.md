# 单元示例1客户端测试用例 v0.1

范围：未来在获批的 Web 浏览器及多模拟手机竖屏矩阵中验证四层 Creator 场景。以下均为**待执行用例**，当前状态 `NOT_TESTED`。测试前置条件包括 Client Feature Brief 与 QA Test Plan 获用户批准、实际工程接入完成、Web 矩阵和性能预算获批。输入以 `UNIT-MENU-SCENE1-SCOPE-001 v0.1/ACCEPTANCE.md` S01–S09、Gate2 v0.3、Tech Runtime v0.2 为准。

## 通用执行记录字段

每次执行须填写：用例 ID、日期、构建 commit/hash、Creator 版本、浏览器/版本、OS、Web 渲染后端、模拟视口/DPR、安全区假设、输入模拟方式、测试者、结果、缺陷 ID、截图/录屏/日志路径。资源相关步骤还须记录稳定 ID、美术源完整相对路径与 SHA-256、Creator 实际相对路径与 SHA-256、导入 `.meta` image/Texture2D/SpriteFrame UUID、Prefab UUID、Scene 实例及登记表版本。当前登记表中计划路径状态为 `PLANNED_NOT_IMPORTED`；没有真实工程工件时该项不能填实际 UUID 或声称导入通过。

## 运行证据和未测规则

- 每项保留原始日志/状态数据及必要截图或录屏；文件名包含用例 ID、矩阵配置 ID、构建短 hash 和序号。
- Web 截图须能辨识逻辑视口与 DPR；模拟设备模式和输入来源须标明。DevTools 名称不是实体机证据。
- 第4/7项条件只定义未来接口；没有独立获批 Artifact 和对应实现时只保留 `NOT_TESTED`。
- 测试预算未批准时不得按自选阈值判性能通过；测试环境缺失则记 `BLOCKED`，没执行记 `NOT_TESTED`。
- 实体手机、微信/抖音容器、发布平台、实际弱网和服务端均不在本计划范围。
