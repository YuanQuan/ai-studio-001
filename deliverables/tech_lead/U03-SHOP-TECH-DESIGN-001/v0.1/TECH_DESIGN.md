# U03 六店单店切换技术规格 v0.1

任务：`U03-SHOP-TECH-DESIGN-001`。输入：已获用户批准的 `U03-SHOP-SCOPE-001 v0.1`、`U03-SHOP-ART-PLAN-001 v0.1`，项目决定 `DEC-U03-SHOP-008`、`project/ART_GUIDE.md` 第 6 条，以及已批的 `UNIT-MENU-TECH-DESIGN-001 v0.2` 同源原则。本稿为待评审技术提案；没有 U03 正式图、Prefab、构建或运行结果。

## 1. 工程现状和范围

当前工程为 Cocos Creator 3.8.8，`settings/v2/packages/project.json` 与 `UnitSampleGallery.ts` 都使用 `720×1280` 设计分辨率和适宽布局。仓库当前 `UnitSampleGallery.ts` 菜单仅有 U01 入口；`UnitSamples.scene` 是该入口场景。正式 U01 四层背景 Prefab 和纹理已存在。本任务不改这些工程文件，不把正在规划的 U02 当成已上线入口。U03 的菜单整合要在 Client 获批开工包中依据**实施当时**已批准的 U01/U02/U03 范围处理。

U03 是六店正式资源的单店查看入口。店面本体资源、牌匾和允许的静态灯光属于同一店身份；Lab 专有的是导航、控制条、错误消息和展示位置。正式六店 Prefab 与贴图仅一套，未来主体游戏复用同一资源身份和版本。U03 不建立可运行的平行演示店图，不包含经营、人物、动画、VFX、翻新或主街横向浏览。旧七菜单第 2 项奶茶动态历史范围保持独立，不由 U03 静态预览宣称完成。

## 2. 对象结构与依赖

推荐沿用当前单 Cocos 工程：`units/shops/<正式店对象>/textures/` 与 `prefabs/` 放六家店正式资产，`labs/menu/` 只放 U03 页面和控制组件。各店一个顶层 Prefab，含 `rear`、`body`、`interior`、`sign`、`light`、`front`、`ground_contact` 中实际需要的静态节点；不强制每层一贴图。六店差异包括形制、材质、牌匾和陈设，不能把同一横匾仅换位置。公共底景仅在 Art 与切图方案批准采用时作为独立对象，且不可包含相邻店或地标。

`ShopDefinition` 为实施期本地只读索引：稳定 ID、产品顺序、界面显示名、唯一 Prefab 引用、对应资源登记版本。它不定义商店玩法或网络字段。标签文字来自已批 Product/UI 语义；牌匾画面来自同一店 Prefab，不在页面层另拼错位字牌。切换执行用六项索引，不靠文件名排序或节点名猜身份。候选稳定身份与旧 `MT_SHOP_01` 映射详见 `RESOURCE_ID_AND_HANDOFF.md`；这些是待同版用户批准的契约提案，不能自行把旧 Prefab 重命名或复用未知 UUID。

## 3. 状态机与原子切换

状态为 `CLOSED → LOADING(01) → READY(01..06)`，切换中为 `LOADING(target)`，故障为 `ERROR(target, reason)`。首次进入与每次返回再入均请求 01 奶茶；没有本地持久化。UI 决定前后控件外观，技术层对 `previous/next` 应用 `(index ± 1 + 6) % 6`；若 UI 采用经批准的直接选择，同样只接收 01–06。边界 01 前一项到 06，06 后一项到 01。

维护 `presentedIndex`（当前真实可见店）与 `desiredIndex`（最新待呈现目标）两个值。进入时 `desiredIndex=01`，`presentedIndex=null`，首次成功提交后才变为 01；已呈现店的名称栏始终读取 `presentedIndex`，切换提示才读取 `desiredIndex`。加载中 `previous/next` 从 **`desiredIndex`** 递推，而不是从仍可见的 `presentedIndex` 重算：01 可见时连续两次 `next` 为 02→03；一次 `next` 随即一次 `previous` 为 02→01。前后均按六项取模循环。若新 `desiredIndex == presentedIndex`，立即令旧请求代次失效并取消待加载，保持原店一间及其身份栏，不重建同一店；首次 01 尚未可见时前后控件禁用。

每次有效目标变更递增请求序号 `generation`，只有最新一代加载结果允许提交。若目标 Prefab 已在内存，可同步准备；若异步加载，先保留**一个**当前店并给目标加载态，不能显示半套目标牌匾或双店。加载成功后在一个提交点：实例化完整目标店、绑定同一 `ShopDefinition` 的名称和序号、停用并移除旧店、激活新店，再把 `presentedIndex` 与 `desiredIndex` 设为目标并更新身份栏。渲染提交过程中不可暴露同时可见两店；可用非活动准备节点和同一帧的先隐藏旧、再激活新。牌匾是 Prefab 子节点，连同店体整体替换；阴影、接地和可选静态灯光按店清理，公共底景除外。连续快切以**最后一次有效目标**为准；较早回调在令牌不匹配时丢弃且释放其临时实例/句柄。

目标资源缺失、加载失败或结构/身份校验失败时，转 `ERROR`：保留上一间有效店并显示清楚的 `failedTarget` 与重试入口，或在首入无旧店时显示明确空态；绝不拿另一店冒充目标，也不将错误项显示为已完成。失败时使该代请求失效；若有已呈现店，将 `desiredIndex` 复位为 `presentedIndex` 作为后续前后键的递推基准，重试按钮仍单独请求 `failedTarget`。重复选择当前店不重建、不叠加。离开 U03 时令牌失效，取消监听/回调、销毁页面店实例，依实际 Creator 引用管理释放仅本页持有的资源；正式共享缓存由 Client 依使用场景决定，不能释放主体仍使用的同源资产。重进从 01 建立新会话，旧回调无权写入。

## 4. UI、镜头与层序契约

U03 只显示一间店及一份名称/序号状态。单店容器、控制和返回安全区由 UI 同版规格确定；技术层提供当前 ID、状态和错误目标。店体保持六店共用的投影地线和缩放规则，但不将伞车或开架硬拉宽成瓦房。预览不允许裁掉屋檐牌匾、轮廓和接地影；短视口或安全区冲突时先调整布局/适配并复核牌匾可读，不自动缩到不可读，也不改已批 PSD 外观。

由后向前建议：可选低对比公共底景 → 店后层 → 主体/室内 → 牌匾挂件对应深度 → 店前遮挡 → 接地影/静态灯光按实际合成关系 → Lab 控制。正式层序以各店 PSD 重组和 Art/Tech/Client 切图协作记录为准。控件不得遮牌匾、壶口或主要营业线索。01 与 04 屋顶连续瓦线必须可见，不以运行时遮盖块删除大杯/大剪刀。

## 5. 不扩展接口与后续门禁

本方案无 Server/API/经济配置变更，也不引入第三方运行依赖。规格获批仅成为 Client Brief 的技术输入。首图前来源权利和字体/字稿来源须解除停止条件，并由 Art/Tech 对同批画布、PSD、层/脚点、裁切与预算预签；正式图/切片 Gate2 获用户批准后才能进入 Client 正式导入。UI 本版也须独立审批，Client 实现报告、QA 测试计划与报告仍按流程分别审。实际 Creator CLI 构建、本地 HTTP 与内置浏览器检查、目标视口和适用平台测量留给后续实现/QA，当前均为 `NOT_TESTED`。
