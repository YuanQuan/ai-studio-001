# 百鬼夜市核心场景 Demo｜技术设计

版本：v0.1｜任务：TECH-DEMO-001｜输入：已获用户批准的 `deliverables/product/DEMO-001/v0.1/DEMO_PRODUCT_SPEC.md`。本稿供专业评审与用户审批，尚非客户端实施授权。

## 1. 目标与范围

在 Cocos Creator 3.8.8 + TypeScript 中实现一张竖屏 2.5D 夜市地图：可拖拽缩放的正交相机、一处一次性修复摊位、一名随修复出现的店长、从左上奈何桥经石路到右下桥的循环顾客流，以及修复所需的最简 UI。两张视觉参考图只确定构图和前后气质，不把图上的资源栏、导航按钮当成功能。Demo 运行数据只存内存，重新进入场景回到破败初态；不调用服务器、账号、经济、存档或正式顾客配置。

## 2. 场景与模块边界

```text
DemoScene
├─ WorldRoot                 地图固定层、桥、水域、道路、背景破败摊位
│  ├─ WalkwayRoot             路径地标与路径点（编辑器中标定）
│  ├─ TargetStall             RuinedVisual / RestoredVisual / HitArea / StaffAnchor
│  └─ ActorsRoot              顾客池、店长
├─ WorldCamera               仅拍摄地图与角色；不拍摄屏幕 UI
└─ ScreenCanvas              修复提示、确认/关闭、完成提示
```

| 模块 | 责任 | 依赖方向与输出 |
|---|---|---|
| `DemoSession` | 持有本轮唯一摊位状态；接收 `repair()` 命令并只发一次状态变化事件 | 不依赖节点或 UI；对外提供 `RUINED/RESTORED` 快照 |
| `CameraController` | 拖拽、缩放、可视边界钳制 | 读取 `MapBounds`；不写摊位和顾客状态 |
| `GestureRouter` | 统一识别单指拖动、双指缩放、点击候选；管理 UI 消耗 | 将确认过的地图点击传给命中模块；不包含修复规则 |
| `StallPresenter` | 根据状态切换破败/营业视觉、提示与店长锚点 | 订阅 `DemoSession`；不自行修改状态 |
| `StallHitTest` | 将屏幕点经相机转换到地图坐标，仅命中目标摊位的明确区域 | 向 UI 发“打开修复面板”意图；背景摊位没有命中逻辑 |
| `CustomerFlow` | 固定路径点、生成节奏、池化移动与出口回收 | 使用地图坐标，不依赖相机或修复状态 |
| `DemoUI` | 展示修复入口、确认、关闭和完成提示；发送修复命令 | 不直接切换场景节点或生成店长 |

`DemoSession` 是本 Demo 的单一运行事实源。一次 `repair()` 只有 `RUINED→RESTORED` 会返回成功并发事件；已修复返回已完成，不触发第二次生成。`StallPresenter` 以“确保已有一名店长”的方式响应状态，避免重复订阅或快速点击造成多个实例。关闭确认面板只关闭 UI，不改变摊位状态。启动时显示破败视觉、隐藏营业视觉与店长；不读取正式项目存档。

## 3. 地图坐标、相机与手势

地图、路径点、目标摊位与角色使用同一世界坐标系；入口和出口是地图中的锚点，不按当前屏幕像素判断。美术资产按前后图相同的地标和透视组织，目标摊位两套表现对齐同一锚点。地图可拆为背景、建筑遮挡、道路与前景装饰层；角色脚底的世界位置用于遮挡顺序。具体分层与资源尺寸由 Art 交付，Client 在场景中标定路径且检查不穿越水面和建筑。

使用正交相机和受限的平移/缩放范围。以地图可显示矩形与视口半宽、半高计算中心位置合法区间；每次平移或缩放后都将中心钳到区间内。当某一缩放级别使视口大于地图，该缩放级别不允许。最远端以完整可用画面仍由地图覆盖为约束，最近端以目标摊位可辨认、可点击且能观察局部通道为约束；具体倍率由实际资产与竖屏设备安全区标定。相机边界采用场景可显示区域，而非参考图原始像素尺寸；极端长宽比机型需复核两轴覆盖。

`GestureRouter` 记录触点 ID、按下点及移动量：单指超过点击容差才进入拖动；未超过容差且抬起时才发点击；第二触点加入立即取消点击候选并进入缩放。双指以两触点距离变化缩放，以中点保持所指地图位置尽可能稳定；任一手指离开后重新建立单指基准，防止跳动。UI 控件优先消耗触摸，地图手势不穿透面板。拖动和缩放期间不触发摊位点击；镜头移动后用当前相机变换重新命中目标。测试工具可注入双指事件，正式 UI 不增加缩放按钮。

## 4. 摊位修复与店长

状态只有 `RUINED` 和 `RESTORED`。点击 `TargetStall.HitArea` 时，若为 `RUINED` 打开确认面板；若为 `RESTORED` 显示“已修复／店长已到位”。确认按钮调用 `DemoSession.repair()`；若成功，立即切换营业视觉、在 `StaffAnchor` 放置一名店长并显示短提示。重复确认、重复点击或异步视觉回调都不再改变状态。视觉切换失败时不应凭空显示成功；Client 应在本地记录资源缺失并给出可诊断错误，集成测试中作为阻断项。

店长采用一个场景预置节点或单实例 Prefab，初始隐藏／未实例化均可；选择一种方案后由 `StallPresenter` 控制实例存在且可见。店长不参与顾客路线、不承担技能或经营数据。其它背景摊位只作为视觉，不注册 `StallHitTest`。

## 5. 顾客路径与复用

在 `WalkwayRoot` 标定 `Entry`（左上奈何桥）、若干石路转折点、主要夜市区域点和 `Exit`（右下桥）。每名顾客从 Entry 出生，沿顺序路径点平滑移动，达到 Exit 后继续越过桥的地图可见边界再回收到对象池，避免屏幕内凭空消失。路径点保持世界坐标；相机操作只改变投影，不改角色位置。通过路径段朝向选择行走方向及动画；资源不足时至少保持行走状态可辨识。

生成器从少量外观 Prefab 池取实例。入池必须清理路径索引、位置、动画、透明度和调度状态；出池重新初始化，避免复用后瞬移或残留状态。用可调本地 Demo 参数控制生成间隔、移动速度和活跃对象上限；这些参数仅供演示与性能调试，不进入正式游戏经济或顾客配置。可持续观察至少两名顾客依次完成路线。路径固定，不引入导航网格、动态寻路或复杂避让；可采用轻微出生错时／路径内偏移避免完全重叠，但不能走离石路或改变地标。离屏顾客仍须沿路径前进，不能因相机移走而暂停后回到画面时跳段。

## 6. 资源组织与性能验证

建议将场景地图、两种摊位状态、店长、顾客动画及最简 UI 分组；相同材质与尺寸适合的静态元素合图集，避免把整张大地图做成一张高分辨率不可控纹理。层级和遮挡需兼顾合批，减少透明层过度叠加；水面、灯光以贴图/轻量动画表现，不做真实全局光照或流体模拟。可见地图分块或裁剪是地图较大且测得开销后才实施的优化，不预先加入复杂流送系统。

按产品规格，将主流中高端手机的竖屏运行 60 FPS 作为验证目标，而非所有机型承诺。Client 在本地 Web 开发环境先打通功能，再在目标移动设备记录稳定帧率、帧时间、draw call、纹理内存、活跃角色数和加载耗时；分别覆盖初始/修复后、相机两端缩放、持续顾客生成与拖拽。以同一设备、同一场景位置重复采样，报告平均与明显卡顿点。实际同屏对象上限、图集大小、更新频率由测量结果定稿；动态角色才逐帧更新位置，静态装饰不挂逐帧脚本。性能不足时依次减少装饰动画与粒子、降低顾客同屏上限/生成密度、压缩远景资源或降低远处动画频率；保留完整地图、可操作相机、一次修复、可见店长和至少一名完整顾客路线。任何降级不得让顾客在画面中突兀消失或使目标不可辨认。

## 7. Client 与 QA 的具体输入

Client 开工前需取得：已批准的本技术设计、Art 的生产资产与场景分层/锚点规格、UI 的竖屏安全区和控件状态规格。Client 在 `FEATURE_BRIEF.md` 中锁定实际地图矩形、相机倍率范围、点击容差、路径点坐标、演示参数、目标设备和性能采样方法；不得把这些实现参数提升为正式玩法规则。若 Art 资产尚为概念图，先用占位资产验证结构，正式视觉集成仍须通过视觉 Artifact 门禁。

QA 应覆盖：初始画面地标与边界、双指缩放和拖拽后点摊位、关闭面板不修复、快速重复确认与再次点击仅一店长、其它摊位无入口、顾客进入/经过/离开完整连续录屏、镜头移动中路径固定、重启回破败。性能报告注明设备型号、系统、构建、场景条件及上述测量指标；低性能模式按相同产品验收检查。正式 QA 执行范围以之后批准的 `TEST_PLAN.md` 为准。

## 8. 风险与变更边界

- 概念图含完整资源栏与大量摊位，但产品只批准一个可修复目标和最简 UI；资产拆分时须避免误纳入演示外系统。
- 2.5D 绘制顺序与高分辨率场景可能增加透明绘制、内存与加载成本；以生产资产导入后的设备采样决定优化幅度。
- 入口/出口与中途石路若未按实际美术地标标定，会导致穿越建筑或水面；路径点和遮挡须在真实场景联合检查。
- 本设计不改变 `project/ARCHITECTURE.md` 的项目级基线。单机 Demo 是任务限定的验证切片，不推导正式游戏的权威或部署模式。若正式产品范围变化，重新评审相关技术设计。
