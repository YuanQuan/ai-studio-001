# 七项菜单镜头、图集与真机性能取证计划 v0.1

日期：2026-10-02。本文件定义测法与放行门禁，不宣称已达到帧率、DrawCall、内存或文字可读性目标。当前无可运行的新七项工程、骨骼导出、正式分层底板与目标机日志；所有运行结果为 `NOT_TESTED`。具体目标设备列表和硬阈值须由后续获批性能/QA规格确定，不拿旧九项压测或概念图推导。

## 1. 测试构建与环境

每条记录固定：Creator精确版本、构建提交/资源哈希、Web/微信/抖音平台与真机设备型号、OS、DPR、屏幕物理/逻辑像素、安全区、纹理压缩格式与实际回退格式、是否冷启动、画面相机中心/缩放、同时可见对象ID/状态、是否开特效。Web先排功能和资源引用；微信与抖音需在各自真实目标手机上复测导入、动画、alpha边缘、输入、加载和性能；开发工具不能代替真机。尚未选定机型时记录 `待定`，不可写 `PASS`。

## 2. 镜头与交互矩阵

| 场景/比例 | 需要执行的操作 | 通过证据 |
|---|---|---|
| 入口1 720×1280设计比例 | 初值、水平拖到两端、缩到最小/放到最大、恢复初值；鼠标拖轮与触控拖/双指各试 | 视频和四角截图；背景无空白，桥/河/路连接，镜头边界不抖 |
| 入口1 多台目标机宽高比/安全区 | 重复以上，UI交互时拖动/缩放不穿透至场景 | 手机截图和指针日志；牌匾预留范围与UI安全区不冲突 |
| 入口7 相同底板/相机 | 动态加入店、孟桃、顾客、板凳、树花灯；同样水平拖与缩放 | 与入口1相机参数和底板UUID一致；近/远位置可读，无遮挡误判 |
| 入口3B/7 座姿与遮挡 | 左右各做移动、跑、情绪、入座/稳坐/离座，走过桥、栏杆、店前柜、树/灯附近；移除板凳或切入口 | 10格+过渡录屏；脚点、座点、碰撞/点击区域、光影与前后顺序正确，无残留 |

正交相机需按实际视口和缩放重算半宽/半高与合法世界边界；当竖屏可见范围超出横幅底板可绘区域时，调整正式分层画布覆盖或合法缩放区间，重新由Art/产品复核。不能仅设 `fitWidth/fitHeight` 就视为适配；不能直接把2172×724概念合图拉伸成竖屏底板。初始倍率、最小/最大倍率、平移端点、实际屏幕字体大小和点击面积在第一次 Creator+手机试验后提交数值建议，获批前不锁本版数值。

## 3. 分阶段负载、测量与回落

| 阶段 | 同时可见对象和动作 | 测量重点 |
|---|---|---|
| A | 入口1空底板、相机拖/缩 | 基线帧时间、背景分层DrawCall、纹理常驻、加载时间 |
| B | A+店静态/店帘/暖光明暗变化 | 店前后插层、半透明光与阴影的批次及过绘 |
| C | B+孟桃 idle→work→idle 与幽灵双向五态/板凳 | 骨骼顶点、混合/裁剪断批、动作切换峰值、座点稳定 |
| D | C+树、花草、灯笼动态全开+UI/对话可选 | 组合峰值DrawCall、GPU/CPU帧时间、alpha过绘、文字清晰度 |
| E | 从D逐一关闭/移除，再重置和重进 | 临时对象、VFX、纹理/骨骼引用与事件监听是否回落；无叠播 |

每阶段同条件至少采多轮稳定区间，并标注采样时长、冷/热缓存、最坏动作帧；保存帧时间p50/p95/p99、FPS、DrawCall、骨骼数量/可见附件、纹理页数、纹理实际格式与可得的GPU内存或估算公式、JS内存/资源缓存、加载峰值与截图。记录Cocos Profiler和设备工具的原始采样，不只写平均FPS。单页图集的基础RGBA8量为512²≈1MiB、1024²≈4MiB、2048²≈16MiB；实际压缩/副本/mipmap/帧缓冲另算。对比同源Prefab修改前后独立入口、组合入口结果；实例覆盖导致两个入口性能或样式不同须修复。

## 4. 性能与质量放行条件

1. Art/Tech正式双签记录和导出图证明每个动态骨骼对象恰为一页，Creator导入日志、Web/微信/抖音构建依赖一致；超一页或使用第二方向图先提变更。
2. 在目标机实际纹理格式下，翻转两向无白边、非镜像字/挂件不反，店光影与角色世界受光一致；牌匾、孟桃腰牌“孟”、幽灵朝向及对话字在最近/最远镜头均能辨。
3. 帧时间、DrawCall和内存与后续批准阈值比较；若超限，先定位素材面积/透明过绘/材质断批/同时播放数量/资源生命周期，再由Art/VFX/Tech提出不损失必验动作的减载方案。降低效果不能静默删除左右×五状态、灯光材质变化、独立物件或组合装配。
4. 入口离开或重置后动作、光斑、回调、座点占用和对话焦点全部清除；重进初态稳定。性能数值通过仍不能替代视觉与交互验收。
5. QA按批准设备、阈值和10格矩阵复测并给报告；未选择设备/未完成真机时保持 `NOT_TESTED`。

依赖：正式 Art 分层与骨骼、UI/VFX规格、Client实现及QA测试计划均需各自用户审批。当前仅能完成仓库审计和概念级图集候选，不可用本计划给未完成资产盖“性能通过”。
