## 1. 工程选择与可独立打磨证据

推荐在现有 Creator 3.8.8 **一个物理工程**中建立每类资产的独立 Prefab、资源目录和可直接打开的 Lab Scene。一个对象在独立入口、第 7 项组合入口和未来主体场景中引用同一 `.prefab.meta` UUID、骨骼数据 UUID、UI/VFX 资产 UUID；Lab 只包装控制面板与测试相机。这样可以按背景、店、角色、植被、灯、UI、VFX 并行修改源文件，避免把同一对象复制到数个工程后靠人工同步。每类可单独打开 Scene、单独编辑 Prefab、单独导出与检查依赖，满足用户“尽量独立的 Creator 工程文件”在当前阶段的编辑目标。多物理工程将复制依赖和 UUID，引入同步、版本和许可证维护成本；仅当团队实际需要不同 Creator 版本/独立发布周期/不同仓库权限，或同一工程并行编辑冲突持续发生时，再由 Master 发起架构变更，讨论共享资产 package 或自动导入映射，禁止手拷贝同名文件冒充同源。

## 2. 七项入口、生命周期与旧入口迁移

| 入口 | 装载与初始状态 | 交互/退出条件 |
|---|---|---|
| 1 空底板 | 唯一 `STREET_BASE_01` 与共享相机；店、人、凳、树花灯为零实例 | 水平拖动、缩放、重置相机；不露出未绘区域 |
| 2 店 | 同源店 Prefab；静态店体+独立 `MT_SHOP_MOTION_01` 骨骼帘+光照表现 | 常态→一次可读动效和材质明暗/投影变化→常态；重复触发不叠播 |
| 3A 孟桃 | 同源角色骨骼单实际视角，初始待机 | `idle→char_work→idle`；`char_work` 完成是这一轮唯一完成/复位主条件，帘与VFX可选且不能阻塞；复位清理挂点/效果 |
| 3B 幽灵 | 一个骨骼源，逻辑朝向左/右，初始朝向标明；板凳独立 | 左右各检查移动、跑动、高兴、沮丧、坐姿；动作切换取消旧位移/回调；进座/稳定/离座完整 |
| 4 其他元素 | 树、花草、灯笼各一个独立源；初始开关状态显式记录 | 每类独立开关、预览与重置；关闭时附属光/VFX一并停掉 |
| 5 UI | 仅共用身份组件及Lab外壳 | Lab控制与正式组件隔离，无经营HUD |
| 6 对话 | 共用对话组件，初始关闭 | 仅一轮标记“演示”的孟桃/玩家文字；关闭、重置释放焦点，不保存剧情进度 |
| 7 组合 | 从入口1同一底板与相机初态开始，其余对象零实例 | 任意顺序增删上述 Prefab；同状态与UI/VFX源；重置清空后与入口1一致 |

各 Scene 实现统一 `enter→active→reset/leave`：进入时装载一次源、建立事件订阅和当前项控制；重置先停动画/位移/补间/VFX/回调、清理临时对象和占用的座点，再恢复初始位置、朝向、开关、UI和镜头；离开解除监听并释放实例引用。任何异步完成回调须绑定本次会话标识，返回或切菜单后不再改变新场景。组合场景先添加角色后添加店仍可各自显示；移除店不会销毁孟桃；移除板凳而顾客正坐着时先安全离座或切到不依赖座位的状态，再移除板凳。再次添加从可预测初态开始，不复活旧特效。上述是表现控制，不定义消费/寻路/经营/剧情。

历史场景意图中的祈愿小纸船和蜡烛如在后续获批范围使用，应作为独立河面装饰/光效源与水体关系设计，不烘进本轮可复用空底板；本七项已批准范围没有要求现阶段新增该资产，不将其偷列为第4项必选对象。

旧 `UnitSamples.scene` 和 `UnitSampleGallery.ts` 保留历史但从新七项导航退出；U01–U09 不按编号一对一迁移，不复制其 21 张 `assets/demo` PNG、9 个 Prefab、绘制形体或“伪四方向”资源。迁移顺序：新增目录/独立 Scene→新菜单路由→新源 Prefab 与资源依赖登记→七项逐个接入→独立与组合双入口对照→QA确认旧入口不可误入；每步需要获批专业资产和 Client 开工包。原九项只读存档，删除或改写需另行授权。

## 3. 幽灵一源左右翻转、座姿和遮挡

`UG_GHOST_01` 只有一个原创朝向的 `.spine` 源、对应骨骼导出数据、atlas描述及**一张**PNG页；五类状态从该源制作，不把左、右分别打两页，也不预设十条动画剪辑。`facing ∈ {left,right}` 是逻辑状态；仅 `VisualRoot` 在 X 轴镜像。位置、速度方向、命中区域、碰撞和座点以未翻转世界坐标计算。UI名字/字、图标、特定不能镜像的附件置于非镜像节点并引用同源资产；若手持物、衣纹、手势、挂点或光影在镜像后不合理，优先改原始设计/同源挂点配置。仍需为另一向新增专属绘制附件时，先交显式变更和用户审批，不由工程偷偷加第二套方向。

`BENCH_01` 独立源给出世界座点与前后遮挡片。进入坐姿：停止行走位移→选择合法侧/座点→移到接近点→入座过渡→坐稳；离座：播离座过渡→释放座点→恢复可移动状态。左右两向都须实测接触、腿/凳面重叠与脚点；翻转视觉根不能把世界座点或碰撞一并镜像。若固定板凳布局无法使两向都合理，退回 Art/Tech/产品评审，不删掉任何一格。顾客在坐姿中转向、快速切状态、移除板凳、退出菜单都按统一取消路径清理。

平视场景以明确层级和脚点排序：远景/水与桥背景→后景装饰→店后层/板凳后片→角色及可交互物（按脚点Y或明确遮挡区排序）→店前柜/板凳前片/栏杆前片→局部光与可选VFX→屏幕UI。桥拱、栏杆、水岸不可用整张前景图一刀遮住所有角色；Art需给可拆前后片和脚点/遮挡区。Spine内部slot只保证单骨骼内部顺序，跨Sprite节点的前柜/栏杆必须使用场景节点或经实测的遮罩分片；不把动态角色烘进场景图。光照按世界位置不随视觉根镜像；若同源反转导致不合理明暗，改无方向依赖的原画/分层或同源材质参数，并逐向截图确认。

## 4. 横向场景在竖屏画布的镜头契约

当前工程设计分辨率是 `720×1280` 且 `fitWidth/fitHeight=true`，选定长幅概念图约 `2172×724` 只提供构图与风格；本任务不擅自把游戏改横屏。入口1与7使用同一底板 Prefab、世界边界和相机组件/默认值。2D正交相机的视口宽随屏幕宽高比和缩放变化；每次手势缩放或设备比例变化后重算可见半宽/半高，水平中心限制在`[worldLeft+halfVisibleWidth, worldRight-halfVisibleWidth]`，上下方向锁定或仅在已绘边界内。若可见宽度大于底板宽度，应扩大获批底板覆盖或限制最大缩小倍率，并由Art/产品复核；不能露白，也不能私自把全景拉伸到竖屏。拖动采用世界坐标转换，鼠标拖/轮缩放用于Web，触控拖/双指缩放用于真机；UI或对话获得指针时阻止场景手势。相机初值、缩放上下限、世界边界、牌匾/腰牌字在720×1280及目标机比例下的可读性需由Client实测后锁定，本版**无已验证数值**。组合场景的移动、桥/栏杆/凳的遮挡变化在近/远缩放都须复核。
