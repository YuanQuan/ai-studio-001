# 七菜单镜头、序列帧与目标设备性能取证计划 v0.2

任务：`UNIT-MENU-TECH-DESIGN-001`；日期：2026-10-03。此处规定**之后如何测量与判定**；当前没有七菜单运行版本或正式资源，因此 FPS、帧时间、DrawCall、图集页数、内存、输入与画质均为 `NOT_TESTED`。不能用旧九项压测或概念 PNG 文件大小填数。硬阈值、正式机型和允许的降级须在后续获批的 Client/QA 开工包中锁定。

## 1. 每份记录的环境键

每条视频/截图/Profiler 原始数据至少记：构建 commit、Creator 精确版本、源资产版本与 hash、目标入口与资源 UUID、Web/微信/抖音平台、开发工具或真机、设备型号/OS、DPR、画面宽高比/安全区、渲染后端、实际纹理压缩及回退格式、冷启动或热加载、相机中心与缩放、同时可见对象/动作/VFX/UI，以及采样时长。Web 可先验证资源/逻辑；小游戏必须在选定目标真机上复核，开发工具不代替真机。未确定机型时写 `待定`，不填 `PASS`。

## 2. 画面、镜头与状态取证矩阵

| 范围 | 操作 | 证据与通过方向 |
|---|---|
| 入口 1，720×1280 设计比例及目标机各比例 | 初始、水平拖至两端、放大/缩小至边界、重置；Web 鼠标和真机触控分别试；点击 UI/打开对话后拖动 | 连续录屏及四角截图；不露未绘区域，重置回相同初视野；UI 捕获输入不带动世界；桥/水/路连续 |
| 入口 2 | 店常态→动帘/可动件与暖灯前中后→常态，连续触发两次 | 同相机同位置关键帧；邻近店材质的亮部/暗部或投影对应变化，不只灯泡颜色变 |
| 入口 3A | 孟桃 idle→一次工作演示→idle，再快速触发/退出 | 腰牌“孟”小屏截图、骨骼完成回调和残留检查 |
| 入口 3B 与 7 | 左/右各跑移动、跑动、高兴、沮丧、坐姿五格；每向进座、稳坐、离座；快速切态/中途转向/板凳移除 | 10 格视频与单帧标注；move/run 各约 4–6 帧草排的首尾并排检查，轮廓、脚点、alpha 边、座点、非镜像文字、地影与世界受光均稳定 |
| 入口 4 与 7 | 树/花/灯分别开关，再全开/全关 | 各对象骨骼和附属光/VFX 跟随开关，无残留；前后层不串 |
| 入口 5/6 | UI 状态与孟桃示例对话打开/关闭/重置 | 字体、牌匾、腰牌、状态及对话字可读，许可与资源版本同源；UI 不遮关键动作或穿透拖拽 |
| 入口 7 | 任何顺序增删店/孟桃/顾客/凳/树花灯；顾客走过前柜、栏杆、桥、凳附近，缩放观察 | 与独立项相同 UUID/版本及表现；脚点与前后片不穿透；重置仅剩入口 1 同源背景 |

横幅视觉和竖屏 `720×1280` 的冲突要用真实相机视口验证。测所有目标宽高比的可见半宽/半高、可平移合法区间、最大缩小下的可绘覆盖与小屏字投影。若出现露白、桥断开或字形不可辨，修订底板分层覆盖或合法缩放边界，再经 Art/产品/Tech 对照审阅；不直接拉伸概念图或未经审批改游戏横竖屏。

## 3. 分层负载与真实批次

| 负载 | 同时可见内容 | 对比指标 |
|---|---|---|
| A | 空背景+镜头拖/缩 | 底板页数、DrawCall、帧时间、加载峰值与镜头输入延迟基线 |
| B | A+奶茶店静态、店骨骼可动件、暖光/投影 | 骨骼单页是否成立、材质/前后片/半透明光导致的断批和过绘 |
| C | B+孟桃骨骼 idle/work + 幽灵 SpriteFrame 左右五态 + 板凳 | 幽灵实际帧图集页数、切帧 CPU、材质与遮挡断批、动画/位移峰值、座点稳定 |
| D | C+动态树花灯全开，UI 与对话可选 | 组合峰值帧时间、DrawCall、纹理常驻/峰值、骨骼对象数、alpha 过绘和字形质量 |
| E | D 逐一关/删、重置、离开/重进 | 事件/回调/座点、VFX、临时实例、资源缓存是否回落；无叠播和幽灵复制 |

每种负载固定相机和动作序列，分别记录冷加载、稳定运行及最坏动作切换；至少多轮采样并保留原始区间、p50/p95/p99 帧时间、FPS、DrawCall、可用的 CPU/GPU 时间、纹理实际格式/页数/内存或可核的计算式、JS/资源缓存量与加载峰值。正式阈值由批准设备清单确定之后再比较。纹理基础 RGBA8 量 `宽×高×4`，不可把 PNG 压缩文件大小或“同 atlas”当 GPU 占用/一 DrawCall 证据。Cocos 的 [Atlas](https://docs.cocos.com/creator/3.8/manual/en/asset/atlas.html)和 [2D 合批说明](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/engine/ui-batch.html)仅作为配置参考；材质、混合、纹理、遮罩和渲染顺序需在 Profiler 真实验证。

## 4. 放行与返工判定

1. 每次正式出图前 Art/Tech 共同签认，出图后核真实尺寸/帧数/哈希。幽灵是帧序列，不要求骨骼单页；孟桃、店铺动态件、动态树花灯每骨骼对象附件一页。超页、扩帧、另绘反向或回骨骼按各自规则提出变更；不静默改需求。
2. 幽灵左右×五态共 10 格均有录屏；move/run 分别检查 4–6 帧预算下首尾接缝、动作辨识与透明边，高兴/沮丧和坐姿按一次动作/保持/过渡核验。视节点镜像不翻世界位移、座点、阴影、名字/UI。合批/内存达标不能替代视觉通过。
3. 空场景与组合场景在目标比例/安全区无露白、可稳定拖缩且对话/UI 不误触；店暖光须对相邻材质产生可比对变化；桥/栏杆/前柜/板凳遮挡逐位置验。
4. 单元阶段保留可编辑母版、权利链、正式导出、Prefab/资源 UUID/hash、目标机证据及独立/组合双入口对照，才可评为最终可复用资源。未来主体接入未发生时三入口实测保持 `NOT_TESTED`，届时复验同版资源，不重做一套。
5. 若帧时间、DrawCall、内存或 alpha 边超已批准阈值，先定位透明空白、图集页数、材质/遮罩断批、重复实例、同时播放和压缩回退。Art/Tech/VFX 提议精简不得删除必验状态、店真实光影、独立开关与组装；改变正式内容/页数或帧预算须重签及按工作流审批。
6. 目前尚无上述实际数据；正式 QA Test Plan/TEST_REPORT 和用户确认之前，本任务只可给技术设计 Review 结论，不可给运行质量或设备 `PASS`。
