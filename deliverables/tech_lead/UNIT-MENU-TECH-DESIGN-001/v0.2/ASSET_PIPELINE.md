# 七菜单正式资源出图与图集管线 v0.2

任务：`UNIT-MENU-TECH-DESIGN-001`；日期：2026-10-03。正式输入：已批准 Product v0.2、`DEC-UNIT-FINAL-ASSET-004`。本文件是**生产前技术合同**，并不表示已拥有最终原画、逐帧、图集、骨骼工程或授权。旧 v0.1 对幽灵的 Spine 单页预案失效；概念展示板只保留视觉方向参考，禁止裁成正式帧图。

## 1. 源、导出与身份链

每类对象保留原创可编辑母版、图层/帧/骨骼工程、参考与许可记录、导出预设和正式 Creator 资源。候选路径：`art-source/units/<对象ID>/` 放源文件及逐次签认，`apps/client/assets/units/<对象>/` 放正式导出与 Prefab；最终目录/扩展名由 Art 与 Client 在实际工具链中校准。Creator 的 `.meta` UUID 及资源版本哈希是单元独立、组合、未来主体同源检验键，不能以相似文件名代替。每次从母版导出，要登记母版版本、导出工具及参数、输出文件 hash、导入日志、Prefab 依赖 UUID；新旧版本不得静默覆盖已审资源。

用户参考图属于构图/桥/牌匾/画风**参考证据**，须登记来源与相似风险；不能完全照搬、换色描摹。图像与系统/美术字体均须核验实际商业使用、修改、嵌入和分发许可；改造既有字体不产生自动授权。权利状态未明者不得进入正式 Creator 资源。UI 的杯标、牌匾文字、腰牌“孟”及对话字形都需跟踪字体/手绘字来源；正式 UI 复用同一图标和状态资源。

## 2. 对象分层、页数和图像面积输入

| ID | 正式源与表现 | 草排输入/页数规则 |
|---|---|---|
| `STREET_BASE_01` | 空背景分为天空远景、路/河、石拱桥与栏杆的可遮挡前/后片；不烘入店、人、板凳、可切换树花灯 | 静态非骨骼，按实际相机覆盖/装载/压缩策略分片；2172×724 概念图不是生产纹理尺寸 |
| `MT_SHOP_01`/`MT_SHOP_MOTION_01` | 木砖瓦静态店体、牌匾/杯标/奶茶机/纸盒原料；可动帘等为骨骼；暖光区域和相邻暗部/投影分层 | **每骨骼对象**全部附件一页；静态店体和光影另排，不能用全店大透明画布强塞一页 |
| `MT_CHAR_01` | 孟桃单实际视角骨骼 idle/work，腰牌仅“孟” | 该骨骼对象所有附件一页；计入工作动作极限姿态与换手/杯件 |
| `UG_GHOST_01` | 一个原创朝向的透明帧图；move/run 各约 4–6 帧循环预算起点，happy/sad 一次动作与保持，sit 进/稳/离；反向水平翻转 | **不适用骨骼单页规则**。按所有独立帧实际像素、统一逻辑画布、裁切偏移、透明边、padding、材质与设备支持草排所需 atlas 页数；页数是测量结论，不预设一页 |
| `BENCH_01` | 独立板凳、世界座点、前/后片 | 静态分层；不画入幽灵帧图；双方向坐姿都需透视/接触验证 |
| `UE_TREE_01`、`UE_GRASS_01`、`UE_LANTERN_01` | 可开关的树、花草、灯笼；需要动态的部分用骨骼，伴随 VFX/世界暖光独立 | 每个动态骨骼对象的附件各一页；静态根/盆/灯光另记；隐藏时附属光/VFX同时清理 |
| 正式身份 UI、对话 UI、VFX | 共用 UI 图标、状态、获授权字体与可重复使用特效 | 依据正式 UI/VFX 规格排图；如 VFX 采用骨骼才适用该骨骼对象单页，不预造未批准资源 |

草排时先量每帧和每附件的**实际像素宽高**与极限包围盒，再计算 padding、bleed、旋转/trim 可用性、atlas 有效面积、透明留白和目标平台最大纹理限制；在对应近/远镜头测屏幕投影大小。对于幽灵，要提供五态完整帧清单、循环边界的首帧/尾帧并排图、每帧原点/脚点/座点、左右镜像合成预览；不能仅展示一张姿势拼图。字体/牌匾要按目标机实际屏幕投影验证，而不是只看源 PNG 清晰度。

RGBA8 单层基础量 `width × height × 4` 字节：512²约 1 MiB、1024²约 4 MiB、2048²约 16 MiB。它**不等于**最终显存：mipmap、压缩格式/回退、GPU 副本、Web 解码源/图集副本与帧缓冲还会影响峰值。512²/1024²/2048²只能作计算示例，非已批准图集上限或推荐实际尺寸。若骨骼对象单页草排失败，先核真实屏幕尺寸、附件复用、透明边与排图，再连同视觉损失/内存提出重评，不擅改为多页；幽灵按序列帧实际页数、批次与内存权衡，不为强塞一页牺牲清晰度。

## 3. 每次正式出图前的 Art/Tech 共签表

每个对象**每一源版本、每一次正式图片产出**都保存一份签认记录，至少填下列字段；缺项则状态保持 `DRAFT`，不得标为可集成：

| 字段组 | 必填内容 |
|---|---|
| 身份与依据 | 对象 ID、Task、已批准 Product/Art/UI/VFX/Tech 适用版本、用途入口、母版路径与版本、目标导出/Prefab、负责人、计划出图日期 |
| 原创与许可 | 各参考来源、版权/IP/外观相似性检查、图片/系统字体/美术字体的作者和商业使用、修改、嵌入、分发许可；不明项与处理人 |
| 表现与方向 | 视角、原创朝向；幽灵五态、move/run 各自计划帧数/循环首尾/驻留时间、情绪保持/坐姿过渡、统一逻辑画布与每帧脚点/座点；反向镜像后的字/饰件/手势/受光；骨骼对象的分件/slot/极限姿态 |
| 尺寸与纹理 | 每帧/附件实际像素宽高、最大包围盒、alpha 边界、trim/pivot/offset、padding/bleed/过滤/混合、预估 atlas 页数与每页尺寸/利用率、目标机最大纹理与压缩/回退 |
| 合批与内存 | 材质/混合状态、可能断批的前后景/遮罩/UI/VFX 插层、基础 RGBA8 与压缩候选纹理量、冷加载峰值风险；**不能把同 atlas 写成保证一 DrawCall** |
| 工具与输出 | 出图软件及精确版本和许可，骨骼作者工具/导出运行时兼容版本，导出格式、命名、hash 与 Creator 3.8.8 导入验证计划 |
| 签认 | Art 与 Tech Lead 分别署名、日期、结论 `APPROVED_FOR_EXPORT / REVISE / BLOCKED`、条件与重新签认触发点 |

这份表是**出图前**门禁；产出后还要对比实际帧数/尺寸/alpha/页数/hash/Creator 导入与签认是否一致。改动帧数、动作、方向、atlas 页数/材质、字体、许可、工具版本、屏幕覆盖或压缩策略，均需要重新联签。Art 签视觉、原创与权利资料；Tech 签资源布局/性能/导入约束；双方都不能以一次概念预检代替正式每次签认。

## 4. Creator 导入与合批验证

幽灵 SpriteFrame 可以依 Creator 3.8 的 [SpriteFrame](https://docs.cocos.com/creator/3.8/manual/en/asset/sprite-frame.html)、[AnimationClip](https://docs.cocos.com/creator/3.8/manual/en/animation/animation-clip.html)和 [Atlas](https://docs.cocos.com/creator/3.8/manual/en/asset/atlas.html)机制组织，但具体自动裁切、Packable、页数与帧切换需在本工程实际验证。检查每帧渲染原点、尺寸变化、半透明边与镜像结果。骨骼对象按已登记且合法的作者工具、与仓库 `spine-3.8` 配置兼容的实际导出版本、骨骼数据/atlas 描述/**一页**图像交付，并在 Creator 3.8.8 导入留日志；运行配置本身不是许可或导入成功证据。

同一图集减少纹理切换可能性，但 DrawCall 受材质、混合/遮罩、纹理、节点顺序、骨骼批次和 UI/VFX 插层影响。测量时分别看幽灵独立状态、店+孟桃、树花灯全开与组合峰值；记录实际 atlas 页数、DrawCall、帧时间、纹理实际格式/回退和过绘。正式出图前可用草排估算，正式放行必须是 Creator 与目标设备数据。旧 Demo PNG、概念图及 UI 审阅 SVG 不得导入正式 `units/` 以占完成数。
