# CP-UNIT-REUSE-001｜Tech Lead 预评审 v0.1

结论：**原则支持，带条件通过技术方向；提案仍为 `PROPOSED`，不得据此直接进入 Client 实现。** 该提案与已批准 Product v0.1、`DEC-UNIT-DIRECTION-002` 的单视角范围一致；旅客四方向应留待独立单元。Art v0.1 的结构预案可供联合评审，但它本身尚未获得用户批准。

| 条款 | 评审意见／需落地的动作 |
|---|---|
| 独立迭代与工程形态（1、4） | 建议先在 `apps/client/` 单一 Creator 3.8.8 工程内以独立 Scene、Prefab、脚本和资源目录实现；避免多个物理工程造成 `.meta` UUID／引用和版本分叉。若要跨工程共享，需另提正式包契约。 |
| 同源与界面（2、3、5、9） | 必须以同一 Prefab／行为控制／获批身份 UI 与 VFX 源供 Lab 和主体入口引用；对实例属性覆盖、Asset Bundle 依赖、旧 Demo 残留做扫描。测试控制层单独放在 Lab。验收以“改一个源、双入口呈现同版”取证。 |
| 骨骼与单图集（6、7） | 孟桃与店铺可动件各一套骨骼和各自一页图集；静态店身不强行骨骼化。本轮不做孟桃、店铺四方向，也不制作旅客。Spine 3.8 是现有工程启用且 Creator 3.8 文档支持的**候选**，导出版本、工具许可、三平台导入需核验。单页失败必须提变更，不得自行拆页。 |
| 合批／性能（8） | 改写“单图集等于合批”的误解：Spine 有内部机制，跨对象不保证合批。逐对象记录混合模式、材质、透明裁切、图集尺寸估算和真机基线／峰值；用户批准目标设备与预算前不得写“达标”。每次正式资源输出前 Art 与 Tech 共同签认。 |
| 版权／字体（9） | Art 继续登记实际参考与可识别相似性；UI 后续登记系统及美术字体的显示、嵌入、分发、修改许可。现有 Art v0.1 只登记文字输入，无图片或字体授权结论。 |

## 必须由后续审批锁定的契约

1. **Art 与 Tech 下轮联合出图单**：正式概念图、分件包围盒、同屏最近／最远尺寸、图集一页草排、裁切／扩边、骨骼版本、透明与材质策略、设备支持与估算。此单两方共同签认并关联具体资产版本；本预审不能替代。
2. **项目级 Creator 边界**：单工程、Prefab 及场景组织、表现事件、资源版本／Bundle 依赖、双入口验收方法，由 Master 组织 Art、UI、VFX、Client、QA 评审并经用户批准后写入项目决定或技术规格。`CP-UNIT-REUSE-001` 当前不提供这些可直接实现的细节。
3. **目标设备／预算**：低档和主流微信／抖音设备型号、目标帧时间、DrawCall 与纹理内存预算、包体和画质取舍。现在只有测量方法，不能通过性能门禁。
4. **UI／VFX 正式规格**：身份组件和工作反馈另由责任角色提交并获用户批准；Tech 不替他们决定视觉或产品语义。工作期间重复触发策略由 Tech/Client 形成可测试接口候选，再纳入下游审批。

建议 Master 将本评审与 Art v0.1 同送专业 Review；Producer 保持当前逐环节审批门禁。只有获批版本可以进入正式制作和 Client 实现。
