# 七项菜单单元｜店铺与场景特效规格 v0.2

任务：`UNIT-MENU-VFX-SPEC-001`。正式输入为已获用户 `USER_APPROVED` 的 `UNIT-MENU-PRODUCT-001 v0.2`、`DEC-UNIT-FINAL-ASSET-004` 与当前选定的非像素美术方向。本版是 **VFX 制作与验收规格**，不表示正式图片、骨骼、图集、Creator 运行或目标设备性能已完成。旧 v0.1 整版 `REJECTED`，只作问题追溯；其中幽灵骨骼与挂点要求失效。

## 1. 视觉和功能边界

沿用平视、可爱中式夜市插画：冷夜蓝环境、局部暖橙灯光，木砖瓦材质与简洁暗部。店铺灯影须让人同时看出灯罩亮态、邻近墙/柜受光和地面暗部/投影变化；光晕不可烘入不能关闭的店身，也不可遮挡木框牌匾、杯吸管标志、孟桃脸或腰牌“孟”。树、花、灯各有独立可辨效果。顾客五状态由**原创透明序列帧**负责表达，本任务不附加情绪奖励粒子、法阵、魔法符号或经营完成反馈。任何热气或工作动作强调线仅为候选层，不是额外必须资产，不触发商品、订单或奖励规则。

“必要”指产品 B02、B04、B05、B08/B09 的可观察表现；具体时长与亮度是待 Art/Tech 在正式源和设备上校准的候选观察窗，不能据此声明性能达标，也不在此创建 Client API。

## 3. 层级、镜像与遮挡

相对层按真实 Art 分片与脚点排序校准：天空/河及桥后片 → 世界地面与地影 → 店后墙/柜受光 → 树花灯后片与板凳后片 → 孟桃/幽灵帧显示及可见效果 → 店前柜/栏杆/板凳前片 → 必要的局部热气或工作短线（仍可被前片遮挡）→ 共用 UI 与 Lab 控件。桥与栏杆不能一律顶盖；顾客经过店前、桥口、栏杆和坐板凳时，检查局部前后片与脚点。相机拖拽、缩放后世界地影和暖光仍应贴在对应位置。

幽灵 `FrameVisual` 只负责帧图及同源左右翻转。世界灯照、地面影、碰撞/脚点、板凳座点、店铺牌匾、孟桃腰牌、文字与 UI 均留在不镜像的世界或界面节点。顾客如有非对称挂件、持物或动作手势，先在单方向正式帧图设计中使两向可读，左右×五状态和进/离座分别检查；不得在 VFX 中私增另一向绘件。反向专属资源或显著扩帧/退回骨骼须显式变更及用户批准。

## 4. 生命周期与正式资源边界

对象显示、触发、关闭、移除、重置、返回菜单、Scene 卸载及加载失败都必须按**实例归属**处理效果。离开时先禁止新触发和旧异步回调，再停所属骨骼/帧动画、补间、计时器与订阅，复原 alpha/材质参数和灯影基态，回收热气与光斑。快速切态以当前状态和当前会话为准，迟到回调不得复活已移除对象。关闭板凳必须让幽灵安全退出坐姿；移除店铺与灯笼各自清理，互不牵连。

单元运行输出是未来主体直接复用的正式同源资源：独立入口、组合入口与未来主体引用相同获批源、导出、对象状态和 VFX 定义；Lab 控件仅是观察入口。概念图、旧 Demo、样张光晕与尚待审的试点短线都不能计入成品。所需资产、逐次出图双签见 `ASSET_REQUIREMENTS.md`；批次、显存、降级与无残留取证见 `PERFORMANCE_AND_CLEANUP.md`。正式接入与 QA 需在各自门禁后执行，现阶段无运行通过结论。
