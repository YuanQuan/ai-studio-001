# 头脑风暴脑图方法变更｜Producer 流程评审

评审对象：`CAP-2026-09-29-BRAINSTORM.json`
评审结论：**同意按下列门禁实施。** 脑图可以成为初期概要的主阅读入口，短说明承担来源、状态和边界记录；表达方式变化不改变正式任务与审批流程。

1. **Task 与版本**：正式任务仍由 Master 创建，Task Packet 列出脑图、短说明及交付元数据的真实路径。每次讨论修订形成新版本，旧版保留；两项内容应在同一版本的 Deliverable 中登记，不能只提供一张未编号的图。
2. **用户审批 Gate**：Product 提交脑图和短说明后仍需专业评审，再由 Producer 将该版本推进 `USER_REVIEW`。只有用户明确批准的版本可作为下游详细 PRD 的正式输入；脑图先行不表示自动批准任何玩法语义。
3. **Dashboard 追溯**：Producer 按现有 `WORKFLOW_STATUS.md`、`MILESTONE_LOG.md`、`APPROVAL_LOG.md` 记录当前版本、各次修订、评审和用户决定；Dashboard 链接对应版本的脑图、短说明、Task、Review 与 Approval 路径。

短说明至少保留稳定模块编号、关键输入输出关系、已确认方向与产品假设的区别、来源和未决问题。若脑图与短说明有冲突，Product 须修订同一版本的交付包后再送审，避免下游自行选择解释。

本评审仅确认流程可追溯性，不批准当前游戏 v0.6 概要，也不修改 Studio 规则文件。
